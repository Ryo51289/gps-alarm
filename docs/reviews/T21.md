## Đánh giá #3: dependency trực tiếp, file riêng, backup rules, T25

- **API của plugin có ổn định và đúng không:** `SharedPreferencesAsyncAndroidOptions(backend: SharedPreferencesAndroidBackendLibrary.SharedPreferences,
  originalSharedPreferencesOptions: AndroidSharedPreferencesStoreOptions(fileName: …))` là API công khai, được README chính thức của
  `shared_preferences` 2.5.6 hướng dẫn nguyên văn (mục "Android platform storage", kèm `import 'package:shared_preferences_android/shared_preferences_android.dart'`).
  CHANGELOG 2.5.3 còn sửa lỗi biên dịch web "for example to use `SharedPreferencesAsyncAndroidOptions`", tức là nhà phát triển plugin
  chủ động hỗ trợ cách import này từ app. Native: `fileName != null` → `context.getSharedPreferences(fileName, MODE_PRIVATE)` →
  `shared_prefs/napstop_onboarding.xml` (khớp quan sát của coder trên emulator); `setInt`/`getInt` đi qua `putLong`/`getLong` nên ghi và
  đọc cùng kiểu.
- **Dependency trực tiếp:** đúng cách. Với plugin federated, muốn dùng lớp riêng của nền tảng thì phải khai package nền tảng là
  dependency trực tiếp (không được import package transitive, lint `depend_on_referenced_packages`). Bản trong lock không đổi (2.5.4,
  cùng sha256), chỉ đổi `transitive` → `direct main`; `^2.5.4` tương thích với ràng buộc của `shared_preferences` 2.5.6. Rủi ro còn lại:
  khi nâng `shared_preferences` phải nâng cả package này (cùng một task nâng phiên bản).
- **So với các phương án khác:** (a) loại cả file DataStore mặc định (`files/datastore/FlutterSharedPreferences.preferences_pb`, domain
  `file`) sẽ kéo theo tuỳ chọn T25 ra khỏi sao lưu, trái quyết định hiện tại (T25 muốn giữ); (b) một file DataStore riêng: plugin không
  cho đặt tên file DataStore, phải viết native + Pigeon mới, phức tạp hơn; (c) cờ ở native (`napstop_permissions.xml`) cũng cần Pigeon
  mới. Phương án đã chọn là ít code nhất mà vẫn tách được file. Đồng ý.
- **Backup rules:** `<exclude domain="sharedpref" path="napstop_onboarding.xml"/>` dùng cùng cú pháp với `napstop_permissions.xml`
  (đã có từ vòng 1). Với domain `sharedpref`, `path` là đường dẫn tương đối trong thư mục `shared_prefs/`, nên phải có đuôi `.xml` như
  đang viết. Cả 3 chỗ đã có: `full-backup-content` (API ≤ 30), `data-extraction-rules` → `cloud-backup` và `device-transfer` (API 31+),
  hai schema dùng chung bộ `include/exclude` + `domain`. S02 kiểm cả 2 file ở 3 chỗ + tên hằng Dart. Việc các công cụ chuyển máy của OEM
  (ví dụ Smart Switch) có tôn trọng `device-transfer` hay không thì ngoài tầm kiểm soát. Ghi để tester thử bằng `bmgr`, không phải lỗi.
- **Tuỳ chọn T25 không bị ảnh hưởng:** `keyValueStoreProvider` vẫn là `SharedPreferencesKeyValueStore()` với `SharedPreferencesOptions()`
  mặc định (DataStore, vẫn được sao lưu). Tham số `options` mới là tuỳ chọn, mặc định giữ nguyên hành vi. Chỉ `main()` (`createOnboardingStore()`)
  và nút chính màn 0 (`onboardingStoreProvider`) dùng kho mới, nên đọc và ghi cùng một file. Bản dev cũ đã ghi cờ vào DataStore thì trên
  máy đó màn 0 hiện lại một lần (vô hại, chưa phát hành).
- **iOS:** kho mặc định là UserDefaults, vẫn nằm trong bản sao lưu iCloud. Implementation notes đã chuyển việc này cho T17 quyết. Đề
  nghị orchestrator ghi vào cột ghi chú T17 trong TASKS để không bị quên.
