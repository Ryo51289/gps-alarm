## Trọng tâm

**1. `onSilenced` khớp từng dòng với Kotlin `onSilenced(w)`:**

| Kotlin | Swift | Khớp |
|---|---|---|
| `if (phase != ALARMING && phase != OVERSHOT) return` | như vậy | ✓ |
| `expired = now − (lastRingAtMs ?: now) ≥ alarmMaxActiveS·1000` | `now − (a.lastRingAtMs ?? now) >= TMath.ms(p.alarmMaxActiveS)` | ✓ |
| `OVERSHOT && ringing && lastReason ≠ OVERSHOOT && !expired` | như vậy | ✓ |
| `markRing(OVERSHOOT, now, true)` + `Alarm(now, OVERSHOOT, ringNow = true, snoozeAllowed = false, nil…)` | `markRing(.overshoot, ringAt: now, ringNow: true)` + `appendAlarmPlaceholder(.overshoot, ringNow: true)` (payload điền ở bước 10, `snoozeAllowed: false`) | ✓ |
| ngược lại `ringing = false` | như vậy | ✓ |

- **Vế hạn:** dùng `<` (không hết hạn khi `now − lastRingAtMs < alarmMaxActiveS·1000`). Biểu thức trùng bước 3 của Swift
  (`runFromStep3`: `now − l >= TMath.ms(p.alarmMaxActiveS)`).
- **`lastRingAtMs` đọc trước `markRing`:** `let a = s.alarm` được chụp trước khi gọi.
- **Thứ tự bước không đổi:** input vẫn xử lý ở bước 2, `runFromStep3` vẫn chạy sau. U130 g/g2 (đúng hạn: kết thúc
  `ALARM_UNANSWERED`, không kêu; 1 ms trước hạn: kêu) xác nhận điều này.
- Không đổi snapshot hay tham số. U132 kiểm: không thêm khoá mới; `restore(PENDING)` sau mỗi Step cho cùng dãy sự kiện.
