### 3. Đồng hồ ảo (`TripClock`, `:core-runtime`)

```kotlin
/** [wallMs] = trip time at the anchor (≈ wall clock at trip start; after a rebase, the trip time of the rebase). */
data class ClockAnchor(val wallMs: Long, val elapsedMs: Long, val bootCount: Int?, val speed: Double = 1.0)

/** Read-only, thread-safe view of a trip clock (no monotonic floor): for the simulation source and timers. */
interface SimTimeline {
    fun tripNow(): Long
    /** Real ms until trip time [tripMs]; 0 if reached. */
    fun realDelayMs(tripMs: Long): Long
}

class TripClock(anchor: ClockAnchor, private val time: TimeSource, floorMs: Long = Long.MIN_VALUE) {
    @Volatile var anchor: ClockAnchor = anchor; private set
    val speed: Double get() = anchor.speed
    val timeline: SimTimeline                                   // backed by tripAt(time.elapsedMs())
    fun now(): Long                                             // max(lastIssued, tripAt(elapsed))
    fun toElapsed(tripMs: Long): Long; fun toWall(tripMs: Long): Long; fun toTrip(wallMs: Long): Long
    fun futureWallToTrip(wallMs: Long): Long                    // a wall time in the future, on the trip clock (ring guard)
    fun realDelayMs(tripMs: Long): Long
    fun rebase(newSpeed: Double)                                // actor only
}
```

```
up(d)   = speed == 1.0 ? d : floor(d · speed)          -- thời lượng thật → ảo
down(d) = speed == 1.0 ? d : ceil(d / speed)           -- thời lượng ảo → thật (ceil: tới hạn thì đã qua mốc)
tripAt(e)            = anchor.wallMs + up(e − anchor.elapsedMs)
now()                = lastIssued = max(lastIssued, tripAt(time.elapsedMs()))
toElapsed(t)         = time.elapsedMs() + down(max(0, t − now()))
toWall(t)            = time.wallMs()    + down(max(0, t − now()))
toTrip(w)            = now() − up(max(0, time.wallMs() − w))
futureWallToTrip(w)  = now() + up(max(0, w − time.wallMs()))
realDelayMs(t)       = down(max(0, t − now()))
rebase(s):  e = time.elapsedMs(); n = max(lastIssued, tripAt(e)); lastIssued = n; anchor = ClockAnchor(n, e, anchor.bootCount, s)
timeline.tripNow()        = tripAt(time.elapsedMs())               -- không cập nhật lastIssued
timeline.realDelayMs(t)   = down(max(0, t − tripNow()))
```
- `speed == 1.0` đi đúng nhánh cũ (không nhân/chia số thực): kết quả trùng T15 từng ms (SM01).
- `anchorNow(time)` giữ `speed = 1.0`; `anchorValid` không đổi.
- Lưu: `anchor.speed` chỉ ghi khi ≠ 1.0 (khoá `anchor.speed`), nên file của chuyến thật giữ nguyên từng byte (L17 T15). Đọc: vắng = 1.0;
  giá trị không hữu hạn hoặc ≤ 0 → `StoreFormatException`.

Chỗ phải đổi sang phép có `speed` (coder đối chiếu, review đọc mã):

| `updateTracking` throttle | `notifMinIntervalMs` | chuyến giả lập: `max(simNotifMinIntervalFloorMs, notifMinIntervalMs / a.clock.speed)` — theo **tốc độ hiện tại**, không theo `meta.simulation.speedFactor`; sau D3 (về 1×) ra đúng `notifMinIntervalMs` như chuyến thật (sửa sau review, nit #4) |
| Thông báo "Báo lại lúc" | `view.snoozeUntilMs` | chuyến giả lập: `a.clock.toWall(snoozeUntilMs)` trước khi gửi `TrackingNotice` |

**Thời điểm Step của fix giả lập (sửa sau review, thay cho "Step lấy giờ lúc giao" của bản spec đầu).** Hiện thực ở
`TripRuntime.kt` `handleFix` (~1241). Bất biến:
1. **Chỉ áp cho fix giả lập** (`RawFix.simFixAtMs != null`). FLP luôn gửi `simFixAtMs = null` → `now = clock.now()`, đường chuyến thật
   giống T15 từng ms (L-test T15 không sửa, SM01).
2. **Không lùi thời gian:** `atMs ≥ engine.nowMs` (Step trước, kể cả Tick/UserAction đã chen vào sau mẫu), và `atMs ≤ clock.now()`
   (không đi trước đồng hồ chuyến). Khi mẫu tới đúng hạn (thường lệ) thì `atMs = fixAtMs = simFixAtMs`, tuổi fix = 0; khi đã có Step muộn
   hơn mẫu thì `atMs = engine.nowMs`, `fixAtMs = simFixAtMs`, tuổi fix ≥ 0.
3. **Chỉ dấu thời gian là giờ của mẫu; hiệu ứng vẫn chạy lúc giao thật.** `applyStep` lập kế hoạch với `nowTrip = clock.now()` (ring, hẹn
   giờ, thông báo), nên không có gì bị trễ hay chạy sớm. Dấu thời gian Step/sự kiện là giờ ảo, khớp D14 và cách SI01 tính `t` theo
   `AlarmMsg.atMs`.
4. Kết quả: dãy sự kiện (nhãn, lý do) của SM19 **giống nhau ở 1×/60×/600×**, lệch ≤ 1 s ảo, không phụ thuộc độ trễ giao.

Các phép còn lại đã đi qua `TripClock` (`toWall`, `toElapsed`, `toTrip`) nên tự đúng. `RING_RETRY_MS`, `fallbackLagS · 1000` cộng vào wall
(khe canh chuông, T15 "sau test" G1/G2) là **giờ thật** có chủ đích: lưới an toàn khi kêu lỗi tính bằng thời gian người dùng chờ.

### 4. Nguồn vị trí giả lập

```kotlin
package app.napstop.core.trip.runtime.sim

/** One GPX sample (README §2). toString() redacts lat/lng. */
data class TraceSample(val t: Int, val lat: Double, val lng: Double, val accM: Float, val spdMps: Float?)
class SimTrace(val id: String, val samples: List<TraceSample>)   // samples non-empty, t strictly increasing, samples[0].t == 0
data class SimSpec(val traceId: String, val speedFactor: Double)

class TraceFormatException(message: String) : RuntimeException(message)   // message names the rule, never a value

object TraceGpx {
    const val NS = "https://napstop.app/xmlns/trace/1"
    /** SAX, namespace-aware [A-SAX]; every trk/trkseg/trkpt in document order (README §2). Throws TraceFormatException. */
    fun parse(input: java.io.InputStream): List<TraceSample>
}

object SimTraceIds { val PATTERN = Regex("^[a-z0-9]+(_[a-z0-9]+)*$"); fun valid(id: String) = id.length <= 64 && PATTERN.matches(id) }

class SimulatedLocationSource(
    private val samples: List<TraceSample>,
    private val startTripMs: Long,            // trip clock at commit (D2) = trace t 0
    private val timeline: SimTimeline,
    private val time: TimeSource,             // real; only for RawFix.elapsedRealtimeNanos
    private val scope: CoroutineScope,
    private val dispatcher: CoroutineDispatcher,
    private val pollMaxMs: Long,
) : LocationSource {
    override fun request(spec: FlpRequestSpec, sink: FixSink)   // stores spec + sink; starts the player once
    override fun stop()                                          // spec = null, sink = null (player keeps time; samples skipped)
    override suspend fun lastKnown(): RawFix? = null
    fun cancel()                                                 // trip ended
}
```

`TraceGpx.parse` — luật (lỗi → `TraceFormatException`): `trkpt` có `lat`, `lon` hữu hạn trong khoảng; có `time` (ISO-8601 UTC,
`java.time.Instant.parse`, có từ API 26 = minSdk PRD §5); có `napstop:acc` hữu hạn > 0; `napstop:spd` nếu có thì hữu hạn ≥ 0; thời gian
tăng nghiêm ngặt; ≥ 1 mẫu. `t = (time − time₀)/1000`. Không giới hạn số `trkseg` (khoảng mất GPS = không có mẫu). Không bật DTD/entity
ngoài (asset do ta sinh, không có DTD).

Bộ phát (chạy trên `dispatcher`):
```
play():
  lastT = null
  for s in samples:
    due = startTripMs + s.t · 1000
    timeline.awaitTrip(due, pollMaxMs)        -- while (d = realDelayMs(due)) > 0: delay(min(d, pollMaxMs))
    sp = spec ?: continue                      -- đang dừng (HEADLESS / chưa request): mẫu mất, như GPS không có
    if lastT != null && (s.t − lastT) · 1000 < sp.intervalMs: continue        -- chế độ policy (README §6)
    lastT = s.t
    sink.onFix(RawFix(s.lat, s.lng, s.accM, s.spdMps, elapsedRealtimeNanos = time.elapsedNanos(), simFixAtMs = due)) { }
  -- hết trace: không giao gì nữa (engine tự thấy mất GPS)
```
- `RawFix` thêm trường cuối `simFixAtMs: Long? = null` (FLP luôn `null`); `toString` vẫn che toạ độ.
- `spdMps` giữ nguyên (m/s ảo): quãng đường và thời gian đều ảo, không nhân tốc độ (khác lệnh debug `replay … speedScale` của T15).
- Đổi `spec` giữa chừng có hiệu lực từ mẫu kế tiếp. `awaitTrip` đọc lại `timeline` sau mỗi lần ngủ, nên `rebase(1.0)` (D3) làm các mẫu sau
  tới chậm lại ngay.

`SwitchableLocationSource` (đang ở `:app`, `FusedLocationSource.kt`, thuần) chuyển sang `:core-runtime`. Runtime tự bọc
`ports.location` bằng một `SwitchableLocationSource` riêng (`runtimeLocation`) để gắn/gỡ nguồn giả lập; `lastKnown()` trả `null` khi đang
gắn nguồn giả lập, nên `submitLastKnown()` sau khi bắt đầu không đưa vị trí thật vào chuyến giả lập. Lệnh debug `replay` (T15) vẫn dùng
Switchable của `RuntimeHost` (lớp dưới), không đổi.

```
SimAlarmScheduler.setWake(..., wakeAtMs):   cancelWake(); tl = timeline
    wakeJob = launch(dispatcher) {
        if (tl != null && wakeAtMs >= 0) tl.awaitTrip(wakeAtMs, pollMaxMs) else delay(max(0, triggerElapsedMs − time.elapsedMs()))
        onWake(wakeAtMs, triggerWallMs) }
SimAlarmScheduler.setFallback(slot, …, targetAtMs, …): cancelFallback(slot)
    slotJobs[slot] = launch(dispatcher) { tl.awaitTrip(targetAtMs, pollMaxMs); onFallback(tripId, slot, generation, targetAtMs, kind) }
Routing:  canScheduleExact = simulated ? true : os.canScheduleExact()
          setWake / setFallback          → simulated ? sim : os
          cancelWake / cancelFallback(s) → os.… rồi sim.…      (huỷ cả hai: không phụ thuộc thứ tự bật/tắt simulated)
          setRestoreRetry / cancelRestoreRetry → os
```
- Hẹn giờ dùng **giờ ảo của mốc** (`wakeAtMs`, `targetAtMs`) chứ không dùng `triggerElapsedMs`/`triggerWallMs` đã đổi sẵn: sau `rebase` mốc
  vẫn tới đúng giờ ảo. Khe canh chuông (GUARD) có `targetAtMs = futureWallToTrip(now + fallbackLagS)` nên vẫn ≈ `fallbackLagS` thật.
- `onWake`/`onFallback` được runtime nối vào `this::onWake` và `this::onFallbackFired` (cùng hàm mà receiver gọi; đều là `call` vào actor).
- **Ngoại lệ có chủ đích của D5 (ghi sau review, nit #5):** `setRestoreRetry` luôn tới OS, kể cả khi sổ có `activeSimulated=true` mà đọc
  snapshot quá ngân sách sau khi process chết. Đó là alarm dọn dẹp `ELAPSED_REALTIME_WAKEUP` (`setExactAndAllowWhileIdle`/`setAndAllowWhileIdle`, không
  `setAlarmClock`: không biểu tượng báo thức, không kêu); nó đưa lần nạp kế tiếp vào D9 sớm, đóng chuyến và `stopRinging` chuông `:ring`
  còn sót. Không sửa.
- `FallbackScheduler` của runtime dùng `RoutingAlarmScheduler` (thay `ports.scheduler`). Mọi chỗ khác trong runtime đang gọi
  `ports.scheduler` cũng đi qua router.

### 13. Phần iOS → task mới T18.1 `[mac]` (sau T17)
