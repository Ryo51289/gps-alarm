# T23.6 — Live Activity + Dynamic Island cho chuyến đang chạy (iOS)

Trạng thái đề xuất: **cần-quyết-định** (Q1–Q7 bên dưới). Bước B0 (spike xtool, `docs/spikes/T23.6.md`) không phụ thuộc
câu trả lời, làm được ngay.

## 1. Bối cảnh & mục tiêu

- PO yêu cầu ngày 12/11/2026: chuyến đang chạy hiện trên màn khoá và Dynamic Island. Người đi xe liếc là biết còn bao xa,
  tới lúc nào và đang báo theo chế độ nào; dừng chuyến được mà không cần mở app.
- PRD §4 "Theo dõi chuyến": Android có thông báo thường trực, kèm nút Dừng. iOS chưa có gì tương đương. Live Activity là
  bản tương đương trên iOS.
- PRD §6 đang ghi "Live Activity (stretch goal nếu kịp)". PO đã mở phạm vi, cần sửa ở T19.1 (xem §11).
- Runtime iOS (T17, T17.1–T17.3, T18.1) đã phát `TripView` và sự kiện engine qua `RuntimeListener`
  (`TripRuntime.addListener`). Live Activity chỉ **nghe** luồng này: không đổi engine, không đổi đường báo thức.
- Ràng buộc: không backend, không push (pushType `nil`). Vị trí không rời máy. Không có Mac: kiểm bằng WSL (`swift test`,
  typecheck), CI macOS, và iPhone của PO cài bằng xtool (Apple ID miễn phí).

## 2. Phạm vi

**Làm**
- Widget Extension SwiftUI `NapStopLiveActivity`, chỉ chứa Live Activity, không có widget màn hình chính. Gồm 4 dạng:
  màn khoá (kiêm banner), Dynamic Island thu gọn (compact leading/trailing), tối thiểu (minimal) và mở rộng (expanded).
- Kiểu dữ liệu chung `NapStopTripAttributes` (+ `ContentState`), đặt trong target SwiftPM `LiveTrip`. App và extension
  cùng link target này.
- Logic thuần trong `TripRuntime`, test được trên Linux: dựng nội dung từ `TripView`, ngân sách cập nhật, và máy trạng
  thái vòng đời. Cầu ActivityKit mỏng nằm trong `NapStopIOS`.
- Nút "Dừng theo dõi" dùng `LiveActivityIntent` (Q2). Intent chạy trong process của app và gọi `userAction(.stopTrip)`.
- Kết thúc Live Activity khi chuyến kết thúc (tắt báo thức, người dùng dừng, báo không ai tắt). Khôi phục sau khi app bị
  kill. Có `staleDate`.
- Chuỗi hiển thị: thêm vào `NativeCopy` và ARB, có test đối chiếu ARB (như IU34). App gửi chuỗi đã dịch cho extension.
- `project.pbxproj`: thêm target, embed, phụ thuộc. CI kiểm appex có trong IPA. Thêm XCTest trên Simulator, test tích hợp
  (nếu khả thi) và giao thức thử tay.

**KHÔNG làm**
- Push ActivityKit, push-to-start, `NSSupportsLiveActivitiesFrequentUpdates` (khoá này chỉ dành cho push).
- `AlertConfiguration` khi cập nhật. Live Activity **không bao giờ** là kênh báo thức và không phát âm thanh.
- Widget màn hình chính, Control Center, StandBy tuỳ biến (StandBy dùng dạng màn khoá mặc định), Apple Watch.
- Giao diện AlarmKit dạng đếm ngược hay tạm dừng (`AlarmPresentation.Countdown/Paused`). NapStop chỉ dùng `Alert`.
- Công tắc bật/tắt trong màn 12 (Q6: dùng Cài đặt hệ thống). Sự kiện Analytics mới. Tham số Remote Config mới.
- Android (thông báo thường trực đã có ở T15).
- Đổi `TripRuntime` (actor), engine, Pigeon, Dart (trừ ARB và một test tích hợp).

### 5.2 Kiểu dữ liệu (`LiveTrip/NapStopTripAttributes.swift`)

```swift
import Foundation

/// Static part of the trip Live Activity (docs/specs/T23.6.md §5.2). Every string is already localized by the app (D3).
/// Never holds coordinates. Encoded size (with ContentState) must stay far below the 4 KB limit [AK-SIZE] (LU01).
public struct NapStopTripAttributes: Codable, Hashable, Sendable {
    public var schema: Int                 // 1
    public var tripId: String
    public var destinationName: String     // trimmed, ≤ LA_DEST_MAX_CHARS, fallback "nơi đến"
    public var modeLabel: String           // "Khoảng cách · 1 km" | "Thời gian · 15 phút" | "Thông minh"
    public var isSimulated: Bool
    public var startedAtEpochMs: Int64     // D8 (age of an adopted activity)
    public var labels: Labels

    public struct Labels: Codable, Hashable, Sendable {
        public var stop: String            // "Dừng theo dõi"
        public var stopA11y: String        // "Dừng theo dõi chuyến tới Ga Đồng Hới"
        public var stale: String           // "Chưa cập nhật — mở NapStop để xem"
        public var arrivalPrefix: String   // "Dự kiến tới lúc " (template split at {time})
        public var arrivalSuffix: String   // ""
        public var remaining: String       // "Còn"
        public var simulatedBadge: String  // "Giả lập"
        public var snoozePrefix: String    // "Báo lại sau " (template "Báo lại sau {time}" split)
        public var snoozeSuffix: String
    }

    public enum Phase: String, Codable, Hashable, Sendable {
        case acquiring, tracking, estimating, alarming, snoozed, overshot
    }

    public enum Compact: String, Codable, Hashable, Sendable { case distance, eta, none }

    public struct ContentState: Codable, Hashable, Sendable {
        public var phase: Phase
        public var statusText: String          // localized, one line
        public var distanceText: String?       // "12 km" | "850 m" | "~12 km"; nil = unknown
        public var etaAtEpochS: Int64?         // whole minute; nil = unknown, simulated, or not tracking
        public var snoozeUntilEpochS: Int64?   // nil unless phase == .snoozed and real trip
        public var progress: Double?           // TripView.progress clamped 0...1
        public var compact: Compact
        public var showStop: Bool
    }
    // memberwise public inits (spelled out in code)
}

#if canImport(ActivityKit)
import ActivityKit
@available(iOS 16.1, *)
extension NapStopTripAttributes: ActivityAttributes {}   // ContentState inferred from the nested type
#endif
```

Quy tắc: thêm trường mới chỉ được thêm loại optional, có giá trị mặc định khi decode. Lý do: sau khi cập nhật app, một
activity cũ vẫn được extension mới decode. Đổi nghĩa trường → tăng `schema`, và planner kết thúc activity có `schema` khác.

### 5.3 Dựng nội dung (`LiveActivityContentBuilder`, thuần)

```swift
public struct LiveCopy: Sendable { /* resolved strings for one locale, built from NativeCopy */ }

public enum LiveActivityContentBuilder {
    public static func attributes(meta: TripMeta, startedAtEpochMs: Int64, locale: String) -> NapStopTripAttributes
    /// nowWallMs: wall clock at the Step; view.atMs is trip clock (T17 §5.3).
    public static func state(view: TripView, meta: TripMeta, nowWallMs: Int64, locale: String)
        -> (state: NapStopTripAttributes.ContentState, relevance: Double)?   // nil when view.phase == .ended
}
```

Ánh xạ `TripView` sang `ContentState`:

| Điều kiện (theo thứ tự) | phase | statusText (khoá ARB) | distanceText | showStop | relevance |
|---|---|---|---|---|---|
| `view.phase == .ended` | — (trả nil) | | | | |
| `.alarming` | alarming | `trackingAlarmRinging` "Đang báo thức" | như dòng dưới | **false** | 10 |
| `.snoozed` | snoozed | `trackingSnoozedTitle` "Đang báo lại" | như dưới | true | 50 |
| `.overshot` | overshot | `appScreenOvershootTitle` "Đã đi quá trạm" | như dưới | true | 50 |
| `.acquiring` | acquiring | `trackingAcquiring` "Đang tìm vị trí…" | nil | true | 50 |
| `locationCause == .permissionRevoked` | estimating | `trackingGpsNoPermission` "Mất quyền" | như dưới | true | 50 |
| `locationCause == .servicesOff` | estimating | `trackingGpsOff` "Định vị tắt" | như dưới | true | 50 |
| `gps == .lost` hoặc `isEstimated` | estimating | `trackingGpsLost` "Mất GPS" | như dưới | true | 50 |
| còn lại (tracking, gps ok) | tracking | `appScreenTrackingTitle` "Đang theo dõi" | như dưới | true | 50 |

- `distanceText`: `view.distanceM == nil` → nil. Ngược lại `s = NoticeFormatter.distance(Double(distanceM), locale)` (10 m
  khi < 1 km, 100 m khi ≥ 1 km, giống T17/T23). Nếu `isEstimated` hoặc `gps == .lost` thì dùng
  `trackingApprox` "~{value}".
- `etaAtEpochS`: nil nếu chuyến giả lập, hoặc `etaS == nil`, hoặc phase ∉ {tracking, estimating}. Ngược lại
  `round((nowWallMs/1000 + etaS) / 60) * 60`, làm tròn tới phút gần nhất.
- `snoozeUntilEpochS`: chỉ khi `.snoozed`, chuyến thật và `snoozeUntilMs != nil`. Giá trị
  `(nowWallMs + (snoozeUntilMs − view.atMs)) / 1000`.
- `progress`: `view.progress` kẹp trong [0, 1], nil nếu nil.
- `compact` (Q1): mode TIME → `.eta` nếu có `etaAtEpochS`, không thì `.distance` nếu có `distanceText`. Mode DISTANCE và
  SMART → `.distance` nếu có, không thì `.eta`. Không có cả hai → `.none`.
- Attributes:
  - `modeLabel` từ `settingsTripModeDistance` (distance định dạng bằng `NoticeFormatter`), `settingsTripModeTime`,
    `settingsTripModeSmart`;
  - `destinationName` qua `NativeCopy.destination(_:_:)` rồi cắt còn `LA_DEST_MAX_CHARS` ký tự (grapheme), thêm "…";
  - `stopA11y` lấy từ `liveActivityStopA11y` (mới);
  - các nhãn template tách tại `{time}`.

### 5.4 Ngân sách cập nhật (`LiveActivityThrottle`, thuần)

Cập nhật chỉ sinh ra khi runtime đã có một Step (fix, tick, sự kiện). Live Activity **không** tự thức máy, không xin vị trí
thêm. Throttle chọn Step nào được đẩy sang ActivityKit.

```swift
public struct LiveActivityThrottle: Sendable {
    public init(constants: LiveActivityConstants = .default)
    public enum Reason: String, Sendable { case first, significant, routine, keepalive }
    /// elapsedMs: TimeSource.elapsedMs() (real, monotonic, also for simulated trips — D7).
    public mutating func decide(_ s: NapStopTripAttributes.ContentState, distanceM: Int?, etaS: Int?,
                                elapsedMs: Int64) -> Reason?          // nil = skip
}
```

Pseudo-code:
```
if last == nil                                   → publish(.first)
if significant(last.state, s)                    → publish(.significant)   // never capped
if s == last.state:
    if elapsed − last.at ≥ LA_KEEPALIVE_MS       → publish(.keepalive)     // pushes staleDate forward
    else                                         → skip
near = (distanceM ≤ LA_NEAR_DISTANCE_M) || (etaS ≤ LA_NEAR_ETA_S) || s.phase == .snoozed
minGap = near ? LA_MIN_INTERVAL_NEAR_MS : LA_MIN_INTERVAL_FAR_MS
if elapsed − last.at < minGap                    → skip
if routineCount(last 3 600 000 ms) ≥ LA_ROUTINE_CAP_PER_HOUR → skip
publish(.routine)
on publish: last = (s, elapsed); if reason == .routine: append elapsed to window
significant(a, b) = a.phase != b.phase || a.showStop != b.showStop || a.statusText != b.statusText
                 || (a.distanceText == nil) != (b.distanceText == nil) || a.compact != b.compact
                 || a.snoozeUntilEpochS != b.snoozeUntilEpochS
```

Bước bị bỏ qua thì không xếp hàng, Step sau mang trạng thái mới hơn. Nếu runtime im lặng (app bị kill), `staleDate` sẽ
báo nội dung cũ.

Hằng số mặc định (`LiveActivityConstants`, không qua Remote Config, xem §12):

| Hằng | Giá trị | Ghi chú |

### 5.5 Vòng đời (`LiveActivityPlanner`, thuần)

```swift
public struct ExistingActivity: Sendable, Equatable { public let id: String; public let tripId: String
                                                      public let schema: Int; public let startedAtEpochMs: Int64 }
public enum LiveActivityCommand: Sendable, Equatable {
    case start(NapStopTripAttributes, NapStopTripAttributes.ContentState, staleAtEpochMs: Int64, relevance: Double)
    case update(id: String, NapStopTripAttributes.ContentState, staleAtEpochMs: Int64, relevance: Double)
    case end(id: String, NapStopTripAttributes.ContentState?)            // always .immediate (D6)
}
public struct LiveActivityEnv: Sendable { public let appActive: Bool; public let enabled: Bool
                                          public let nowWallMs: Int64; public let elapsedMs: Int64 }

public struct LiveActivityPlanner: Sendable {
    public init(constants: LiveActivityConstants = .default)
    /// Launch: activities the system still has, and the runtime's active trip id after restore (nil = none).
    public mutating func onLaunch(existing: [ExistingActivity], activeTripId: String?, env: LiveActivityEnv) -> [LiveActivityCommand]
    public mutating func onStep(meta: TripMeta, view: TripView, events: [TripEvent], env: LiveActivityEnv) -> [LiveActivityCommand]
    public mutating func onAppActive(env: LiveActivityEnv) -> [LiveActivityCommand]
    /// From activityStateUpdates: .ended / .dismissed not caused by our own end command.
    public mutating func onSystemEnded(id: String, env: LiveActivityEnv)
    /// Activity.request threw (or returned) — host reports back.
    public mutating func onStartResult(tripId: String, id: String?, env: LiveActivityEnv)
}
```

Trạng thái theo chuyến (một chuyến tại một thời điểm):

```
           onStep(view≠ended), appActive && enabled
  none ──────────────────────────────────────────────▶ starting ──onStartResult(id)──▶ active(id, startedAt)
   │  onStep, !appActive || !enabled                     │ onStartResult(nil)              │  onStep → update (throttle)
   ▼                                                     ▼                                 │  view ended / tripEnded → end → done
 pendingStart ──onAppActive && enabled──▶ starting   pendingStart (thử lại ở onAppActive  │  onSystemEnded:
   │ trip ended → done                                kế tiếp, tối đa 1 lần mỗi lần active)│    age ≥ 7,5 h → pendingStart (D8)
                                                                                           │    age < 7,5 h → suppressed
 suppressed: không bắt đầu lại cho tripId này; trip ended → done      done: bỏ qua mọi Step của tripId
```

- **Bắt đầu.** Bắt đầu ở Step đầu tiên có `view.phase != .ended`, khi `env.appActive && env.enabled`. Chuyến luôn được bắt
  đầu từ màn 3 lúc app mở (PRD §4), nên Step đầu thường tới khi app đang foreground. Nếu không: `pendingStart`, chờ
  `onAppActive`. Đây cũng là đường cho process do intent hoặc AlarmKit khởi chạy ở nền.
- **Cập nhật.** Ở trạng thái `active`, mỗi Step dựng state (§5.3) rồi hỏi throttle (§5.4).
- **Kết thúc.** Kết thúc khi Step có sự kiện `tripEnded` hoặc `view.phase == .ended`: lệnh `end(id, state cuối)`, trạng
  thái `done`. Có 3 lý do kết thúc theo PRD §4 (`dismissed`, `userStop`, `alarmUnanswered`), cả 3 đều kết thúc như nhau.
- **Khởi động (`onLaunch`).** `RuntimeHost` gọi sau `ensureLoaded()` + `current()`:
  - activity cùng `activeTripId` và `schema` khớp → nhận làm `active` (không start mới), cập nhật ở Step kế;
  - mọi activity khác (chuyến đã xong, schema cũ, trùng) → `end`;
  - `activeTripId == nil` → `end` tất cả.
- **App bị kill giữa chuyến.** Live Activity còn lại do hệ thống giữ, nhưng không còn ai cập nhật. Sau 15 phút nó thành
  `stale`, extension hiện `labels.stale` thay cho dòng trạng thái. Báo thức dự phòng AlarmKit vẫn kêu (PRD §4). Nếu
  StopIntent của AlarmKit chạy lại process, `RuntimeHost` khởi tạo, `onLaunch` đối soát, Step kết thúc → `end`.
- **Khởi động lại máy.** Live Activity không còn (không có tài liệu nói nó sống qua reboot, đo ở LM09b). App mở lại thì
  `onLaunch` thấy danh sách rỗng, chuyến còn chạy → bắt đầu mới (app đang active).
- **Người dùng tắt Live Activities trong Cài đặt.** `enabled = false`: không start, không báo lỗi. Bật lại khi chuyến còn
  chạy → start ở `onAppActive` kế tiếp. Activity đang chạy bị hệ thống gỡ → `onSystemEnded` → `suppressed` (< 7,5 giờ).
- **Mất quyền vị trí hoặc tắt định vị.** Chỉ đổi dòng trạng thái (§5.3), chuyến vẫn chạy.

### 5.6 `LiveActivityHost` (NapStopIOS, `@available(iOS 17.0, *)`, `#if canImport(ActivityKit)`)

```swift
public actor LiveActivityHost {
    public static func attach(to runtime: TripRuntime, time: TimeSource, appState: AppStatePort,
                              locale: @escaping @Sendable () -> String, journal: RuntimeJournal) -> LiveActivityHost
    public nonisolated func onAppActive()          // RuntimeHost observer
    public func reconcile() async                  // EndTrip intent, launch
}
```

- `attach`: `runtime.addListener { tripId, view, _, events in host.enqueueStep(...) }`. Closure chỉ `yield` vào một
  `AsyncStream` rồi trả về ngay (D1, LU22). Sau đó `Task { await runtime.ensureLoaded(); let cur = await runtime.current();
  onLaunch(existing: Activity<NapStopTripAttributes>.activities.map(...), activeTripId: cur?.meta.tripId) }`.
- Chạy lệnh tuần tự trên actor:
  - `start` → `Activity.request(attributes:content:pushType: nil)`, rồi `onStartResult`. Theo dõi `activityStateUpdates`
    của activity mới;
  - `update` → `activity.update(ActivityContent(state:staleDate:relevanceScore:))`;
  - `end` → `activity.end(content, dismissalPolicy: .immediate)`. Đánh dấu id đã tự kết thúc để bỏ qua
    `onSystemEnded` của chính nó.
- `enabled` = `ActivityAuthorizationInfo().areActivitiesEnabled`, đọc mỗi lần dựng env. `appActive` lấy từ
  `AppStatePort.activity() == .active`.
- Log: `Logger(subsystem: "app.napstop", category: "live")`, chỉ kiểu lỗi (`String(describing: type(of: error))`). Journal
  chẩn đoán: `la` với `{op: start|update|end|skip, reason, ok}`, không bao giờ có chuỗi hiển thị, khoảng cách, giờ, tên đích.
- Bản `NAPSTOP_DIAG` trên Simulator: ghi tóm tắt `flutter.napstop.diag.liveActivity` =
  `"state=<none|active|ended>;starts=N;updates=N;ends=N"` vào `UserDefaults.standard` (như `FakeSystemAlarmsIOS.summary`,
  T17.2 AC04), để test tích hợp đọc. Không có nội dung.
- `RuntimeHost` thêm `public private(set) var liveActivities: LiveActivityReconciling?`. Đây là protocol không gắn
  `@available`, có `func reconcile() async`, và `LiveActivityHost` tuân theo protocol này. Lý do: thuộc tính lưu trữ
  không được có kiểu bị giới hạn iOS 17 trong class iOS 16.
- `RuntimeHost.start()`: nếu `#available(iOS 17.0, *)` thì `LiveActivityHost.attach(...)` (cả khi `fakeAlarms`). Observer
  `didBecomeActive`/`UIScene.didActivate` gọi thêm `liveHost?.onAppActive()`.

### 5.9 Quan hệ với AlarmKit và kênh thông báo T17.3

- AlarmKit trong NapStop chỉ có trạng thái `Alert` ([ALK-WX]). Báo dự phòng đã lên lịch không hiện gì trước giờ kêu, nên
  không trùng với Live Activity của chuyến. Extension mới **không** khai báo `ActivityConfiguration` cho `AlarmAttributes`.
- Khi đang kêu, app hiện giao diện báo thức của hệ thống. Live Activity của chuyến chuyển sang `alarming`: hạ relevance
  xuống 10, ẩn nút Dừng. Như vậy không có 2 nút dừng khác nghĩa, và activity báo thức được ưu tiên hơn activity chuyến
  ([AK-REL]). Hệ thống xếp hai thứ này thế nào chưa có tài liệu → LM06.
- Kênh thông báo (iOS < 26 hoặc AlarmKit bị từ chối) dùng thông báo Time Sensitive. Live Activity không dùng
  `AlertConfiguration`, nên không có âm hay banner thứ hai. Thông báo "nhắc nhẹ" (T17 `preAlert`) giữ nguyên.
- Tắt báo thức (StopIntent) → runtime kết thúc chuyến → Step `tripEnded` → `end`. Báo lại → `snoozed` + đếm ngược.
- **Hồi quy phải canh:** thêm extension có thể đổi hành vi AlarmKit (tài liệu chỉ nói về countdown). B0-H4 và LM06/LM07
  kiểm lại S3 H9.
