## Thiết kế

### 1. Thành phần & luồng dữ liệu

```
data/routes/<route>.json ─┐
                          ├─▶ ProfileRepository (parse + validate) ─▶ Profile + Route
data/profiles/<id>.json ──┘
        │
        ▼
 Polyline (geo.dart) ─▶ MotionPlan (motion.dart) ─▶ TruthTimeline: 1 trạng thái thật / tick
                                                        │
                    SplitMix64 streams (rng.dart) ──────┤
                                                        ▼
                                  Sensor (sensor.dart): nhiễu, mất GPS, outlier ─▶ Observation? / tick
                                                        │
                       Milestones + Anchors (milestones.dart) ─▶ truth summary, mốc, case đã giải
                                                        │
                    GpxWriter + ExpectWriter (canonical_json.dart, fmt.dart) ─▶ bytes (UTF-8, LF)
                                                        │
                    CLI: generate (ghi file) │ check (so byte) │ validate (đọc + kiểm) │ list
```

Mọi bước giữa "đọc JSON" và "trả bytes" là **hàm thuần**, không IO, không đồng hồ hệ thống, không `dart:math.Random`.
IO chỉ nằm ở `cli.dart` và test.

### 5. Toán học

#### 5.1 SplitMix64 (theo bản C tham chiếu [R-SM])

```
state := seed                                    // int 64-bit
nextInt64():
  state = state + 0x9E3779B97F4A7C15             // wrap-around
  z = state
  z = (z ^ (z >>> 30)) * 0xBF58476D1CE4E5B9
  z = (z ^ (z >>> 27)) * 0x94D049BB133111EB
  return z ^ (z >>> 31)
nextDouble():   return (nextInt64() >>> 11).toDouble() * (1.0 / 9007199254740992.0)   // 2^-53
nextGaussian(): sum = 0.0; repeat 12: sum = sum + nextDouble(); return sum - 6.0     // cộng theo thứ tự
stream(seed, k): SplitMix64(seed ^ (k * 0x9E3779B97F4A7C15))                          // wrap-around
```
- Dart cho phép literal hex trong khoảng [2^63, 2^64) và hiểu là số âm (bù hai) trên VM [D-INT]. Nếu analyzer vẫn báo lỗi thì
  viết dạng số thập phân có dấu tương đương và ghi vào Implementation notes.
- Test vector (seed 0, 3 giá trị đầu, dạng hex không dấu): `0xE220A8397B1DCDAF`, `0x6E789E6AA1B965F4`, `0x06C45D188009454F`.
  Coder đối chiếu với `splitmix64.c` [R-SM]. Nếu vector trong spec sai thì tin bản C và ghi lại.
- Stream: `1` = motion (seed), `2` = noise (noiseSeed), `3` = outlier (noiseSeed).

#### 5.2 Hình học

```
cosDeg(d):  require |d| <= 90
  x = d * kDegToRad; y = x * x
  // Horner, cos x = 1 - y/2 (1 - y/12 (1 - y/30 (1 - y/56 (1 - y/90 (1 - y/132 (1 - y/182 (1 - y/240 (1 - y/306 (1 - y/380 (1 - y/462))))))))))
  r = 1.0
  for den in [462, 380, 306, 240, 182, 132, 90, 56, 30, 12, 2]:  r = 1.0 - y / den * r
  return r
distanceM(a, b):
  kx = kMetresPerDegLat * cosDeg((a.lat + b.lat) / 2)
  dx = (b.lng - a.lng) * kx ; dy = (b.lat - a.lat) * kMetresPerDegLat
  return sqrt(dx*dx + dy*dy)
offsetM(p, e, n): LatLng(p.lat + n / kMetresPerDegLat, p.lng + e / (kMetresPerDegLat * cosDeg(p.lat)))
Polyline: đoạn i có độ dài distanceM(P[i], P[i+1]); pointAt(s): tìm đoạn i có cum[i] <= s <= cum[i+1] (tìm nhị phân),
  f = (s - cum[i]) / len_i; lat = P[i].lat + f*(P[i+1].lat - P[i].lat); lng tương tự (nội suy tuyến tính lat/lng)
```
Ghi chú: các phép chia `y / den * r` giữ đúng thứ tự trên. Kinh độ luôn trong (−180, 180) ở Việt Nam, không xử lý vượt kinh tuyến 180.

### 6. Thuật toán sinh trace

#### 6.1 Lưới quãng đường và giới hạn tốc độ
```
L = polyline.lengthM; Δ = 10 m; N = ceil(L / Δ); gridS[k] = min(k*Δ, L), k = 0..N
sWp(id) = cumulativeM của waypoint id; idx(id) = round(sWp(id) / Δ) kẹp trong [0, N] (waypoint cuối -> N)
motionRng = SplitMix64.stream(seed, 1)
chunks = ceil(L / jitterChunkM); f[c] = 1 + cruiseJitter * (2*motionRng.nextDouble() - 1), c = 0..chunks-1 (rút theo thứ tự c)
limitAt(s): entry speedLimits cuối cùng có sWp(from) <= s; v = kmh / 3.6; nếu entry.jitter != false: v = v * f[floor(s / jitterChunkM)]
cap[k] = limitAt(gridS[k])
cap[0] = cap[N] = 0
dwell[k] = 0; với mỗi stop (waypoint) và regular stop: cap[idx] = 0, dwell[idx] = dwellS
dwell[0] = startDwellS (cộng dồn nếu trùng); dwell[N] = endDwellS
```
Regular stop (`regularStops`): tại `s = i * everyM` (i = 1, 2, …), bỏ điểm nào cách đầu tuyến, cuối tuyến, đích hoặc một stop
waypoint dưới `marginM`; idx = round(s / Δ).

#### 6.2 Hồ sơ tốc độ (2 lượt, gia tốc giới hạn)
```
v = copy(cap)
for k = N-1 down to 0:  v[k] = min(v[k], sqrt(v[k+1]^2 + 2*decel*Δk))    // Δk = gridS[k+1] - gridS[k]
for k = 1 to N:         v[k] = min(v[k], sqrt(v[k-1]^2 + 2*accel*Δk-1))
```

#### 6.3 Dòng thời gian và trạng thái thật theo tick
```
arriveT[0] = 0; departT[0] = dwell[0]
for k = 0..N-1:
  dt = 2*Δk / (v[k] + v[k+1])                  // v[k]+v[k+1] > 0 luôn đúng sau 6.2
  arriveT[k+1] = departT[k] + dt; departT[k+1] = arriveT[k+1] + dwell[k+1]
endT = departT[N]; ticks: t = j*I, j = 0..floor(endT / I)  (I = sampleIntervalS)
stateAt(t):
  k = chỉ số lớn nhất có arriveT[k] <= t (tìm nhị phân)
  nếu k == N hoặc t <= departT[k]: s = gridS[k]; speed = (dwell[k] > 0 ? 0 : v[k]); dwelling = dwell[k] > 0 && t >= arriveT[k]
  ngược lại: f = (t - departT[k]) / (arriveT[k+1] - departT[k]); s = gridS[k] + f*Δk; speed = v[k] + f*(v[k+1] - v[k])
  pos = polyline.pointAt(s)
```

#### 6.4 Cảm biến (nhiễu, mất GPS, outlier) — số lần rút RNG cố định
```
noise = SplitMix64.stream(noiseSeed, 2); outl = SplitMix64.stream(noiseSeed, 3)
eE = σ*noise.g(); eN = σ*noise.g()                          // khởi tạo, trước tick 0
for mỗi tick j (kể cả tick nằm trong khoảng mất GPS):
  gE = noise.g(); gN = noise.g(); uAcc = noise.u(); gS = noise.g(); uMiss = noise.u()     // luôn rút đủ, đúng thứ tự
  eE = rho*eE + sqrt(1 - rho^2)*σ*gE;  eN = rho*eN + sqrt(1 - rho^2)*σ*gN
  uOut = outl.u(); uMag = outl.u(); dE = outl.g(); dN = outl.g()                          // luôn rút đủ
  pos = offsetM(truth.pos, eE, eN)
  acc = max(accMinM, σ * 1.5 * (0.8 + 0.4*uAcc))
  speed = (uMiss < speedMissingRate) ? null : max(0, truth.speedMps + speedSigmaMps*gS)
  nếu outlierRate > 0 và uOut < outlierRate:
     r = sqrt(dE^2 + dN^2); (ux, uy) = r < 1e-9 ? (1, 0) : (dE/r, dN/r)
     m = outlierMinM + (outlierMaxM - outlierMinM)*uMag
     pos = offsetM(truth.pos, ux*m, uy*m); ghi OutlierRecord(random)
  nếu tick thuộc một scripted outlier (§6.5): pos, acc theo kịch bản; ghi OutlierRecord(scripted) (ghi đè random)
  nếu tick thuộc khoảng mất GPS: KHÔNG phát observation (RNG vẫn đã rút)
```
- `1.5·σ`: với nhiễu Gauss 2 chiều độc lập mỗi trục σ, bán kính chứa 68% ≈ 1,51σ, khớp ngữ nghĩa "accuracy = bán kính tin cậy
  68%" của Android `Location.getAccuracy()` [A-LOC] (iOS: `horizontalAccuracy` là bán kính bất định, mét [I-LOC]).
- `errorM` của outlier = `round(distanceM(pos, truth.pos))`.
- Rút RNG đủ số lần ở mọi tick để: sửa khoảng mất GPS hay thêm outlier **không** làm đổi nhiễu của các tick khác (TC12).

#### 6.5 Mất GPS và outlier có kịch bản
- `gpsGaps[i] = {at, durationS}`: `fromT` = tick đầu tiên có `s >= sWp(at)`; `toT = fromT + durationS` (loại trừ: mẫu đầu tiên
  sau khi có lại GPS ở `toT`). `durationS` phải chia hết cho `I`; `toT` phải ≤ tick cuối − I. Các khoảng không chồng nhau.
- `scriptedOutliers[i] = {atRemainingM, count, distanceToDestinationM, accM}`: tick bắt đầu = tick đầu tiên có
  `remaining(t) <= atRemainingM` và không nằm trong gap; áp dụng cho `count` tick liên tiếp (không được chạm gap, nếu chạm là
  lỗi profile). Vị trí: lấy hệ mét cục bộ quanh đích D, `(e, n)` = toạ độ của vị trí thật; `r = sqrt(e²+n²)` (r = 0 là lỗi);
  `pos = offsetM(D, e*d/r, n*d/r)` với `d = distanceToDestinationM`. Tức là điểm giả nằm cách đích đúng `d` mét, trên tia từ
  đích tới vị trí thật. `d < r` kéo điểm về gần đích (giả "sắp tới"); `d > r` đẩy điểm ra xa đích. Khi xe đang tiến về đích,
  điểm giả khi đó nằm **phía sau xe**, về phía đoạn tuyến đã đi, chứ **không** nằm bên kia đích. Khoảng cách chim bay tới đích
  tăng vọt. Kiểu này chỉ đánh lừa bộ phát hiện quá trạm dựa trên khoảng cách chim bay; chiếu lên tuyến thì nó chỉ trông như xe
  nhảy lùi. Biến thể điểm giả nằm sau đích (cần đích ở giữa tuyến) để T11.

#### 6.6 Sự thật, mốc và neo thời gian (anchor)
```
sDest = gridS[idx(destination)]; remaining(t) = sDest - s(t)          // âm khi đã đi quá
arrivalT = tick đầu tiên có s(t) >= sDest
straight(t) = distanceM(truth.pos(t), D)
stops: với mỗi chỉ số dừng (waypoint stop, regular stop; không tính đầu/cuối tuyến):
  arriveT = tick đầu tiên có s(t) == gridS[idx] và dwelling; departT = tick cuối cùng như vậy
overshoot (chỉ khi tuyến còn >= 1000 m sau sDest):
  closestM = min straight(t) trên mọi tick; destDepartT = tick cuối có s(t) == sDest (hoặc arrivalT nếu không dừng)
  overshoot.t = tick đầu tiên > destDepartT có s(t) > sDest và straight(t) >= closestM + 1000
milestones.distance: X ∈ [200, 500, 1000, 2000, 3000, 5000, 10000, 25000, 50000], chỉ ghi X < remaining(0):
  routeT = tick đầu có remaining <= X; straightT = tick đầu có straight <= X (null nếu straight(0) <= X)
milestones.time: N ∈ [5, 10, 15, 20, 30, 60] phút, chỉ ghi khi arrivalT - 60N >= 0: t = arrivalT - 60N
```
Ngữ pháp **anchor** (dùng trong cửa sổ kỳ vọng của case):
```
anchor := "start" | "end" | "arrival" | "overshoot"
        | "gpsGap[" <int> "]." ("start" | "end")
        | ("route" | "straight") "<=" <int mét>
```
- `start` = 0; `end` = tick cuối; `arrival` = arrivalT; `overshoot` = overshoot.t (lỗi nếu trace không có overshoot);
  `gpsGap[i].start/end` = fromT/toT (lỗi nếu i ngoài phạm vi); `route<=X`/`straight<=X` = tick đầu thoả điều kiện (0 nếu thoả
  ngay từ đầu; lỗi nếu không bao giờ thoả).
- Giá trị cửa sổ = `clamp(anchor + offsetS, 0, durationS)`. Sau khi giải, phải có `notBefore <= notAfter`, nếu không là lỗi profile.

Quy tắc (byte-exact, đúng thụt lề 2 dấu cách như trên, mỗi `trkpt` một dòng):
- `lat`, `lon`: 7 chữ số thập phân (≈ 1 cm). `time`: UTC, giây nguyên, hậu tố `Z`. Thứ tự con của `trkpt` theo XSD: `time` rồi
  `extensions` (không có `ele`).
- `napstop:acc` (bắt buộc): độ chính xác ngang, mét, 1 chữ số thập phân, > 0. Ngữ nghĩa như Android `getAccuracy()` / iOS
  `horizontalAccuracy`.
- `napstop:spd` (tuỳ chọn): tốc độ mặt đất, m/s, 2 chữ số thập phân, ≥ 0. **Vắng** = thiết bị không báo tốc độ (Android
  `hasSpeed() == false`, iOS `speed < 0`) [A-LOC][I-LOC].
- Không có hướng (bearing) và độ cao: khớp `LocationSample` ở ARCHITECTURE §2.
- Mất GPS biểu diễn bằng **`trkseg` mới**, đúng khuyến nghị của GPX 1.1 cho trường hợp mất tín hiệu [GPX]. Trong cùng
  `trkseg`, các mẫu cách đều `sampleIntervalS`.
- Escape `& < > " '` trong text và thuộc tính. Extension thuộc namespace khác GPX nên hợp lệ với XSD (`xsd:any
  namespace="##other" processContents="lax"`).

**Cách đọc cho consumer (Kotlin/Swift/Dart):** lấy mọi `trk/trkseg/trkpt` theo thứ tự tài liệu, nối lại thành một chuỗi;
`t = time − startTime` (giây). Thời gian tăng nghiêm ngặt. Có thể lấy thưa (mỗi k mẫu một) một cách tất định nếu T10 cần
mô phỏng chu kỳ lấy mẫu dài.

**Đồng hồ ảo của harness (bắt buộc, T12/T13/T18):**
- Harness cho đồng hồ ảo tiến từng bước `sampleIntervalS` từ `0` tới `durationS`, **kể cả trong khoảng mất GPS** (các tick
  `fromT <= t < toT` không có mẫu nào), và **gọi engine ở mọi tick**. Nhờ vậy các quy tắc theo thời gian (phát hiện mất GPS,
  "đang mất tín hiệu mà ETA < 20 phút thì báo luôn") phát được ngay trong khoảng mất GPS.
- Không được chỉ gọi engine khi có mẫu mới: khi đó engine chỉ "thấy" khoảng mất GPS ở mẫu `toT`, tức là sau khi xe đã ra khỏi
  hầm.
- Sự kiện phát ra khi xử lý tick (hoặc mẫu) `t` được tính là xảy ra lúc `t`.
- Hệ quả: cửa sổ `gpsLost`/`alarm` của case hầm kết thúc ở `gpsGap[0].end − sampleIntervalS` (tick cuối còn trong khoảng mất
  GPS), không phải ở `toT` (§8.4).

#### 7.4 Định dạng số và JSON chuẩn tắc
- `fmt(x, d)`: `x.toStringAsFixed(d)`; nếu kết quả khớp `^-0\.0+$` thì bỏ dấu `-`.
- lat/lng: `fmt(x, 7)` trong cả GPX và JSON; `acc`: `fmt(x, 1)`; `spd`: `fmt(x, 2)`. Số nguyên trong JSON: `round()` của Dart
  (làm tròn nửa ra xa 0), in dạng thập phân không có dấu `.`.
- Writer JSON tự viết (`canonical_json.dart`), bố cục giống `JsonEncoder.withIndent('  ')`: mỗi phần tử một dòng, `"key": value`,
  mảng/đối tượng rỗng là `[]`/`{}`, có `\n` ở cuối file. Chuỗi: escape `"`, `\`, và ký tự < U+0020 (`\b \f \n \r \t`, còn lại
  `\u00XX` chữ thường); ký tự ngoài ASCII (tiếng Việt, `→`) ghi nguyên UTF-8; không escape `/`. Số thập phân bọc trong
  `Fixed(value, decimals)`.

#### 7.5 Kiểm hợp lệ (`validate`, cũng dùng trong test)
GPX: XML well-formed, khai báo UTF-8; root `gpx` namespace GPX 1.1, `version="1.1"`, `creator` khác rỗng; đúng 1 `trk`, ≥ 1
`trkseg`, mỗi `trkseg` ≥ 1 `trkpt`; `lat ∈ [−90, 90]`, `lon ∈ [−180, 180)`; `time` đúng mẫu `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ$`,
tăng nghiêm ngặt; `acc` có, hữu hạn, > 0; `spd` nếu có thì ≥ 0; không có BOM, không có `\r`.
Cặp GPX + expect: `schemaVersion == 1`; đủ key bắt buộc; `sampleCount`, `startTime`, `durationS` khớp GPX; trong một `trkseg`
khoảng cách thời gian đúng bằng `sampleIntervalS`; mỗi `gpsGaps[i]` không có mẫu trong `[fromT, toT)` và đúng là chỗ ngắt
`trkseg`; số `trkseg` = số gap + 1; mọi `0 <= notBefore <= notAfter <= durationS`; `event`/`forbid` thuộc tập tên v1; một sự
kiện không vừa ở `expect` vừa ở `forbid` của cùng case; `cases[].id` duy nhất.
Mọi lỗi in dạng `<file>:<vị trí>: <mô tả>`; `validate` liệt kê hết lỗi rồi mới trả exit 1.

#### 7.6 Version
- `schemaVersion` tăng khi có thay đổi **phá vỡ** (đổi tên, bỏ trường, đổi ngữ nghĩa). Thêm trường tuỳ chọn, tên sự kiện mới,
  anchor mới là thay đổi **bổ sung**, giữ nguyên version; consumer **phải bỏ qua** key lạ.
- Namespace extension GPX có `/1`; thêm phần tử extension mới là thay đổi bổ sung.
- `generator.version` (= `kGeneratorVersion` = version trong `pubspec.yaml`): tăng khi code generator làm đổi output với cùng
  input (patch), thêm tính năng (minor), đổi schema (major). Đổi dữ liệu profile/route thì không cần tăng.

#### 8.1 File lộ trình `data/routes/<id>.json`
```json
{
  "id": "road_dn_langco",
  "title": "Bến xe Trung tâm Đà Nẵng → Lăng Cô qua hầm Hải Vân",
```

- `source` khớp `^(osm:(node|way|relation)/\d+|approx)$`. `osm:` = toạ độ lấy từ OSM (Nominatim, đã tra ngày 2026-10-28, xem
  [OSM]); `approx` = điểm uốn ước lượng (sai lệch có thể tới vài trăm mét). Coder **được** tinh chỉnh điểm `approx` theo bản đồ OSM

### Quyết định nhỏ / sai khác với spec

1. **Hằng số SplitMix64:** cả literal hex ≥ 2^63 lẫn số thập phân có dấu tương đương đều bị lint `avoid_js_rounded_ints`
   (VGA 11) báo, nên viết bằng hai nửa 32 bit: `(0x9E3779B9 << 32) | 0x7F4A7C15` (hằng số compile-time, cùng giá trị bit).
   Test vector §5.1 **đúng** (đã đối chiếu bằng bản tái hiện BigInt của `splitmix64.c`); test so qua `BigInt.toUnsigned(64)`
   vì `int.toUnsigned(64)` trên VM vẫn trả số âm.
2. **Cú pháp Dart 3.13:** `factory new(...)` là lỗi biên dịch (`factory_constructor_new_name`); factory không tên viết
   `factory (...)` (Polyline), factory có tên `factory stream(...)`, constructor riêng `new _(...)`.
3. **`kGeneratorVersion`** nằm ở `lib/src/expect_writer.dart` (cùng `kSchemaVersion`) thay vì `generator.dart`, để tránh
   import vòng `generator ↔ expect_writer`; vẫn export qua `package:tracegen/tracegen.dart`. TC21 kiểm khớp pubspec.
4. Thêm file `lib/src/anchor.dart` (không có trong danh sách file của spec) cho ngữ pháp anchor, dùng chung bởi profile và
   milestones.
5. Kiểm thêm ngoài spec (đều → `ProfileException` kèm đường dẫn, exit 65):
   - stop trên lưới phải cách đầu/cuối tuyến và cách stop khác ≥ 2 ô (nếu không thì `v[k] + v[k+1] = 0` ở §6.3, chia 0);
     trạm `regularStops` rơi vào trường hợp này bị bỏ qua thay vì báo lỗi;
   - gap phải bắt đầu sau t = 0 và các gap không được chạm nhau (`fromT > toT` của gap trước), để mọi `trkseg` có ≥ 1 mẫu;
   - đích không được là waypoint đầu; đích phải có tick tới được (với `endDwellS = 0` mà `endT` không chia hết cho I thì
     tick cuối nằm trước lúc tới đích → lỗi rõ ràng);
   - một case không được kỳ vọng cùng một sự kiện hai lần; trường số nguyên không nhận số thập phân (`5.5`).
6. `stops`, `gpsGaps`, `scriptedOutliers` là tuỳ chọn trong profile (mặc định `[]`, đúng ý "rỗng nếu không ghi" §8.4); 6 file
   data vẫn ghi đủ.
7. Outlier ngẫu nhiên rơi vào tick trong gap **không** được ghi vào `truth.outliers` (không có mẫu tương ứng). Tick scripted
   giữ tốc độ nhiễu bình thường (spec chỉ thay `pos`, `acc`).
8. `generate` sinh mọi trace trong bộ nhớ trước rồi mới ghi (profile lỗi thì không ghi file nào). `list` nạp và kiểm từng
