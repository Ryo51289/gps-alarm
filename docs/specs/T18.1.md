## Bối cảnh & mục tiêu

- PRD §4 "Chế độ giả lập (demo)": phát trace qua **cùng** đường ống Location → Trip Engine → Alarm như dữ liệu thật, 1×/10×/60×. Android xong
  ở T18; iOS hiện trả `simulation-unavailable`. Bản demo TestFlight (PLAN-ios) cần giả lập để trình diễn trên iPhone khoá màn hình.

  báo `GPS_LOST` thay vì `DISTANCE`. Nguyên nhân: Step lấy giờ của đồng hồ chuyến lúc **xử lý**. Bộ phát mẫu và Tick chạy theo giờ thật, nên một
  Tick (hẹn giờ) tới sau một khoảng trễ thật nhỏ (> 100 ms ở 600× = 60 s ảo = `gpsLostMinS`) thấy fix cuối đã "cũ" trong khi mẫu kế tiếp vẫn
  chưa được giao.

### 3. Đồng hồ (`TripClock.swift`)

```swift
public struct ClockAnchor: Sendable, Codable, Equatable {
    public let wallMs: Int64; public let elapsedMs: Int64; public let bootSessionId: String?
    public let speed: Double               // mới; decode: thiếu → 1.0; không hữu hạn hoặc ≤ 0 → lỗi codec
}
public struct TripClock: Sendable {
    // up(d)   = speed == 1.0 ? d : Int64(floor(Double(d) * speed))
    // down(d) = speed == 1.0 ? d : Int64(ceil(Double(d) / speed))
    // tripAt(e) = anchor.wallMs + up(e − anchor.elapsedMs)
    public mutating func now(_ t: TimeSource) -> Int64                    // max(lastIssued, tripAt(t.elapsedMs()))
    public mutating func toWall(_ tripMs: Int64, _ t: TimeSource) -> Int64   // t.wallMs() + down(max(0, tripMs − now))
    public mutating func toTrip(wall w: Int64, _ t: TimeSource) -> Int64     // now − up(max(0, t.wallMs() − w))
    public mutating func futureWallToTrip(_ w: Int64, _ t: TimeSource) -> Int64  // now + up(max(0, w − t.wallMs()))
    public mutating func realDelayMs(_ tripMs: Int64, _ t: TimeSource) -> Int64  // down(max(0, tripMs − now))
    public mutating func rebase(_ newSpeed: Double, _ t: TimeSource) -> Bool   // e = elapsed; n = max(lastIssued, tripAt(e)); lastIssued = n; anchor = (n, e, boot, newSpeed)
    /// Vòng 2 (D8): neo lại ở giờ chuyến `atTripMs` thay vì giờ đồng hồ. Chỉ dùng cho D8.
    public mutating func rebase(_ newSpeed: Double, _ t: TimeSource, atTripMs: Int64) -> Bool
        // e = elapsed; anchor = (atTripMs, e, boot, newSpeed); lastIssued = atTripMs
    // Cả hai: newSpeed không hữu hạn hoặc ≤ 0 → false, đồng hồ giữ nguyên (Kotlin ném IllegalArgumentException).
}
```

**`rebase(atTripMs:)` (vòng 2, designer chấp nhận 06/11).** Đây là ngoại lệ có chủ đích của "đồng hồ không lùi": đồng hồ lùi từ `clock.now()` về
`atTripMs`. Đúng nghĩa vì phần giờ ảo `(atTripMs, clock.now()]` **chưa từng được giao cho engine hay ra ngoài**: nó chỉ là khoảng mà vòng đuổi kịp
chưa kịp xử lý. Sau khi neo lại, khoảng đó được phát lại ở 1× từ giờ thật hiện tại (trace "dừng" đúng bằng độ trễ đuổi kịp), nên dãy sự kiện vẫn
là hàm của trace (D2). Điều kiện bắt buộc (reviewer đọc mã, test SIU21 dưới):
1. `atTripMs = step.atMs` của Step báo, và `atTripMs ≥` mọi `atMs` đã giao cho engine (Step báo là Step mới nhất) — engine không bao giờ thấy thời
   gian lùi.
2. Không giá trị giờ chuyến nào > `atTripMs` đã ra khỏi runtime trước khi neo lại: `TripStateMsg`/sự kiện lấy giờ từ engine (≤ `atTripMs`);
   vòng đuổi kịp lấy giới hạn `min(target, clock.now())` **đọc lại ở mỗi sự kiện**, nên sau khi neo lại không xử lý sự kiện nào quá giờ mới.
3. Đầu vào ngoài lấy `atMs = max(engine.nowMs, min(target, clock.now()))` (D5 làm rõ).
4. Đổi giờ thật → giờ chuyến (`toTrip`, `toWall`, `realDelayMs`) sau khi neo lại dùng neo mới; mọi thứ theo giờ thật (`deferred`, `simGuard`,
   giờ AlarmKit) không bị ảnh hưởng.
5. `rebase(_:_:)` gốc giữ nguyên ngữ nghĩa §3 cũ (SIU03 = SM03), chỉ dùng lúc bắt đầu chuyến (D2 của T18).
- `speed == 1.0` đi nhánh nguyên (không phép số thực): T17 không đổi kết quả (SIU01).
- `anchorValid`/`sameBoot` không đổi. Chuyến giả lập không khôi phục (D10) nên không cần neo lại theo tốc độ.
- `EffectPlanner` đổi giờ wall → trip (obligation 3, `RingFacts.ringStartedAtWallMs`) dùng `up(...)`: `PlanInput` thêm `speed` (mặc định 1,0).

### 4. GPX và `SimDriver` (`TripRuntime/Sim/*.swift`, thuần)

```swift
public struct TraceSample: Sendable, Equatable, CustomStringConvertible {   // description che toạ độ
    public let t: Int; public let lat: Double; public let lng: Double; public let accM: Double; public let spdMps: Double?
}
public struct SimTrace: Sendable { public let id: String; public let samples: [TraceSample] }   // t tăng nghiêm ngặt, samples[0].t == 0
public struct SimSpec: Sendable, Codable, Equatable { public let traceId: String; public let speedFactor: Double }
public enum SimTraceIds { public static func valid(_ id: String) -> Bool }   // ^[a-z0-9]+(_[a-z0-9]+)*$, ≤ 64
public struct TraceFormatError: Error, Equatable { public let rule: String }  // không chứa số/toạ độ
public enum TraceGpx {
    public static let ns = "https://napstop.app/xmlns/trace/1"
    public static func parse(_ data: Data) throws(TraceFormatError) -> [TraceSample]   // luật T18 §4
}
public protocol TraceStore: Sendable { func open(_ traceId: String) -> Data? }        // cổng, RuntimePorts.traces (mặc định: luôn nil)

public enum SimEvent: Sendable, Equatable {
    case fallbackDue(atTripMs: Int64)
    case engineWake(atTripMs: Int64)
    case sample(TraceSample, atTripMs: Int64)
}
public struct SimDriver: Sendable {
    public init(trace: SimTrace, startTripMs: Int64)
    public var fallbackDueTripMs: Int64?          // D6
    public var engineWakeTripMs: Int64?           // = setTimer(dueTripMs) của EffectPlanner khi chuyến là giả lập
    public mutating func nextDueTripMs(intervalMs: Int64?) -> Int64?      // min(fallbackDue, engineWake, mẫu kế tiếp đủ điều kiện D4)
    /// Lấy và xoá sự kiện kế tiếp có giờ ≤ `upTo`, theo thứ tự D3; nil nếu không còn.
    public mutating func pop(upTo: Int64, intervalMs: Int64?) -> SimEvent?
}
```
`TraceGpx.parse` theo đúng luật T18 §4: `trkpt` có `lat`, `lon` hữu hạn trong khoảng; `time` ISO-8601 UTC (bằng `ISO8601DateFormatter` có
`.withFractionalSeconds` khi cần; coder kiểm định dạng trong `fixtures/traces/README.md` §2); `napstop:acc` hữu hạn > 0; `napstop:spd` nếu có
thì hữu hạn ≥ 0; thời gian tăng nghiêm ngặt; ≥ 1 mẫu; `t = (time − time₀)/1000`. Không giới hạn số `trkseg`.

`pop` (D3, D4): khi đang không có yêu cầu vị trí (`intervalMs == nil`, chưa `applySampling` hoặc đang `headless`), mẫu tới hạn bị **bỏ** (như GPS
không có), không giao dồn sau đó.

### 9. Ghi chú cho T18.2 (Android)

Cách D2 (xử lý theo giờ ảo của sự kiện, một hàng đợi có thứ tự, đuổi kịp trước đầu vào ngoài) áp được nguyên cho `:core-runtime` và sửa gốc lỗi
T18.2 (không cần giới hạn 60× hay tách luồng phát mẫu). Đề xuất designer của T18.2 xem xét; không thuộc T18.1.

**Bổ sung vòng 2 — áp được cho Android, đề xuất đưa vào T18.2:**
- **Neo lại D3 ở giờ Step báo.** `TripClock.kt` (T18 §3) thêm `rebase(newSpeed, atTripMs)` với điều kiện 1–5 ở trên; `applyStep` gọi nó với
  `step.view.atMs` thay cho `rebase(1.0)` neo ở `clock.now()`. Trên Android cùng lỗi tiềm ẩn: `SimulatedLocationSource` và hẹn giờ giả lập dùng chung
  `actorDispatcher`; nếu actor bận khi tới giờ báo ở 600×, phần giờ ảo đã trôi bị xử lý dồn ngay sau `rebase(1.0)`. Chỉ có ý nghĩa đầy đủ khi
  Android cũng xử lý theo giờ ảo của sự kiện (D2); nếu T18.2 chỉ sửa cục bộ (ví dụ tách luồng) thì neo ở giờ Step báo vẫn đúng và vô hại.
- **`rearm`/thế hệ hẹn giờ:** không áp nguyên — Android dùng `AlarmManager`/coroutine `delay` theo từng mốc, không có cơ chế một hẹn giờ dùng chung
  có thế hệ. Designer T18.2 chỉ cần kiểm `scheduleAwakeTick`/`SimAlarmScheduler` không huỷ-đặt lại một mốc đã tới hạn ở mỗi Step.
