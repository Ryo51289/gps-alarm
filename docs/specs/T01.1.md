# T01.1 — Chế độ test nhanh cho vòng lặp dev (`-Pnapstop.quick=true`)
Trạng thái đề xuất: spec-ready

## Bối cảnh & mục tiêu
- `./gradlew :core-trip:test :core-runtime:test` đã chậm dần theo các vòng T12.x/T15/T16/T18. Ở T12.1, `:core-trip` mất 28–52 s
  (823 test). Sau khi có fuzz T10.6 thì `:core-trip` lên **2 ph 38 s – 6 ph 24 s** (test report T12.3, review T12.3).
  Lần chạy đủ `:core-runtime` ngày 04/11 (XML trong `app/build/core-runtime/test-results/test/`) có tổng thời gian class **≈ 117 s**.
- Coder phải chạy lại bộ này nhiều lần mỗi vòng sửa. PO duyệt ngày 05/11: thêm cờ Gradle `-Pnapstop.quick=true` để chạy bản
  rút gọn khi lặp. **Không cờ = chạy đủ** (giữ nguyên hành vi). Tester và CI luôn chạy đủ, `ci.yml` không đổi.
- Không đổi hành vi app hay Trip Engine. CLAUDE.md có quy tắc "mọi thay đổi chạm Location/Trip/Alarm phải có test trace"
  (độ tin cậy). Quy tắc này vẫn đảm bảo vì bản đủ là cổng bắt buộc trước `in-review` và ở tester/CI.

## Phạm vi
**Làm:** cờ `napstop.quick` cho `:core-trip` và `:core-runtime`; gắn `@Tag("slow")` ở mức method cho các test chậm theo quy tắc
§3; thêm một test canh (guard) cho mỗi module; đo trước/sau; tài liệu lệnh và quy tắc dùng trong `CLAUDE.md`.
**KHÔNG làm:** đổi `ci.yml`; đổi số seed, phase hay kỳ vọng của bất kỳ test nào; chạy song song (`maxParallelForks`, JUnit
parallel); cờ quick cho `:app` hay Swift (Swift chỉ đề xuất ở §8); sửa logic harness `Suite`.

## Thiết kế

### 1. Chọn cơ chế: JUnit 5 `@Tag("slow")` + `excludeTags` (đã chọn)
| | A. `@Tag("slow")` + `excludeTags("slow")` khi quick | B. Hệ số thu nhỏ số seed/phase khi quick |
|---|---|---|
| Sửa test | Thêm 1 annotation + import, không đổi thân test | Sửa vòng lặp của từng fuzz (`1L..6_000L` → `n(6_000)`) |
| Kỳ vọng thống kê | Không chạm | **Vỡ**: `steps > 100_000`, `urgent >= 150`, `runs >= 300`, seed ghim 55/433/787 (T123 g) phải đổi theo hệ số |
| Kết quả ghi ra file | Không đổi | Bản quick ghi file `u126-*.txt`, `t132p-*.txt` khác bản đủ, dễ đọc nhầm |
| Độ phủ ở quick | Bỏ hẳn những test đã gắn tag | Giữ mỗi test một ít |
| Rủi ro lệch bản đủ | Không có (bản đủ y hệt hiện tại) | Phải bảo đảm hệ số = 1 khi không cờ ở mọi chỗ |

**Quyết định: A.** Lý do: đơn giản, không đụng tới kỳ vọng nào, bản đủ giữ nguyên từng byte. Gradle hỗ trợ sẵn
`useJUnitPlatform { excludeTags(...) }`. Bộ lọc tag của JUnit Platform chạy ở bước discovery. Khi một method
`@TestFactory` bị loại thì method đó không được gọi, nên không sinh dynamic test nào; test case Q03 kiểm điều này.

### 2. Gradle (cả hai `build.gradle.kts`)
```kotlin
// T01.1: -Pnapstop.quick=true skips @Tag("slow") (dev loop only). No flag / any other value = full suite (CI, tester).
val quickTests = providers.gradleProperty("napstop.quick").orNull == "true"

tasks.test {
    useJUnitPlatform { if (quickTests) excludeTags("slow") }   // replaces the current useJUnitPlatform()
    inputs.property("napstop.quick", quickTests)              // quick <-> full never reuses an UP-TO-DATE result
    if (quickTests) doFirst { logger.lifecycle("napstop.quick=true: @Tag(\"slow\") tests skipped - run the full suite before in-review") }
    // ... existing lines unchanged
}
```
- Chỉ giá trị chính xác `true` mới bật quick. Không có cờ, `false` hay giá trị khác (`1`, `yes`) đều chạy đủ, đây là hướng an toàn.
- `:core-runtime` thêm `systemProperty("napstop.testSrcDir", projectDir.resolve("src/test/kotlin").absolutePath)` (guard cần).
  `:core-trip` đã có sẵn dòng này.
- `--tests` vẫn kết hợp được với quick. Gradle giữ bộ lọc khai báo trong build script, nên test có tag `slow` vẫn bị loại.
  Muốn chạy riêng một test slow thì bỏ cờ: `./gradlew :core-trip:test --tests '*TesterT121Test*'`.

### 3. Quy tắc gắn `slow`
Gắn `@Tag("slow")` (`org.junit.jupiter.api.Tag`) **ở mức method**, đặt ngay trên dòng `@Test`/`@TestFactory`. Không gắn ở mức
class. Một method được gắn khi thoả **cả ba** điều kiện:
1. Thuộc một trong các nhóm: fuzz hoặc thống kê nhiều chuyến ngẫu nhiên (≥ 100 kịch bản); quét (kill sweep, quét phase/tốc độ
   trên trace dài); hoặc chờ đồng hồ thật (`Thread.sleep`, disk treo thật);
2. Thời gian đo ở lần chạy đủ gốc **≥ 2,0 s**. Riêng `T123 g` là ngoại lệ: phải gắn vì nó gọi lại U126 a/b (§3.3);
3. Không nằm trong danh sách bắt buộc chạy ở §3.1.

### 4. `SlowTagGuardTest` (mỗi module một file, unit thuần, chạy ở cả hai chế độ)
Đường dẫn: `core-trip/src/test/kotlin/app/napstop/core/trip/SlowTagGuardTest.kt` và
`core-runtime/src/test/kotlin/app/napstop/core/trip/runtime/SlowTagGuardTest.kt`.
```
testSrc = File(System.getProperty("napstop.testSrcDir") ?: "src/test/kotlin")
EXPECTED: Set<String>  = { "<FileName>.kt#<method name, no backticks>", ... }   // exactly the final list of §3.2
MUST_RUN: Set<String>  = file names of §3.1 for this module (whole-class entries)
for f in testSrc/**/*.kt, f.name != "SlowTagGuardTest.kt":
    text = f.readText()
    anyTag = Regex("""@Tag\("([^"]*)"\)""").findAll(text)
    every anyTag value == "slow"                                   else fail "unknown tag <v> in <f>"
    placed = Regex("""@Tag\("slow"\)\s*\R\s*@(Test|TestFactory)\s*\R\s*fun\s+(`[^`]+`|\w+)""").findAll(text)
    count(anyTag) == count(placed)                                 else fail "@Tag must sit right above @Test/@TestFactory (<f>)"
    if f.name in MUST_RUN: count(anyTag) == 0                      else fail "<f> must run in quick mode"
    found += placed.map { f.name + "#" + it.group(2).trim('`') }
assertEquals(EXPECTED, found)   // message lists missing / extra
```
Tên test: `T01_1 slow tags are exactly the reviewed list, method level, never on must-run classes` (core-trip, dùng tên có
backtick theo phong cách của module) và `t011_slowTagsAreTheReviewedList()` (core-runtime). Thêm một test slow mới sau này
nghĩa là phải sửa `EXPECTED`, nên reviewer sẽ thấy thay đổi trong diff.

### 5. Đo
Đo trên máy dev Windows (Git Bash), daemon đã ấm, cắm sạc và tắt sleep (xem T13 test report #5 về Modern Standby). Lấy
**trung vị của 2 lần**. "Thời gian test" của một module là tổng `testsuite@time` trong XML. Fork JVM chạy tuần tự, nên con số
này ≈ thời gian chạy test thật và không gồm biên dịch.
```bash
cd app/android
./gradlew :core-trip:test --rerun :core-runtime:test --rerun                       # full (--rerun is per task)
./gradlew :core-trip:test --rerun :core-runtime:test --rerun -Pnapstop.quick=true  # quick
for m in core-trip core-runtime; do
  grep -ho '<testsuite name="[^"]*" tests="[0-9]*"[^>]* time="[0-9.]*"' ../build/$m/test-results/test/*.xml \
    | sed -E 's/.*name="([^"]*)" tests="([0-9]*)".* time="([0-9.]*)"/\3 \2 \1/' | sort -rn \
    | awk -v m=$m '{t+=$1; n+=$2; print} END {printf "== %s: %d tests, %.1f s\n", m, n, t}'
done
```
Implementation notes ghi các bảng sau:
- **Trước** khi sửa: số test và thời gian của từng module; top 15 class; thời gian từng method của các ứng viên §3.2
  (lấy từ `<testcase … time>`).
- **Sau** khi sửa: số test đủ, số test quick, thời gian đủ và quick, tỉ lệ quick/đủ, wall time Gradle của cả hai chế độ.

> **Test nhanh (T01.1).** `-Pnapstop.quick=true` chỉ dùng cho vòng lặp của coder. Coder phải chạy **đủ** (không cờ) ít nhất
> một lần sau lần sửa cuối, trước khi báo `in-review`, và ghi kết quả vào Implementation notes. Reviewer chạy quick cho cả hai
> module, cộng thêm các class bị diff chạm tới ở chế độ đủ (`--tests`, không cờ). Tester và CI luôn chạy đủ, không dùng cờ.
> Test mới thuộc nhóm fuzz/quét/đồng hồ thật và tốn ≥ 2 s thì gắn `@Tag("slow")`, đồng thời thêm vào `SlowTagGuardTest`.

**`.claude/agents/{coder,reviewer,tester}.md`**: các file này là cấu hình agent nên **orchestrator áp dụng**, không giao
cho coder. Mỗi file thêm một dòng tương ứng với đoạn trên vào bước "chạy kiểm tra":
- coder bước 4: thêm lệnh quick, kèm ghi chú "chạy đủ một lần trước in-review";
- reviewer bước 3: thêm "quick + class liên quan chế độ đủ";
- tester bước 5: thêm `./gradlew :core-trip:test :core-runtime:test` **không cờ**.

## Tiêu chí chấp nhận
1. Không cờ (hoặc giá trị khác `true`): tập test của `:core-trip` và `:core-runtime` bằng tập trước khi sửa cộng 2 guard,
   kỳ vọng không đổi, `ci.yml` không đổi (Q02, Q05, Q09).
2. `-Pnapstop.quick=true`: P05ManifestTest, IdCoverageTest, TraceSuiteTest, TraceRuntimeTest, T18 parity cùng các unit test
   ở §3.1 vẫn chạy và xanh. Các method §3.2 không chạy (Q03).
