  các ca biên U05 của T25.
- CLAUDE.md: package `app.napstop.core.trip`; không chặn main thread; mọi hàm logic thuần phải có unit test; không log toạ độ.
- T14 §5.1: T15 sẽ bọc engine trong `TripBackend` (`addListener`/`ListenerHandle`). Engine **không** biết gì về `TripBackend`,
  coroutine, IO hay đồng hồ.

### 5. Làm rõ hợp đồng T10 (bắt buộc cho cả T12 và **T13**)

Các mục dưới đây chọn **một** nghĩa ở những chỗ T10 chưa viết rõ. Không mục nào đổi hành vi ở chỗ T10 đã rõ. T13 phải làm đúng như vậy,
nếu không P05 lệch.

**C1 — R3-1: trạng thái `fb` (review T10 R3-1, `T10.md:611`, `:1119`).** Mọi thay đổi `fb`:

| Chỗ | `fb` sau đó | Sự kiện |
|---|---|---|
| FallbackPlanner phát (`nextFallbackAt ≠ null`) | `{at, now, REQUESTED, null, false, near = toS(predicted − now) ≤ fallbackNearS}` | `FallbackAlarmChanged(at, RESYNC nếu targetAtMs == null && resync, ngược lại ETA)` |
| `FallbackScheduled(x, ok)` với `x == fb.targetAtMs`, pha ≠ ENDED (gồm cả SNOOZED) | `ok` → `status = CONFIRMED`, `confirmedAtMs = now`; `!ok` → `status = FAILED`, `confirmedAtMs = null` | — |
| `FallbackScheduled` với `x ≠ fb.targetAtMs` (gồm cả khi `targetAtMs == null`) | không đổi | — |
| ALARMING → SNOOZED (`SNOOZE`) | **`{untilMs + fallbackLagS·1000, now, REQUESTED, null, false, false}`** | `Snoozed`, `FallbackAlarmChanged(…, SNOOZE)` |
| `restore` MISSING + SNOOZED, `now < snoozeUntilMs` | **`{snoozeUntilMs + fallbackLagS·1000, now, REQUESTED, null, false, false}`** | `FallbackAlarmChanged(…, RESYNC)` |
| `restore` MISSING + SNOOZED, `now ≥ snoozeUntilMs` | `CLEARED` | không có (bước Tick phát `Alarm(SNOOZE_END)`, không có SUPERSEDED) |
| `restore` MISSING, chưa báo, chưa tới giờ | `{null, null, NONE, null, resync = true, false}` | (bước Tick phát RESYNC) |
| Vào ALARMING/OVERSHOT bằng `Alarm(ringNow=true)` (gồm SNOOZE_END, quá trạm ở SNOOZED) | `CLEARED` | `FallbackAlarmChanged(null, SUPERSEDED)` **chỉ khi** `targetAtMs ≠ null` trước đó |
| Vào ENDED (DISMISS, STOP_TRIP, ALARM_UNANSWERED, restore DISMISSED) | `CLEARED` | `FallbackAlarmChanged(null, TRIP_ENDED)` chỉ khi `targetAtMs ≠ null` |
| `FallbackFired` ở ACQUIRING/TRACKING/SNOOZED; restore RANG/UNKNOWN đã tới giờ/MISSING đã tới giờ | `CLEARED` | không có SUPERSEDED |

Hệ quả cho U84/U89(a):
- Sau SNOOZE, view có `fallbackAtMs = untilMs + 30 000` và `fallbackStatus = REQUESTED`.

### 6. Số học tất định trong Kotlin (D1–D7)

### 7. JSON

#### 7.1 `MiniJson`
- Parser đệ quy, đúng ngữ pháp RFC 8259: khoảng trắng gồm space/tab/LF/CR; chuỗi có escape `\" \\ \/ \b \f \n \r \t \uXXXX`
  (gồm cặp surrogate); không chấp nhận BOM, comment, dấu phẩy thừa, `NaN`/`Infinity`, số có số 0 đứng đầu.
- `JNumber` giữ **lexeme gốc**:
  - `asDouble()` = `lexeme.toDouble()` (JDK làm tròn đúng);
  - `asLongExact()` chỉ nhận lexeme số nguyên (không có `.`, không có `e`), qua `toLong()`.
- `JObject` giữ thứ tự chèn. Khoá trùng thì giá trị sau ghi đè giá trị trước, giữ vị trí lần đầu.
- Writer: không có khoảng trắng; số ghi bằng lexeme gốc (nút đọc từ input) hoặc theo quy tắc của người gọi; chuỗi escape `"`, `\` và
  ký tự < 0x20 thành `\u00XX`.
- Message lỗi: `"json: <rule> at <offset>"`, không trích nội dung.

#### 7.2 `EngineParamsFactory.parseOverrides` (T10 §5 + C12)
```
json == null || json.isBlank()        → (defaults, malformed=false, rejected=[])
tree = MiniJson.parse(json) lỗi, hoặc không phải JObject → (defaults, malformed=true, [])
với mỗi (key, v) theo thứ tự (sau khi đã gộp khoá trùng):
   spec = PARAM_SPECS[key] ?: bỏ qua (khoá lạ)
   I: v là JNumber, d = v.asDouble() hữu hạn, d == floor(d), min ≤ d ≤ max → (d + 0.0).toInt()   (-0.0 → 0)
   D: v là JNumber, d hữu hạn, min ≤ d ≤ max → d + 0.0
   khác → rejected += key
G1–G6 trên giá trị sau bước trên: nhóm vi phạm → mọi khoá **đã override** của nhóm về mặc định, rejected += các khoá đó
G7 (sau G6): fallbackLagS ≤ samplingDenseIntervalS → fallbackLagS về mặc định, rejected += "fallbackLagS" nếu đã override
```
- `fromOverrides(json) = parseOverrides(json).params`.
- `PARAM_SPECS` có **83** mục, đúng bảng §5. Nếu đếm lại khác thì §5 là chuẩn; ghi vào notes.
- Accuracy của tier không phải tham số.

#### 7.3 `SnapshotCodec` (T10 §7.1)
- Object JSON. Khoá theo đúng thứ tự bảng §7.1. Mọi khoá luôn được ghi; giá trị null ghi `null`.
  - `params`: mọi tham số theo thứ tự `PARAM_SPECS`.
  - `config`: `{tripId, destLat, destLng, mode, distanceThresholdM, timeThresholdMin, preAlertEnabled, vehicleHint}`.
  - Enum ghi `UPPER_SNAKE`; Int/Long ghi số nguyên thập phân; Double ghi `Double.toString()`.
- JDK 17 `toString()` round-trip đúng nhưng không phải lúc nào cũng là chuỗi ngắn nhất (ví dụ `1e23` → `9.999999999999999E22`, JDK-4511638).
  Không sao: snapshot chỉ cần round-trip trong cùng nền tảng. Chính vì lý do này P05 **không** dùng chữ thập phân (§9).
- Decode:
  - `snapshotVersion` thiếu, không phải số nguyên hoặc ≠ 1 → lỗi (`> 1` → `snapshot: unsupported version`).
  - Khoá lạ: bỏ qua.
  - Thiếu khoá bắt buộc, sai kiểu, Double không hữu hạn → `SnapshotFormatException("snapshot: <field> invalid")`.
  - Long đọc bằng `asLongExact`.
- U51/U69 so bit (`doubleToRawLongBits`) mọi Double, kể cả từng phần tử của `cvGuard`, `last3`, `recent`.

#### 8.3 Vòng tick (README §6, T10 §8.1). `CaseRunner.run(key, opts)`

```
startMs = trace.startMs + opts.timeShiftMs                       // P06: +86 400 000
step = TripEngine.start(cfg, params, startMs); record(t=0, START, step); os.react(step); drain()
alive = true; lastDelivered = null; sparseShifted = false; locBlocked = false
for t in 0, I, 2I, …, durationS:
  nowMs = startMs + 1000·t
  if kill && t == kill.t:  snapshot = state; alive = false; os.onKill(); recordMarker(t, KILL)
  if relaunch due at t:                                           // B tĩnh, hoặc giải anchor chạy (offsetS ≥ I)
      if status == MISSING: os.dropForMissing()                   // fbOs = null; ringing FALLBACK → NONE
      info = restoreInfo(status, os)                              // README §6.2, §6.4
      step = TripEngine.restore(decodeSnapshot(encodeSnapshot(snapshot)), nowMs, info)
      alive = true; record(t, RESTORE, step); os.react(step); drain()
      if state.phase ∈ {ALARMING, OVERSHOT} && os.ringing == NONE: feed(AlarmSilenced(nowMs, nowMs))
  for input in os.tick(t, nowMs, alive): feed(input)              // osDismiss → silence → báo dự phòng kêu (§8.4)
  if !alive: (action tới hạn → lỗi cấu hình); continue

  else feed(Tick(nowMs))

feed(x): nếu phase đang ENDED → gọi reduce nhưng KHÔNG ghi bản ghi; ngược lại step = reduce(state, x); record(t, x, step);
         assertFiniteState; os.react(step); drain()
drain(): xử lý FIFO các input tức thời do osSim xếp hàng (FallbackScheduled, FallbackFired); mỗi Step của chúng cũng qua os.react.
         Sau khi hàng đợi rỗng: nếu Step gốc có Alarm(ringNow=true) → P07(ii): os.ringing ≠ NONE
allow(t, p): ALL → true
             POLICY: lastDelivered == null → true
                     need = p.intervalS + (j > 0 && !sparseShifted && p.tier == SPARSE ? j·I : 0)
```

- `RunResult` gồm:
  - danh sách `StepRecord(t, input, events, view)`;
  - mảng `fbOsAfterTick[t/I]` (giá trị `os.fbOs` sau khi xử lý xong tick);
  - `firstAlarmT`;
  - anchor chạy đã giải;
  - snapshot (`encodeSnapshot`) + bản sao osSim + trạng thái harness ở các điểm kiểm I8;
  - danh sách vi phạm.
- Một lượt bị lỗi cấu hình (anchor chạy không xảy ra, action lúc engine chết, `osDismiss` không trước relaunch, `B > durationS`,
  relaunch `event:*` có `B ≤ kill.t`, `samplingSparseIntervalS % I ≠ 0` khi quét pha, `policyPhaseSweep` đi với `batteryMaxSaving` hoặc
  `samplingModes: ["all"]`, `killSweep` không có `alarm`) → **fail** với message có tên lượt, `t` và `j`.

#### 8.4 osSim (T10 §8.1-4, README §6.2–§6.6)

Trạng thái: `fbOs: Long?`, `ringing ∈ {NONE, ENGINE, FALLBACK}`, `ringStartMs: Long?`, `osFallbackFiredT: Int?`,
`osFallbackFiredAtMs: Long?`, `osDismissedAtMs: Long?`. `config.osSim == false` → mọi thao tác là no-op.

```
tick(t, nowMs, alive) → list<EngineInput>, theo đúng thứ tự:
  a. osDismiss: !alive && osFallbackFiredT ≠ null && t == osFallbackFiredT + offsetS → ringing = NONE; osDismissedAtMs = nowMs
  b. osRingMaxS ≠ null && ringing ≠ NONE && nowMs ≥ ringStartMs + osRingMaxS·1000:
        s = ringStartMs + osRingMaxS·1000; ringing = NONE; if alive → AlarmSilenced(nowMs, s)
  c. fbOs ≠ null && nowMs ≥ fbOs: ringing = FALLBACK; ringStartMs = fbOs; fbOs = null
        if alive → FallbackFired(nowMs, ringStartMs)
        elif osFallbackFiredT == null → osFallbackFiredT = t; osFallbackFiredAtMs = ringStartMs
react(step): duyệt sự kiện theo thứ tự trong Step
  Alarm(ringNow=true): P07(i) ringing ≠ ENGINE (vi phạm → ghi)
                       ringing == FALLBACK → enqueue FallbackFired(now, ringStartMs)
                       ngược lại → ringing = ENGINE; ringStartMs = now; fbOs = null
  Snoozed, TripEnded → ringing = NONE

action dismiss/stop (lúc feed) → ringing = NONE
onKill(): ringing == ENGINE → NONE
restoreInfo(status): status auto: osFallbackFiredT < tick relaunch → (osDismissedAtMs ≠ null ? DISMISSED(firedAt, dismissedAt) : RANG(firedAt)), ngược lại PENDING
                     status tường minh: firedAtMs = osFallbackFiredAtMs nếu đã kêu trước relaunch; dismissedAtMs chỉ với DISMISSED + osDismiss
```

#### 9.2 Định dạng file
- JSONL, UTF-8 (chỉ ASCII), mỗi dòng kết thúc bằng `\n`, file kết thúc bằng `\n`.
- Không có khoảng trắng nào ngoài giá trị chuỗi. Khoá đúng thứ tự quy định dưới đây.
- Dòng 1 (header): `{"p05":1,"run":"train_hn_dh/distance_1000/all"}`.
- Mỗi Step **được ghi** (§8.3: không ghi input tới khi đã ENDED) là một dòng:
  `{"t":<tick s>,"in":[…],"ev":[…],"v":{…}}`.
  - `ev`: **bỏ hẳn khoá** khi không có sự kiện.
  - `v`: **chỉ ghi** khi chuỗi `v` khác chuỗi `v` đã ghi gần nhất. Step đầu tiên luôn ghi.
- Dòng mốc kill: `{"t":<kill.t>,"in":["KILL"]}`.

**Mã hoá giá trị:**
- **Mọi thời điểm** (ms epoch) ghi dạng **tương đối** `x − startMs` (số nguyên). Nhờ vậy P06 = trùng từng byte.
- Int/Long: thập phân, có `-` nếu âm, không số 0 đứng đầu, không `+`.
- Bool: `true`/`false`. Null: `null`. Enum: chuỗi `UPPER_SNAKE`.
- Double (chỉ trong file chẩn đoán §9.5): chuỗi 16 chữ số hex **thường** của bit thô.
  - Kotlin: `java.lang.Long.toHexString(java.lang.Double.doubleToRawLongBits(x)).padStart(16, '0')`.
  - Swift: `String(x.bitPattern, radix: 16)`, đệm `0` bên trái cho đủ 16.
