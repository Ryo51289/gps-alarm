### 3. Ngôn ngữ, đồng thời, đặt tên

- `Package.swift` không có `swiftSettings`/`unsafeFlags` (không `-Ounchecked`, không fast-math). Cảnh báo kiểm bằng dòng lệnh
  `swift build -Xswiftc -warnings-as-errors`. `platforms: [.iOS(.v15), .macOS(.v13)]` (không cao hơn Runner).
- Enum Swift viết `lowerCamel`, mỗi enum có `jsonName` (UPPER_SNAKE đúng T10 §2) và `init?(jsonName:)`, viết tay bằng `switch`.
  `FallbackStatus` dùng case **`notSet`** ↔ `"NONE"` (giống `FallbackStatusMsg.notSet` của T14, tránh nhầm `Optional.none`).
  `SamplingTier: Int, Comparable` (`sparse < medium < dense`).
- Payload sự kiện là kiểu **lồng** trong `TripEvent` (`TripEvent.Alarm`…): T17 import cả `AlarmKit` (có `Alarm`) lẫn `Trip` không trùng tên.
- Thời điểm `Int64` (ms epoch); số nguyên khác `Int`. Thứ tự trường của mọi kiểu **đúng T10 §2 / T12 §4**.
- Không `print`, không log trong module `Trip` (U44).

### 5. Tính tất định trong Swift (T10 §6 D1–D7, T12 §6)

#### 5.1 Quy tắc

| T10 | Cách làm trong Swift (U44 quét `Sources/Trip`) |
|---|---|
| D1 | Chỉ `+ − * /`, `.squareRoot()`, `.rounded(.down)`, so sánh, và `TMath.*`. Cấm: hàm siêu việt `sin cos tan asin acos atan atan2 exp expm1 log log2 log10 log1p pow cbrt hypot`; `fma`, `addingProduct`, `formRemainder`, `truncatingRemainder`; mọi `import`. `cosDeg` Horner, mẫu số `[462, 380, 306, 240, 182, 132, 90, 56, 30, 12, 2]`, `r = 1.0 - y / den * r` (= `1.0 - ((y / den) * r)`, như `tools/tracegen/lib/src/geo.dart`); `kDegToRad = 3.141592653589793 / 180.0`; `kMetresPerDegLat = 6371008.8 * kDegToRad`. Ngoài miền `[-90, 90]` → `preconditionFailure` (Kotlin ném lỗi; engine không bao giờ gọi ngoài miền) |
| D2 | **Swift không tự gộp `a * b + c` thành FMA**; chỉ `addingProduct`/`fma` mới sinh FMA, và không có cờ nào bật contraction ("There is no way to express this at present in Swift", Steve Canon, [SW-FMA]). Vì vậy **không cần cờ** trên x86_64 Linux lẫn arm64 macOS/iOS; `-Xcc -ffp-contract=off` chỉ tác động mã C qua Clang, module `Trip` không có mã C. Rào chắn: U44 cấm `fma`/`addingProduct`; S05 kiểm `TMath.contractionProbe(0.1, 10, -1)` bằng đúng `0.0` (FMA cho 5.55e-17; đối số đọc từ mảng runtime để không gập hằng); P05 trên macOS arm64 (§10.3). Release `-O` không đổi ngữ nghĩa số thực |
| D3 | `toS(ms) = Double(ms) / 1000.0`; tham số Int `…S` → ms bằng `Int64(x) * 1000`. Chuyển Int → Double **đúng chỗ Kotlin tự nâng kiểu**: Int·Int tính bằng số nguyên, đổi sang Double ở phép đầu tiên gặp Double (T12 §6, bảng "Thứ tự biểu thức hay sai" là chuẩn chung; Swift viết đúng từng dòng của bảng đó). Mọi số nguyên trong miền < 2^53 nên chuyển đổi chính xác |
| D4 | Không `Dictionary`, `Set`, `.random`, `hashValue`, `Date`, `ContinuousClock` trong `Sources/Trip`. Object JSON là mảng cặp có thứ tự; `PARAM_SPECS` là mảng |
| D5 | Double → số nguyên **chỉ** qua `TMath.floorMs`, `TMath.roundHalfUp` và chuyển đổi trong `MiniJson`/`SnapshotCodec`/`EngineParams` (§5.2); U44 cấm `Int(`/`Int64(` với đối số Double ngoài các file đó (giống quy tắc `.toInt()` của T12) |
| D6 | Viết biểu thức đúng thứ tự trong T10 và bảng T12 §6; Swift và Kotlin cùng ưu tiên, cùng kết hợp trái cho `* / + −` |
| D7 | `TMath.min/max/clamp` theo T10 §4.0 (`a <= b ? a : b`, `a >= b ? a : b`; có bản Double, Int, Int64). Cấm `min(`/`max(` trần và `Swift.min/max` cho mọi kiểu. `TMath.max(0.0, -0.0)` = `0.0`, `TMath.min(-0.0, 0.0)` = `-0.0` (so bit, ca bổ sung T12) |

Ghi chú: chỉ `speedMps = -0.0` từ input mới tạo được −0.0, và kết quả `medianHi(groundSample)` chỉ dùng để so sánh (`fast`), nên khác biệt ±0 không lọt vào transcript; vẫn viết giống để không phải lý luận |

#### 5.2 Số nguyên và chuyển đổi

- Kotlin `Double.toLong()`/`toInt()` **bão hoà** (NaN → 0); Swift `Int64(x)` **dừng chương trình** khi tràn. Viết
  `TMath.kotlinToLong`/`kotlinToInt` đúng ngữ nghĩa Kotlin: NaN → 0; `x ≥ 9223372036854775808.0` → `Int64.max`; `x ≤ −9223372036854775808.0`
  → `Int64.min`; bản Int kẹp vào **khoảng Int32** (Int của Kotlin 32 bit); còn lại cắt về 0. `floorMs(s) = kotlinToLong((s * 1000.0).rounded(.down))`;
  `roundHalfUp(x) = kotlinToInt((x + 0.5).rounded(.down))`.
- Cộng/trừ/nhân `Int64` dùng toán tử thường (bẫy tràn), không `&+`. Miền hợp lệ (hợp đồng với T17 và harness): mọi `…Ms` input trong
  `[0, 2^53)`, tham số trong khoảng T10 §5. Trong miền này không phép nào tràn; ngoài miền Kotlin quấn vòng còn Swift dừng — không thuộc
  P05. Ghi vào README package.

#### 5.3 In số thực: Swift ↔ Kotlin khác nhau (vì sao P05 không dùng số thập phân)

| Giá trị | Swift `description` | Kotlin/JVM 17 `toString` |
|---|---|---|
| 1e21 / 1e23 | `1e+21` / `1e+23` | `1.0E21` / `9.999999999999999E22` (JDK 17 không luôn ngắn nhất, JDK-4511638; vẫn đọc lại đúng bit) |
| −0.0 | `-0.0` | `-0.0` |
| NaN, ∞ | `nan`, `inf` | `NaN`, `Infinity` |
| 4.9e-324 (subnormal nhỏ nhất) | `5e-324` | `4.9E-324` |
| 1e-5 | `1e-05` | `1.0E-5` |

Swift dùng SwiftDtoa: ít chữ số nhất, `Double(d.description) == d` với mọi d không NaN [SW-DTOA]. Hai bên đều đọc lại đúng bit, nên snapshot
(chỉ cần round-trip trên cùng một máy) dùng được `description`/`toString`. Transcript P05 của T12 §9 không có số thực thập phân: sự kiện và
view P05 toàn số nguyên/enum/bool, thời điểm ghi tương đối; Double chỉ có trong file chẩn đoán (§9.5 của T12), ghi 16 hex bit thô —
Swift `String(x.bitPattern, radix: 16)` đệm `0` bên trái cho đủ 16.

### 6. JSON

#### 6.1 `MiniJson.swift` (theo T12 §7.1)

- `enum JsonValue { case object([(String, JsonValue)]), array([JsonValue]), string(String), number(String /*lexeme*/), bool(Bool), null }`.
- Parser RFC 8259: khoảng trắng space/tab/LF/CR; escape `\" \\ \/ \b \f \n \r \t \uXXXX` (gồm cặp surrogate; surrogate lẻ → lỗi); không
  BOM, comment, dấu phẩy thừa, `NaN`/`Infinity`, số có số 0 đứng đầu. Kiểm ngữ pháp số **trước** khi gọi `Double(lexeme)` (vì
  `Double(String)` nhận cả `nan`, `inf`, `0x1p3`, `+1`). **Khoá trùng: giá trị sau ghi đè giá trị trước, giữ vị trí lần đầu** (T12 K2, khớp
  Dart T25). Giới hạn độ sâu 64 (chống tràn ngăn xếp; JSON sâu hơn = lỗi cú pháp; T12 không có giới hạn nhưng không case hợp lệ nào sâu
  tới đó — ghi vào notes cho T12 nếu cần đồng bộ).
- `asDouble()` = `Double(lexeme)` (stdlib, đọc làm tròn đúng; trên Linux qua `strtod_l`), `asLongExact()` chỉ nhận lexeme số nguyên (không
  `.`, không `e`). Không hữu hạn → nil.
- Writer: không khoảng trắng; chuỗi escape `"`, `\` và ký tự < 0x20 thành `\u00XX`. Message lỗi `"json: <rule> at <offset>"`, không trích
  nội dung.

#### 6.2 Snapshot (`SnapshotCodec.swift`, theo T12 §7.3)

- Khoá đúng thứ tự bảng T10 §7.1 / `EngineState` của T12 §4; **mọi khoá luôn được ghi**, null ghi `null`. `params` theo thứ tự
  `PARAM_SPECS`; `config` = `{tripId, destLat, destLng, mode, distanceThresholdM, timeThresholdMin, preAlertEnabled, vehicleHint}`; enum
  UPPER_SNAKE; Int/Long thập phân; Double ghi `description`.
- Decode: `snapshotVersion` thiếu, không nguyên, hoặc ≠ 1 → lỗi (`> 1` → `snapshot: unsupported version`); khoá lạ bỏ qua; thiếu khoá bắt
  buộc, sai kiểu, Double không hữu hạn → `SnapshotError("snapshot: <field> invalid")`; Long đọc bằng `asLongExact`.
- Snapshot không so giữa hai nền tảng. Trong test, "trùng từng bit" = so `bitPattern` mọi Double (U51, U69) và `encodeSnapshot(a) ==
  encodeSnapshot(b)` (cùng nền tảng, writer tất định, `description` phân biệt −0.0).

#### 6.3 `EngineParamsFactory.parseOverrides` (T10 §5 + T12 C12, §7.2 — chép nguyên)

```
json == nil || json toàn khoảng trắng → (defaults, malformed=false, rejected=[])
parse lỗi hoặc gốc không phải object  → (defaults, malformed=true, [])
với mỗi (key, v) theo thứ tự (sau khi gộp khoá trùng):
   spec = PARAM_SPECS[key] ?? bỏ qua (khoá lạ, KHÔNG vào rejected)
   I: v là number, d = asDouble hữu hạn, d == d.rounded(.down), min ≤ d ≤ max → kotlinToInt(d + 0.0)   (-0.0 → 0)
   D: v là number, d hữu hạn, min ≤ d ≤ max → d + 0.0                                                  (-0.0 → +0.0)
   khác → rejected += key
G1–G6: nhóm vi phạm → mọi khoá đã override của nhóm về mặc định, rejected += các khoá đó
G7 (sau G6): fallbackLagS ≤ samplingDenseIntervalS → fallbackLagS về mặc định, rejected += "fallbackLagS" nếu đã override
```
`PARAM_SPECS` có **83** mục đúng T10 §5 (nếu đếm khác, T10 §5 là chuẩn, ghi notes như T12).
