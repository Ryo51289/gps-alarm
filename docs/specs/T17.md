## Bối cảnh & mục tiêu

- PRD §1, §4: đánh thức đúng lúc khi máy khoá, Im lặng, Không làm phiền; iOS 26+ dùng AlarmKit. ARCHITECTURE §1: quyết định "báo hay chưa"
  nằm ở native; iOS = `LocationController` + `AlarmController`. Engine Swift đã xong và trùng từng bit với Kotlin (T13–T13.5, P05 303/303).
- S3 chốt phương án **A — AlarmKit + fallback, có điều kiện**: đặt AlarmKit `.fixed(now + 5 s)` từ callback vị trí nền khi máy khoá kêu được
  khi Im lặng + Tập trung; báo đặt trước vẫn kêu khi app bị treo/tự thoát/vuốt tắt; iOS không mở lại app để theo dõi tiếp (H5). K4 #1–#20 là
  yêu cầu cho T17.
- T17 là **bản tương đương T15 + phần "kêu" của T16** trên iOS: nhận vị trí từ `CLLocationManager`, chạy `TripEngine` Swift, thực thi yêu
  cầu của engine (lấy mẫu, Tick, báo dự phòng, kêu), lưu snapshot, khôi phục, nối `TripHostApi` + stream thật thay stub T14.
- Ràng buộc môi trường: **không có Mac**. Logic quyết định đặt trong NapStopCore để `swift test` chạy trên WSL; mã Apple được kiểm kiểu
  bằng SDK của xtool trên WSL, build thật trên GitHub Actions macOS, và kiểm trên iPhone của PO theo giao thức IM.

## Phạm vi

**Làm**
1. Target Swift thuần mới **`TripRuntime`** trong NapStopCore (Foundation, không framework Apple-only): runtime tuần tự hoá engine, đồng hồ
   chuyến, ánh xạ fix + giữ nhịp fix theo `SamplingPolicy`, lập kế hoạch hiệu ứng, sổ báo 2 khe + khe canh chuông, diễn giải `alarmUpdates`,
   khôi phục (`RestorePlanner`, `LedgerReconciler`), codec lưu trữ, bản ghi chuyến đã xong, kiểm cấu hình chuyến, DTO cầu nối, chuỗi native
   vi/en. Test `swift test` (WSL + macOS) gồm chạy runtime trên trace GPX của `fixtures/traces` với cùng `expect.json` như Kotlin.
2. Target **`NapStopIOS`** (`#if os(iOS)`): phiên `CLLocationManager`, báo AlarmKit, kênh thông báo tối thiểu khi không có AlarmKit, lưu
   file, đọc quyền/pin, thông báo cảnh báo chuyến, hẹn giờ trong process, `RuntimeHost` (ghép cổng, theo dõi vòng đời app).
3. Runner: `RealTripBackend` (hiện thực `TripHostApi`), `MsgMapper`, stream `tripUpdates` thật; `StopIntent` (App Intent cho nút Tắt của
   AlarmKit); liên kết gói local `Core` trong `project.pbxproj`; Info.plist (vị trí When In Use, `UIBackgroundModes=[location]`, AlarmKit).
4. Khôi phục: process mở lại do StopIntent (nền), do người dùng mở app, sau khi máy khởi động lại; StopIntent ghi `dismissedAtMs` trước mọi
   việc (T10 §7.2); không kêu lần hai sau khi đã Tắt (S3 #1).
5. Bản chẩn đoán (`NAPSTOP_DIAG`): journal không toạ độ, App Intent chẩn đoán đặt lại báo dày (IM06), cổng báo giả cho Simulator.
6. Một test Kotlin chỉ-đọc sinh bảng `fixtures/runtime/first-alarms.json` (lý do + giờ báo đầu của L30) để so parity.

**KHÔNG làm** (task ở `docs/PLAN-ios.md` §5)
- `PermissionHostApi` thật, `distancesFromLastKnownM`, `InfoPlist.strings`, `PrivacyInfo.xcprivacy`, loại `napstop_db/` khỏi sao lưu → **T17.1**.
- Nút phụ AlarmKit (Báo lại từ màn khoá, "Xem đường quay lại"), `consumeLaunchAction` iOS, danh mục âm + `previewSound`, quá trạm khi chuông
  đầu còn kêu, đo thời lượng kêu tối đa → **T17.2**. Trong T17, alarm chỉ có nút Tắt; báo lại làm được từ màn 5 Flutter khi app đang mở.
- Kênh Time Sensitive đầy đủ (âm < 30 s lặp 3 lần, entitlement, S3-9…11) → **T17.3**. T17 chỉ có kênh thông báo tối thiểu (§5.6.6).
- Giả lập (`simulation != nil` → `simulation-unavailable`) → **T18.1**. Không đổi engine (`Trip`), `EngineParams`, Pigeon, Remote Config,
  mã Android (trừ test Kotlin ở mục 6), mã Dart (trừ file integration test mới).
- Không xin "Luôn cho phép", không `CLMonitor`, không `audio` background mode, không widget extension, không Live Activity, không Critical
  Alerts.

### 4. Interface và kiểu dữ liệu

#### 4.1 Cổng (`Sources/TripRuntime/Ports.swift`)

```swift
import Foundation
import Trip

/// Trip clock inputs (§5.3). All engine times are on the trip clock.
public protocol TimeSource: Sendable {
    func wallMs() -> Int64                     // Date().timeIntervalSince1970 * 1000, floor
    func elapsedMs() -> Int64                  // ContinuousClock, continues while asleep [SW-CC]
    func bootSessionId() -> String?            // sysctlbyname("kern.bootsessionuuid"); nil if unreadable
}

/// One CLLocation, no Apple types. description/debugDescription redact coordinates (T10 §10).
public struct RawFix: Sendable, Equatable, CustomStringConvertible, CustomDebugStringConvertible {
    public let lat: Double
    public let lng: Double
    public let horizontalAccuracyM: Double     // CLLocation.horizontalAccuracy; < 0 = invalid
    public let speedMps: Double                // CLLocation.speed; < 0 = invalid
    public let timestampWallMs: Int64          // CLLocation.timestamp
    public var description: String { "RawFix(<redacted>)" }
    public var debugDescription: String { description }
}

public enum LocationAccuracyClass: String, Sendable, Equatable { case hundredMeters, nearestTenMeters, best }
public struct LocationRequestSpec: Sendable, Equatable {
    public let accuracy: LocationAccuracyClass
    public let intervalMs: Int64               // throttle interval (D9); not passed to Core Location
```

`FixMapper.map(raw, nowWall, nowTrip)` (thuần):
```
if !(raw.horizontalAccuracyM > 0) || !raw.lat.isFinite || !raw.lng.isFinite → drop (đếm droppedPlatform, journal)
ageMs   = max(0, nowWall − raw.timestampWallMs)
atMs    = nowTrip ; fixAtMs = atMs − ageMs
speed   = raw.speedMps ≥ 0 ? raw.speedMps : nil
→ LocationFix(atMs, fixAtMs, lat, lng, accuracyM = horizontalAccuracyM, speedMps = speed)
```
`FixThrottle` (thuần, trạng thái `lastForwardedFixAtMs` trong bộ nhớ; reset khi bắt đầu/khôi phục chuyến):
```
forward(fix, policy) = last == nil || fix.fixAtMs − last ≥ policy.intervalS·1000 − FIX_THROTTLE_SLACK_MS
nếu forward: last = fix.fixAtMs, chuyển vào engine; ngược lại bỏ (không phải "fix bị loại" của engine)
```
`didUpdateLocations` có thể giao nhiều `CLLocation` một lần: xử lý theo thứ tự thời gian, mỗi cái qua `FixMapper` + `FixThrottle`.

Đổi quyền/định vị: `locationManagerDidChangeAuthorization` và `didFailWithError(CLError.denied)` → `IOSDeviceEnv` tính lại:
không When In Use/Always → `PERMISSION_REVOKED`; `locationServicesEnabled() == false` (gọi ngoài main) → `SERVICES_OFF`; còn lại `AVAILABLE`;
chỉ gửi khi đổi. Chỉ còn "Gần đúng" (`reducedAccuracy`) → **không** gửi `PERMISSION_REVOKED` (fix sai số km bị `FixFilter` bỏ, engine tự
vào mất GPS — như Android chỉ còn COARSE, T15 §5.12).

#### 5.5 Hẹn giờ (`wakeAtMs`)

`setTimer(dueTrip)` → `timer.set(delayMs: max(0, dueTrip − clock.now()), generation: ++timerGen)`; `onTimer(g)` bỏ nếu `g` cũ; ngược
lại `Tick(clock.now())` (giờ giao thật, không phải giờ hẹn — T10.4). Timer chạy trong process; app bị treo thì không có Tick (bù bằng báo
dự phòng). Mỗi `onTimer` còn đọc pin (`env.battery()`) → `BatterySample` nếu đổi, và kiểm `locationAccess` → `LocationAvailability` nếu đổi.

#### 5.6 Báo thức

##### 5.6.1 `RingFactsReader` (thuần) và kêu "now"

```
facts(tripId, list, ledger, nowWall):
  a = list.first { tripId == tripId && state == .alerting }
  if a → (true, a.kind, a.fireAtWallMs)
  n = ledger.now
  if n != nil && n.confirmed && !n.seenAlerting && nowWall ≤ n.fireAtWallMs + NOW_ALERT_GRACE_MS → (true, .now, n.fireAtWallMs)
  → (false, nil, nil)
```
Trước khi lập kế hoạch một Step có `Alarm(ringNow=true)`, runtime gọi `alarms.list()` (đọc mới; `nil` → dùng danh sách gần nhất).

`ringNow(req)` (executor):
```
ch = chooseChannel()                                            -- D14, đọc env.channelAccess()
id = UUID; g = ledger.nextGeneration++; fire = nowWall + AK_NOW_LEAD_MS
ledger.now = NowRingRec(id, g, fire, req.reason, confirmed: false, seenAlerting: false, ch); writeLedger   -- trước schedule
bg = bgTasks.begin("napstop.ring")                              -- giữ CPU tới khi đặt xong (S3 quyết định nhỏ 6)

  ok   → ledger.now.confirmed = true; writeLedger
  lỗi  → §5.6.3 (G2)
bgTasks.end(bg)   -- ở chế độ headless: giữ tới khi thấy alerting hoặc NOW_OBSERVE_HOLD_MS (§5.6.4)
```

##### 5.6.2 Khe báo dự phòng (`FallbackSlots`, thuần + cổng)

```
schedule(kind ∈ {fallback, guardSlot}, targetAtMs, targetAtWallMs):
  old = ledger.current; id = UUID; g = ledger.nextGeneration++
  ch = chooseChannel(); title = kind == .fallback ? NativeCopy.fallbackTitle(…) : NativeCopy.alarmTitle(lastReason ?? .fallback, …)
  try await alarms.schedule(SystemAlarmRequest(id, tripId, kind, g, targetAtWallMs, title, ch))
     lỗi → warn; nếu kind == .fallback: feed(.fallbackScheduled(now, targetAtMs, ok: false)); return      -- giữ khe cũ (nghĩa vụ 1)
  ledger.current = AlarmSlotRec(id, kind, g, targetAtMs, targetAtWallMs, nowWall, ch); ledger.stale = old; writeLedger
  if old: await alarms.cancel(id: old.alarmId, channel: old.channel)     -- chỉ khi old đang scheduled (không bao giờ huỷ alerting, K4 #4)
          ledger.stale = nil; writeLedger
  if kind == .fallback: feed(.fallbackScheduled(now, targetAtMs, ok: true))
scheduleFallback(t) = schedule(.fallback, t, toWall(t))
armRingGuard(w)     = schedule(.guardSlot, toTrip(w), w)        -- không feed (engine không biết khe này)
cancelFallbacks     = cancel current + stale (nếu scheduled); ledger.current = nil, stale = nil
```
Báo cũ (`stale`) kêu đúng lúc đang đặt lại (ca T10.5 §8, "còn ~10 s"): `AlarmUpdateInterpreter` thấy nó `alerting` → nghĩa vụ 5 (huỷ khe
mới), chỉ một tiếng kêu.

##### 5.6.3 Kêu lỗi (G2 cho iOS)

`schedule` của alarm "now" ném:
1. Thử ngay kênh còn lại (AlarmKit ↔ thông báo) nếu được cấp; thành công → như ok.
2. Vẫn lỗi → `feed(.alarmSilenced(now, now))` (engine `ringing = false`: UI đúng, quá trạm còn kêu lại được), khe canh chuông của D5 giữ
   nguyên (≤ now + 30 s), `notice(show: .ringFailed)` nếu có quyền thông báo, đặt `ringRetryPending`.
3. `ringRetryPending` và engine còn ALARMING/OVERSHOT: mỗi lần khe canh chuông/khe dự phòng không còn trong `list()` (đã kêu hoặc mất) hoặc
   ở Tick kế tiếp ≥ `RING_RETRY_MS` → đặt khe canh chuông mới ở `nowWall + fallbackLagS·1000`. Dừng khi có alarm `alerting`, chuyến kết
   thúc, hoặc engine rời ALARMING/OVERSHOT. Trần tự nhiên `alarmMaxActiveS` (1 h).

##### 5.6.4 `AlarmUpdateInterpreter` (thuần) — diễn giải `alarmUpdates`

`RuntimeHost` lặp `for await list in AlarmManager.shared.alarmUpdates` (iOS 26+) và gọi `runtime.onSystemAlarms(list)`. Kênh thông báo không có
luồng cập nhật; runtime đọc `list()` ở mỗi Tick. Runtime giữ `prev` (danh sách lần trước) và `expectedStops` (id mà chính runtime đã `stop`/
`cancel`). Với chuyến đang chạy (`tripId`):

```
interpret(prev, cur, ledger, engineView, expectedStops, nowWall, pendingStopIds) → [Action]
  for a in cur where a.tripId == tripId && a.state == .alerting && prev[a.id]?.state != .alerting:
     if a.kind ∈ {fallback, guardSlot}:
        if ledger.lastFired?.alarmId != a.id: → recordFired(a) (ghi sổ lastFired trước), feed(.fallbackFired(now, toTrip(a.fireAtWallMs ?? nowWall)))   -- nghĩa vụ 5
        → cancel mọi alarm khác của chuyến đang .scheduled (khe kia, khe canh chuông, "now" chưa kêu)                                         -- nghĩa vụ 4 vế iOS
     if a.kind == .now:
        → ledger.now.seenAlerting = true; cancel mọi fallback/guard của chuyến đang .scheduled (KHÔNG đụng alarm .alerting)                  -- K4 #3, #4; D6
        → ringRetryPending = false
  for p in prev where p.tripId == tripId && p.state == .alerting && cur[p.id] không còn hoặc ≠ .alerting:
     if p.id ∈ expectedStops → bỏ
     else → hẹn kiểm lại sau STOP_INTENT_GRACE_MS: nếu chưa có RingEventRec cho p.id và engineView.alarmRinging → feed(.alarmSilenced(now, toTrip(goneAtWall)))   -- nghĩa vụ 6
  alarm của tripId ∈ ledger.endedTripIds: .scheduled → cancel; .alerting → stop                                                               -- §5.8
```
- Hai alarm `alerting` cùng lúc (hiếm): không huỷ cái nào (K4 #4); `FallbackFired` gửi một lần; người dùng Tắt một cái → `TripEnded` → dừng
  cái còn lại (D22).
- `alarmUpdates` không tới khi app treo/chết (S3 #6, K4 #10): không suy ra "đã kêu" từ việc thiếu cập nhật; khôi phục dùng `alarms` + giờ (§5.8).
- Chế độ `headless` (process mở ở nền): sau `ringNow`, giữ background task tối đa `NOW_OBSERVE_HOLD_MS` để kịp thấy `alerting` và huỷ khe
  canh chuông; hết giờ mà chưa thấy → giữ khe (có thể kêu thêm một lần ~25 s sau — chấp nhận theo quy tắc "không chắc → kêu", ghi chú
  orchestrator T15 vòng 1 #2).

##### 5.6.6 Kênh thông báo tối thiểu (`NotificationSystemAlarms`)

Dùng khi D14 không chọn được AlarmKit. `schedule`: `UNNotificationRequest(identifier: id, content, trigger)`; "now" → `trigger: nil`; khe
dự phòng/canh chuông → `UNTimeIntervalNotificationTrigger(timeInterval: max(1, (fire − nowWall)/1000), repeats: false)`; `content.title` =

`removeDeliveredNotifications`. Lỗi `add` (ví dụ `UNErrorDomain Code=2003` khi bị từ chối, S3 #3) → ném lên runtime (K4 #15). T17.3 mở rộng
(âm < 30 s, lặp 3 lần, đo S3-9…11).

#### 5.8 Khôi phục

`ensureLoaded()` ở mọi điểm vào (tạo backend, StopIntent, `didBecomeActive`, `onSystemAlarms`): đọc `active_trip.json`, sổ, sự kiện chuông,
`alarms.list()`; neo đồng hồ (§5.3); rồi **chờ D13** nếu app không `active`; rồi lập kế hoạch:

```
LedgerReconciler.reconcile(ledger, list, activeTripId) → (ledger', cancels):              -- thuần, chạy trước RestorePlanner
  alarm của tripId ∈ endedTripIds: scheduled → cancel; alerting → stop
  alarm fallback/guard đang scheduled của chuyến đang chạy mà sổ không biết (process chết giữa schedule và ghi sổ):
       nhận cái có generation lớn nhất làm current (nếu current không có trong list), cancel các cái khác đang scheduled
  ledger.now có confirmed == false mà list có alarm "now" cùng id → confirmed = true
RestorePlanner.plan(s, ledger', events, list, nowTrip, toTrip) → RestoreInfo:            -- thuần
  d = events.first { tripId == s.tripId && action == .dismiss }
  if d → DISMISSED(firedAtMs = resolved(ledger.lastFired) ?? toTrip(fireAt của alarm d.alarmId theo sổ/list),
                   dismissedAtMs = toTrip(d.atWallMs))
  if list == nil → UNKNOWN                                                                -- T10 §7.2: due → như RANG, không due → PENDING
  if a = list.first { tripId == s.tripId && state == .alerting } → RANG(firedAtMs = toTrip(a.fireAtWallMs ?? nowWall))     -- K4 #8
  fb = s.fallback.targetAtMs
  if fb != nil && lf = ledger.lastFired && resolved(lf) > s.nowMs → RANG(firedAtMs = resolved(lf))
  if fb == nil → PENDING
  slotAlive = ledger.current != nil && list có ledger.current.alarmId ở trạng thái .scheduled
  if slotAlive → PENDING
  if fb ≤ nowTrip → RANG(firedAtMs = fb)            -- "giờ đã qua, alarm đã mất → coi chuyến đã báo" (K4 #8, T10 §7.2 iOS)
  → MISSING                                         -- alarm mất trước giờ → engine RESYNC, đặt lại
```
Sau `TripEngine.restore(s, now, info)`:
1. Thực thi hiệu ứng của Step khôi phục như §5.2 (`FallbackAlarmChanged(RESYNC)` → đặt lại; `TripEnded(DISMISSED)` → kết thúc, bản ghi
   `finished/`).
2. **G3 cho iOS:** **thay bằng `RestoreRingPolicy` ở mục "Sửa spec sau review vòng 1" §R2** (bản cũ ở đây kêu lại sau `RANG(fb)`, mâu
   thuẫn với bảng dưới và RK-T17-4).
3. Chế độ: app `active` → bắt đầu phiên vị trí (nếu pha ≠ ENDED và còn quyền) → `.tracking`; ngược lại `.headless` (D10). `.headless` và pha
   ∈ {ACQUIRING, TRACKING} và `!ledger.interruptedAlerted` → `notice(.interrupted)` + ghi `interruptedAlerted = true`. Pha ALARMING/SNOOZED/
   OVERSHOT → không hiện (đang có báo thức).
4. `onAppActive` khi `.headless` và chuyến chưa ENDED → bắt đầu vị trí (`location.start`, lỗi → ở lại `.headless`) → `.tracking`; xoá thông báo
   `interrupted`, `interruptedAlerted = false`.

| Tình huống | Đường | Kết quả |
|---|---|---|
| Người dùng vuốt tắt app / hệ thống tắt app | không có callback tin cậy; `applicationWillTerminate` nếu có → §7 | Alarm AlarmKit đã đặt vẫn kêu (S3 H6) |

### 8. Pin, quyền riêng tư, a11y, copy

**Pin.** Một phiên CoreLocation liên tục cả chuyến; độ chính xác theo tier (§5.4); fix ~1 Hz bị `FixThrottle` bỏ phần lớn trước engine
(chi phí CPU nhỏ, không ghi đĩa). Snapshot ≤ 1 lần/60 s ngoài sự kiện. Alarm AlarmKit: đặt lại theo `FallbackAlarmChanged` (≤ 56 lần/giờ ở
vùng xa, T10 §10) + tối đa 2 alarm mỗi lần kêu (now + khe canh chuông). S4 đo % pin/10 giờ.

**Quyền riêng tư.** Toạ độ chỉ có trong bộ nhớ và trong `engineSnapshot` (thư mục loại khỏi sao lưu, D15). `RawFix`, `StoredTrip`, `TripMeta`,
`SystemAlarmRequest` che toạ độ/tên đích trong `description`. Metadata alarm (`NapStopAlarmMetadata`), `userInfo` thông báo, tham số App
Intent: chỉ `tripId`, `kind`, `generation`, `alarmID`. Journal: không toạ độ, không khoảng cách, không tên đích. Không `print`; log dùng
`os.Logger` với chuỗi tĩnh + tên kiểu lỗi. Không gửi gì tới Analytics/Crashlytics. Tiêu đề alarm có tên đích (người dùng tự chọn) và hiện trên
màn khoá — như màn `AlarmActivity` của Android.

**a11y.** UI báo là của hệ thống (AlarmKit); tiêu đề là câu đầy đủ (VoiceOver đọc được). Thông báo có tiêu đề + nội dung chữ.

### R1 — Khe canh chuông: cận dưới và "khe hiện tại" là khe còn sống (#1)

**Định nghĩa.** `liveSlot(ledger, list)` (hàm thuần, `TripRuntime/EffectPlanner.swift`):
```
liveSlot(ledger, list):
  if list == nil → nil                                         -- không đọc được: coi như không có khe sống (đặt thêm khe là an toàn)
  for c in [ledger.current, ledger.stale] (theo thứ tự, bỏ nil):
     if list có alarm id == c.alarmId với state == .scheduled → return c
  return nil
```
Khe đã bị huỷ, đã kêu (đang `alerting` hoặc đã mất khỏi danh sách), hoặc chỉ còn trong sổ **không** phải khe sống.

**Điều kiện đặt khe canh chuông** (thay dòng `if ledger.current == nil || …` ở §5.2; parity Android `cur.targetAtWallMs in nowWall..atWall`,
`TripRuntime.kt`):
```
guardAt = nowWall + params.fallbackLagS·1000
live    = liveSlot(ledger, freshList)                          -- freshList: list() đọc ngay trước khi lập kế hoạch Step có Alarm(ringNow) (§5.6.1)
if live == nil || live.targetAtWallMs < nowWall || live.targetAtWallMs > guardAt → armRingGuard(guardAt)
```
`PlanInput` thêm `liveSlot: AlarmSlotRec?` (runtime tính, planner không đọc `ledger.current` trực tiếp cho việc này).

**Ngoại lệ (thay đổi của coder, reviewer chấp nhận vòng 1):** nếu `facts.ringingNow` (đã có alarm của chuyến đang `alerting`, hoặc một
"now" đã xác nhận đang chờ kêu theo `RingFactsReader`) thì **không** `armRingGuard`, kể cả khi điều kiện trên đúng. Mục đích: giữ bất biến
"không có 2 alarm của chuyến cùng kêu" (T10 nghĩa vụ 3, "mỗi chuyến tối đa một báo đang kêu"). Thứ tự trong §5.2 thành:
```
if A?.ringNow:
    if !facts.ringingNow && (live == nil || live.targetAtWallMs < nowWall || live.targetAtWallMs > guardAt) → armRingGuard(guardAt)
    persistNow; (feed FallbackFired | ring_live | ringNow) như cũ
```
Hệ quả rủi ro: RK-T17-12.

**Vệ sinh sổ** (để `ledger.current` không còn trỏ vào khe chết):
- `perform(.cancel(id))` (interpreter huỷ khe khi thấy "now" `alerting`, nghĩa vụ 4): nếu `id == ledger.current?.alarmId` → `ledger.current =
  nil`; nếu `id == ledger.stale?.alarmId` → `ledger.stale = nil`; ghi sổ.
- `perform(.fallbackFired(id, …))`: sau khi ghi `lastFired`, nếu `id` là `current`/`stale` → đặt `nil`; ghi sổ.
- `cancelSlots`, `endTrip`: như cũ (đã đặt `nil`).
- **Không** đặt `nil` khi chỉ vì `list()` trả `nil` (không biết trạng thái).

**`handleClockChanged`** chỉ đặt lại khe khi `liveSlot(ledger, list())` khác `nil`, và đặt lại chính khe đó ở `toWall(live.targetAtMs)`; không có
khe sống → không làm gì (không đặt lại khe đã huỷ/đã kêu về giờ quá khứ).

### R2 — Khôi phục khi engine tin "đang kêu": một luật duy nhất (#3)

**Lập luận chốt.** Trên iOS, process chỉ được mở lại khi **người dùng tương tác**: mở app, hoặc bấm nút của một alarm (StopIntent, các intent
của T17.2). App không xin Always, không có `CLMonitor`, không có background fetch (T17 D10, PLAN Q1/Q8). Vì vậy lúc khôi phục chạy, người
dùng **đang thức**. Kêu lại ở bước khôi phục không giúp được người đang ngủ, mà còn có thể kêu lần hai sau khi họ vừa bấm Tắt (S3 #1).
Ngược lại, nếu engine đã quyết kêu mà **chưa có alarm hệ thống nào nhận** việc kêu (process chết trước khi `schedule` xong, và không có khe
canh chuông), thì kêu ngay là đúng: không có gì để người dùng đã Tắt.

**Phương án (orchestrator chọn thay PO theo phương án đề xuất, PO xem lại):**

| | A — **đề xuất, áp dụng** | B | C |
|---|---|---|---|
| Luật | Chỉ kêu lại khi **không** có alarm hệ thống nào của lần kêu đó từng được nhận (`RestoreRingPolicy` dưới). Mọi trường hợp hệ thống đã nhận (khe dự phòng/canh chuông/"now" đã xác nhận) → `AlarmSilenced` | Không bao giờ kêu lại ở bước khôi phục | Luôn kêu lại khi engine tin "đang kêu" mà không có alarm `alerting` (mã hiện tại) |
| S3 #1 (kêu lần hai sau khi Tắt) | Không xảy ra: chỉ kêu khi chưa có alarm nào để Tắt | Không xảy ra | **Xảy ra** (review #3) |
| Bỏ lỡ báo | Chỉ khi AlarmKit đã nhận alarm nhưng không kêu (trễ/mất [AK-FAN]) **và** process chết; khi khôi phục, người dùng đã thức (lập luận trên) | Thêm ca: engine quyết kêu, process chết trước `schedule` mà không có khe canh chuông → không ai kêu, UI hiện "đang báo" khi mở app | Không |
| Parity Android G3 | Có (G3: "lần kêu cuối của engine chưa tới được loa → kêu") | Không | Không |

**`RestoreRingPolicy.decide`** (hàm thuần, `TripRuntime/AlarmUpdateInterpreter.swift`; thay §5.8 bước 2):
```
Điều kiện chạy: pha ∈ {ALARMING, OVERSHOT} && view.alarmRinging && list không có alarm nào của chuyến ở .alerting
Đầu vào: info (RestoreInfo đã dùng), ledger (sau LedgerReconciler), list (có thể nil), nowWall, lagMs = fallbackLagS·1000,
         graceMs = NOW_ALERT_GRACE_MS, alarmWall = ledger.now?.fireAtWallMs ?? toWall(engine lastRingAtMs)
1. info.status == RANG                                   → .silenced(atWall: nowWall)       -- báo dự phòng/canh chuông đã kêu (K4 #8)
2. n = ledger.now; if n?.confirmed == true:                                                  -- AlarmKit (hoặc kênh thông báo) đã nhận "now"
      list != nil && list có n.alarmId ở .scheduled       → .none                            -- sẽ tự kêu
      list == nil && nowWall < n.fireAtWallMs + graceMs   → .none
      else                                                → .silenced(atWall: n.fireAtWallMs)
3. cover = slot đầu tiên trong [ledger.current, ledger.stale] có targetAtWallMs ≤ alarmWall + lagMs + 1 000   -- khe canh chuông (D7: đặt trước PersistNow) hoặc khe dự phòng gần
   if cover != nil:
      list != nil && list có cover.alarmId ở .scheduled   → .none                            -- sẽ kêu ≤ 30 s
      list == nil && nowWall < cover.targetAtWallMs       → .none
      cover.targetAtWallMs ≤ nowWall                      → .silenced(atWall: cover.targetAtWallMs)   -- đã tới giờ, alarm hết → coi như đã kêu
      else                                                → .ring                            -- khe bị mất trước giờ, chưa kêu
4.                                                        → .ring                            -- engine quyết kêu, chưa alarm hệ thống nào nhận (G3)
Hành động: .none → không gì; .silenced(w) → feed(.alarmSilenced(now, max(state.alarm.lastRingAtMs, toTrip(w))));

```
