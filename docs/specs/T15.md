## Bối cảnh & mục tiêu

- PRD §1: báo đúng lúc khi máy khoá, im lặng, chạy 10 giờ. ARCHITECTURE §1: quyết định "báo hay chưa" nằm ở native. Trên Android, nơi
  chạy engine là T15: nhận vị trí từ Fused Location Provider (FLP) trong một foreground service (FGS) `location`, đưa vào `TripEngine.reduce`
  (module `:core-trip`, T12), rồi thực thi các yêu cầu của engine (đổi chu kỳ lấy mẫu, hẹn `Tick` theo `wakeAtMs`, đặt/huỷ báo dự phòng,
  kêu báo, gửi trạng thái cho Flutter).
- ADR-001: chỉ có quyền vị trí "Khi dùng ứng dụng". FGS `location` chỉ khởi động khi activity hiển thị hoặc khi người dùng chạm thông báo.
  Khi FGS đã chết, **không** được khởi động lại nó từ nền (exact alarm, `BOOT_COMPLETED`). Lưới an toàn là báo dự phòng theo ETA của engine.
- T14 đã có lớp nối Pigeon và `StubTripBackend`. T15 thay backend thật vào `BridgeRegistrar`, **không đổi Pigeon**.
- Nhiều ràng buộc mang sang từ các task trước (hàng T15 trong `docs/TASKS.md`): ghi snapshot lỗi không bao giờ chặn việc kêu (review T14
  R2-1), cô lập lỗi listener (R2-3, test report T14 F1), đo Doze c8 (T10.2) và RK17 (T10.4), FLP có giao fix trong Doze không (T12.1/T12.2),
  đặt lại báo dự phòng khi báo cũ còn ~10 s (T10.5), phát `TripStateUpdateMsg` ngay khi bắt đầu và từ chối `startTrip` thứ hai (review T25).

## Phạm vi

**Làm**
1. Module JVM thuần mới `:core-runtime` (giống cách làm `:core-trip`, T12 K1): bộ điều phối chuyến `TripRuntime` (tuần tự hoá engine),
   các hàm thuần quyết định hiệu ứng (`EffectPlanner`, `RestorePlanner`, `FallbackSlots`, đồng hồ chuyến, ánh xạ lấy mẫu/fix), lưu trữ
   snapshot, sổ báo dự phòng, và các interface (cổng) tới nền tảng. Test JVM với cổng giả, gồm chạy trace GPX của `fixtures/traces`.
2. Trong `:app`: `LocationService` (FGS `location`), `FusedLocationSource`, bộ hẹn giờ OS (`setExactAndAllowWhileIdle` cho `wakeAtMs`,
   `setAlarmClock` cho báo dự phòng), các receiver (đánh thức, báo dự phòng, khởi động máy, cập nhật app, sự kiện chuông, nút trên thông báo),
   thông báo thường trực + thông báo cảnh báo chuyến, `RealTripBackend` (hiện thực `TripBackend` của T14), ánh xạ engine → Pigeon.
3. Ranh giới T15 ↔ T16: interface `AlarmPort` + hợp đồng sự kiện chuông. T15 có bản tạm `InterimAlarmPort` (thông báo âm báo dạng
   `FLAG_INSISTENT`) để test được T15 trước khi T16 xong. T16 thay bản tạm.
4. Lưu snapshot ở `noBackupFilesDir`, khôi phục theo T10 §7.2 (process chết, sticky restart, đánh thức bằng alarm, báo dự phòng kêu khi
   process đã chết, khởi động lại máy, cập nhật app, mở lại app).
5. Bản debug: nhật ký đo (`journal`, không toạ độ) + lệnh adb (`DebugCommandReceiver`) + nguồn vị trí phát lại GPX ở 1× để chạy giao thức
   đo trên máy (RK17, Doze c8, FLP trong Doze, đặt lại báo khi còn 10 s, ghi đĩa lỗi).
6. Sửa nhỏ: `BackgroundCheckScheduler` (T21, phép thử 30 s ở màn 9) dùng cùng API với báo dự phòng (`setAlarmClock`), như T21 đã dặn.

**KHÔNG làm**
- Không làm màn báo thức toàn màn hình, âm tăng dần, rung theo mức, flash, tai nghe, cách tắt (vuốt/lắc/phép tính), `AlarmRingService`
  ở process `:ring`, `AlarmHostApi` thật: đó là **T16**. T15 chỉ gọi `AlarmPort`.
- Không làm chế độ giả lập 10×/60× với đồng hồ ảo (T18). Nguồn phát lại của T15 chỉ chạy 1×, chỉ trong bản debug, để đo trên máy.
- Không đổi engine (`:core-trip`), không đổi `EngineParams`, không thêm khoá Remote Config, không đổi Pigeon (`core_api.dart`).
- Không làm UI Flutter (màn 4/6/7 là T26, màn 5/8 là T27). Chỉ thêm khoá ARB cho chuỗi native (để hai bên cùng nội dung).
- Không xin thêm quyền nào ngoài ARCHITECTURE §7.1. Không `ACCESS_BACKGROUND_LOCATION`, không xin miễn tối ưu pin.
- Không có nguồn vị trí thay cho FLP khi máy không có Google Play services (xem Rủi ro, Đề xuất sau MVP).

### 4. Interface và kiểu dữ liệu

#### 4.1 Cổng của runtime (`:core-runtime`, package `app.napstop.core.trip.runtime`)

```kotlin
package app.napstop.core.trip.runtime

import app.napstop.core.trip.*

/** Trip clock (T10 §2.6): monotonic, ≈ wall clock. All engine times use it. */
interface TimeSource {
    fun wallMs(): Long           // System.currentTimeMillis()
    fun elapsedMs(): Long        // SystemClock.elapsedRealtime()
    fun elapsedNanos(): Long     // SystemClock.elapsedRealtimeNanos()
    fun bootCount(): Int?        // Settings.Global.BOOT_COUNT, null if unreadable
}

/** One raw fix as the platform gives it; no Android types. toString() redacts lat/lng. */
data class RawFix(
    val lat: Double, val lng: Double,
    val accuracyM: Float?,            // null = !hasAccuracy()
    val speedMps: Float?,             // null = !hasSpeed()
    val elapsedRealtimeNanos: Long,   // Location.getElapsedRealtimeNanos()
)

enum class FlpPriority { HIGH_ACCURACY, BALANCED_POWER_ACCURACY }
data class FlpRequestSpec(val priority: FlpPriority, val intervalMs: Long, val minUpdateIntervalMs: Long,
                          val maxUpdateDelayMs: Long, val maxUpdateAgeMs: Long)

interface LocationSource {
    /** Starts or replaces the request. Fixes go to [onFix] on any thread. Throws SecurityException if no permission. */
    fun request(spec: FlpRequestSpec, onFix: (RawFix) -> Unit)
    fun stop()
    /** FusedLocationProviderClient.getLastLocation(); null if none or error. */
    suspend fun lastKnown(): RawFix?
}

enum class StartReason { USER_START, APP_VISIBLE, NOTIFICATION_TAP }
sealed interface ForegroundResult { data object Started : ForegroundResult; data class Failed(val errorClass: String) : ForegroundResult }

interface TrackingController {
```

#### 4.4 Sự kiện chuông (T16 → T15, khác process)

Broadcast **tường minh** (component `RingEventReceiver`, `exported=false`, cùng UID nên gửi được từ `:ring`), action
`app.napstop.action.RING_EVENT`, extras:

| Extra | Kiểu | Ghi chú |
|---|---|---|
| `tripId` | String | `[A-Za-z0-9_-]{1,64}` |
| `kind` | String | `DISMISSED` \| `SNOOZED` \| `SILENCED` \| `FALLBACK_RINGING` |
| `atWallMs` | Long | lúc xảy ra |

`RingEvent(tripId, kind, atWallMs)` → runtime: `DISMISSED` → `UserAction(DISMISS)`; `SNOOZED` → `UserAction(SNOOZE)`; `SILENCED` →
`AlarmSilenced(silencedAtMs = toTrip(atWallMs))`; `FALLBACK_RINGING` → `FallbackFired(firedAtMs = toTrip(atWallMs))` (chỉ khi T16 tự
kêu một báo dự phòng không qua `FallbackAlarmReceiver`; T15 hiện không cần, giữ cho T16). Trước khi gửi `DISMISSED`, T16 phải ghi
`pendingDismissAtWallMs` vào `ringFacts` (để process chính chết giữa chừng vẫn khôi phục ra `DISMISSED`, §5.8). Runtime đã nhận
`DISMISSED` thì gọi `AlarmPort.clearTrip` sau `TripEnded`.

#### 5.2 Vòng xử lý Step (actor) và thứ tự hiệu ứng

Hàng đợi có hai mức: **phản hồi nội bộ** (`Effect.Feed`, `FallbackScheduled`) được xử lý ngay sau Step hiện tại, trước mọi lệnh ngoài.

```
process(input):
  s = active ?: return                                   -- không có chuyến: bỏ qua
  step = TripEngine.reduce(s.engine, input)              -- Tick.atMs, fix.atMs = clock.now() lúc giao (không sớm hơn mốc, T10.4)
  facts = alarmPort.ringFacts(tripId)                    -- chỉ đọc khi step có Alarm(ringNow=true) hoặc cần cho restore
  commit(step)                                           -- bộ nhớ: engine, lastView
  for fx in EffectPlanner.plan(PlanInput(prevView, step, …)): execute(fx)    -- mỗi fx trong try/catch riêng, warn(tên lớp)
```

`EffectPlanner.plan` (thuần, thứ tự cố định; theo thứ tự sự kiện T10 §2.3):

```
fx = []
ringOk = true
A = step.events.firstOrNull { it is Alarm }              -- tối đa một (I11)
if A != null && A.ringNow:
    fx += PersistNow(PRE_RING_PERSIST_BUDGET_MS)

        fx += Feed(FallbackFired(atMs = nowTrip, firedAtMs = toTrip(facts.ringStartedAtWallMs) ?: nowTrip))
    else:
        fx += Ring(request(A))                           -- Ring ném → executor đặt ringOk = false (xem dưới)
for e in step.events in order:
    Snoozed                      → StopRinging(SNOOZED)
    PreAlert                     → PreAlertFx(...)
    Overshoot                    → OvershootFx(e.pastM)   (AlarmPort tự bỏ qua nếu không đang kêu)
    SamplingPolicyChanged        → ApplySampling(FlpMapper.spec(e.policy, params))  chỉ khi mode == TRACKING_FGS
    GpsLost(NEVER_ACQUIRED)      → Notice(show = NoGpsYet)
    GpsLost(PERMISSION_REVOKED)  → Notice(show = PermissionRevoked)
    GpsLost(SERVICES_OFF)        → Notice(show = ServicesOff)
    GpsRecovered                 → Notice(clear = NoGpsYet), Notice(clear = PermissionRevoked), Notice(clear = ServicesOff)
    FallbackAlarmChanged(at≠null)→ ScheduleFallback(at)
    FallbackAlarmChanged(null, SUPERSEDED) → CancelFallback(onlyIfRingOk = true)     -- nghĩa vụ 4
    FallbackAlarmChanged(null, TRIP_ENDED) → CancelFallback(onlyIfRingOk = false)
if view.fallbackStatus == FAILED && prevView?.fallbackStatus != FAILED → Notice(show = FallbackFailed)
if view.fallbackStatus == CONFIRMED && prevView?.fallbackStatus == FAILED → Notice(clear = FallbackFailed)
if view.wakeAtMs != null && view.wakeAtMs != scheduledWakeAtMs → ScheduleWake(view.wakeAtMs, WakePolicy.mechanism(view))

```
- Executor: `Ring` ném → `ringOk = false`, `warn(tên lớp)`, và **giữ** mọi khe báo dự phòng (bỏ qua `CancelFallback(onlyIfRingOk=true)`).
  T15 không tự hiện thông báo thay thế (cách báo khi không kêu được là việc của `AlarmPort`). Báo dự phòng còn lại kêu ở giờ đã đặt
  (≤ `P + 30 s` ở vùng gần) và `FallbackAlarmReceiver` kêu nó vì engine đang ALARMING mà port không kêu.
- `Feed` đưa input vào hàng đợi phản hồi; Step kế tiếp cũng đi qua `plan` (ví dụ `FallbackFired` ở ALARMING không có sự kiện).
- `Persist`: writer ghi nếu Step có sự kiện, hoặc đã ≥ `SNAPSHOT_MIN_INTERVAL_MS` kể từ lần ghi trước (T10 §7.1 b, c).
- `Publish`: chuyển `(view, events)` cho `RuntimeListener` của `RealTripBackend`, nơi `MsgMapper` đổi sang `TripStateUpdateMsg` + các `*Msg`

- `Tracking`: chỉ gọi `updateTrackingNotification` khi nội dung đã định dạng khác lần trước **và** cách lần trước ≥ `NOTIF_MIN_INTERVAL_MS`

#### 5.3 Đồng hồ chuyến và đổi giờ sang OS

```
clock(anchor).now() = max(lastIssued, anchor.wallMs + (time.elapsedMs() − anchor.elapsedMs))      -- T10 §2.6, không lùi
anchorValid(a) = a.bootCount != null && a.bootCount == time.bootCount()

toElapsed(tTrip) = time.elapsedMs() + max(0, tTrip − clock.now())      -- cho ELAPSED_REALTIME_WAKEUP
```

Đổi giờ hệ thống giữa chuyến: `LocationService` đăng ký động `ACTION_TIME_CHANGED`; khi nhận, runtime đặt lại báo dự phòng hiện tại ở cùng
`targetAtMs` (`toWall` mới). Trong `HEADLESS` không có đăng ký này; sai lệch = lượng chỉnh đồng hồ (RK9, chấp nhận).

#### 5.5 Đánh thức (`wakeAtMs`)

- Sau mỗi Step có `view.wakeAtMs` khác giờ đã hẹn: `scheduler.setWake(toElapsed(wakeAtMs), mechanism, toWall(wakeAtMs))`. Một
  `PendingIntent` duy nhất (broadcast `WakeAlarmReceiver`, request code riêng); đặt lại là thay thế. Pha ENDED → `cancelWake`.
- `WakePolicy.mechanism(view)` (thuần): `!scheduler.canScheduleExact()` → `INEXACT_IDLE` (`setAndAllowWhileIdle`, journal ghi);
  `NEAR_WAKE_USES_ALARM_CLOCK && view.phase ∈ {ACQUIRING, TRACKING} && view.predictedAlarmAtMs != null &&
  wakeAtMs ∈ [predicted, predicted + 2·WAKE_GUARD_MS]` → `ALARM_CLOCK`; còn lại `EXACT_IDLE`.
- Khi CPU thức và có FGS: coroutine trong runtime gửi `Tick` ở `min(wakeAtMs, lastStep + AWAKE_TICK_MAX_MS)` (T10 §2.6 "không thưa hơn
  60 s khi CPU thức"). Hai nguồn Tick trùng nhau là vô hại (I14).
- `WakeAlarmReceiver.onReceive`: `goAsync()`; trong `RECEIVER_BUDGET_MS`: `runtime.ensureLoaded()`, đọc pin sticky → `BatterySample` nếu đổi,
  kiểm quyền/định vị → `LocationAvailability` nếu đổi, rồi `Tick(clock.now())`; chờ actor xử lý xong; `finish()`. **Không** gọi
  `TrackingController.start` (D9).

```
  exact = scheduler.canScheduleExact()
  try scheduler.setFallback(newSlot, tripId, g, targetAtMs, toWall(targetAtMs), exact)   -- exact: setAlarmClock; ngược lại setAndAllowWhileIdle
  catch e → warn; Feed(FallbackScheduled(now, targetAtMs, ok = false)); return                -- giữ khe cũ (nghĩa vụ 1)
  ledger = L.copy(nextGeneration = g + 1, current = rec(newSlot, g, targetAtMs), stale = L.current)
  store.writeLedger(ledger)            -- lỗi: warn, vẫn tiếp (báo đã đặt; khôi phục dùng snapshot engine)
  if L.current != null: scheduler.cancelFallback(L.current.slot); ledger.stale = null; writeLedger
  Feed(FallbackScheduled(now, targetAtMs, ok = exact))   -- không có quyền exact: vẫn đặt bản inexact nhưng báo ok=false để UI cảnh báo (PRD §3.1)
cancel():                                               -- CancelFallback
  cancel cả hai khe; ledger.current = null, stale = null
```
- `PendingIntent.getBroadcast(ctx, REQ_FALLBACK_BASE + slot, Intent(FallbackAlarmReceiver)+extras, FLAG_UPDATE_CURRENT | FLAG_IMMUTABLE)`;
  extras: `tripId`, `generation`, `targetAtMs`. **Không** có toạ độ, tên đích. `AlarmClockInfo(triggerWallMs, showIntent)` với
  `showIntent` = `PendingIntent.getActivity(MainActivity)`.
- Huỷ: `PendingIntent` cùng request code với `FLAG_NO_CREATE | FLAG_IMMUTABLE` → `alarmManager.cancel(pi)`, `pi.cancel()` [A-ALM].

`FallbackAlarmReceiver.onReceive(tripId, generation, targetAtMs)`:
```
pending = goAsync()                                     -- mọi bước trong try riêng; tổng ≤ RECEIVER_BUDGET_MS
L = store.readLedger()  (lỗi → ledger rỗng)
if L.activeTripId != tripId && !runtimeKnowsActive(tripId) → cancel khe này; journal(ignored); finish   -- báo cũ của chuyến đã xong
facts = alarmPort.ringFacts(tripId)
if facts.ringingNow → (đã có một báo của chuyến đang kêu) không kêu; vẫn đi tiếp bước ghi + Feed   -- "mỗi chuyến tối đa một báo đang kêu"
else:
  store.writeLedger(L.copy(lastFired = FiredRec(generation, targetAtMs, toTrip(nowWall), nowWall)))  -- trước khi kêu (D8); lỗi: vẫn kêu
  alarmPort.ringFallback(RingRequest(tripId, FALLBACK, reason = null, snoozeAllowed = <ring_config>, …, destinationName từ
                         ring_config.properties hoặc null))
cancel khe còn lại của chuyến; ledger.current = null                                               -- nghĩa vụ 5
runtime.ensureLoaded(); runtime.onFallbackFired(tripId, generation, targetAtMs)  -- → FallbackFired(firedAtMs) nếu runtime chưa biết (§5.8)
pending.finish()
```
- Báo cũ chưa kịp huỷ (khe `stale`) kêu trong lúc đặt lại: đi đúng đường trên (nghĩa vụ 5); khe mới bị huỷ, nên không có tiếng thứ hai (ca
  T10.5 §8, test L24, đo M4).
- `snoozeAllowed` của `RingRequest` báo dự phòng = `snoozeCount < maxSnoozes` đọc từ `ring_config.properties` (T15 ghi lại `snoozeCount` mỗi
  khi đổi). Nếu engine sau `FallbackFired` cho `Alarm.snoozeAllowed` khác (không xảy ra với T10 §3, vì cùng công thức), runtime gọi
  `AlarmPort.ringNow` với cùng `tripId` để cập nhật nội dung (port không kêu lần hai, §4.2).

#### 5.7 Lưu trữ (định dạng, vị trí, ghi)

Thư mục `context.noBackupFilesDir/napstop_trip/` — bị loại khỏi Auto Backup **và** chuyển máy, kể cả khi có `<include>` [A-BAK]. Mọi file
`java.util.Properties`, ghi `tmp` + `fd.sync()` + rename nguyên tử (giống `StubStore`, T14 §5.3).

| File | Nội dung | Ghi khi |
|---|---|---|
| `active_trip.properties` | `runtimeVersion=1`, `meta.*` (như khoá `config.*` của `StubStore`, không toạ độ), `anchor.wallMs/elapsedMs/bootCount`, `savedAtWallMs`, `engine` = `TripEngine.encodeSnapshot(state)` (JSON v1, có toạ độ đích + ≤ 3 fix) | writer: Step có sự kiện; ≥ 60 s nếu bẩn; `PersistNow` trước khi kêu; `start` |

| `ring_config.properties` | `tripId`, `destinationName`, `RingSettings`, `snoozeCount`, `maxSnoozes` (cho T16/receiver, khác process) | `start`; khi `snoozeCount` đổi |
| `finished/<tripId>.properties` | `FinishedRecord` (cùng khoá với `StubStore.encodeFinished`) | `Finish` |

- **Writer** (`SnapshotWriter`): coroutine trên IO, kênh `CONFLATED` (luôn ghi bản mới nhất). Lỗi → `warn("snapshot write failed (<Lớp>)")`,
  thử lại sau `SNAPSHOT_RETRY_MS` hoặc ở Step kế tiếp; không bao giờ ném ra actor. `PersistNow(budget)` = `withTimeoutOrNull(budget) {
  writer.flush() }`; hết giờ/lỗi thì actor đi tiếp (D4). Không log nội dung, không log toạ độ.
- **Kết thúc chuyến** (`Finish`): `writeFinished` → `deleteActive` → `deleteRingConfig` → ledger `activeTripId = null`. `writeFinished` lỗi →
  giữ bản ghi trong bộ nhớ (`pendingFinished()` trả cả bản này), ghi snapshot với `phase = ENDED` (best-effort), thử lại; lần nạp sau thấy
  snapshot ENDED thì dựng `FinishedRecord` từ `EngineState` (`FinishedRecordBuilder.fromEnded(state)`: `ended.outcome/endReason/atMs`,
  `startedAtMs`, `alarm.atMs/reason/dismissedAtMs/snoozeCount`, `roundHalfUp(movingDistM)`, `vehicleGuess` theo T10 §4.14 — test L19 so với
  `TripEnded.summary`).
- Đọc: `decodeSnapshot` lỗi (`SnapshotFormatException`) hoặc `runtimeVersion ≠ 1` → xoá file, `warn` mã lỗi, coi như không có chuyến; nếu
  ledger còn `activeTripId` → hiện `TripNotice.Interrupted` (không tên đích) và **giữ** báo dự phòng đang đặt (T10 RK8).

#### 5.8 Khôi phục (`RestorePlanner`, thuần)

`ensureLoaded(cause)` chạy một lần mỗi process, ở **mọi** điểm vào: tạo backend (mở app), `LocationService.onStartCommand`,
`WakeAlarmReceiver`, `FallbackAlarmReceiver`, `BootReceiver`, `RingEventReceiver`, `TripActionReceiver`. `cause` thực tế = `BOOT` nếu anchor
không hợp lệ (§5.3) hoặc gọi từ `BOOT_COMPLETED`; `PACKAGE_REPLACED` nếu gọi từ `ACTION_MY_PACKAGE_REPLACED`; còn lại `PROCESS_START`.

```
plan(s: EngineState, ledger, facts: RingFacts, cause, nowTrip) → RestoreInfo:
  fb = s.fallback.targetAtMs
  if facts.pendingDismissAtWallMs != null:
        → DISMISSED(firedAtMs = toTrip(ledger.lastFired?.firedAtWallMs ?: facts.ringStartedAtWallMs), dismissedAtMs = toTrip(pendingDismiss))
  if fb != null && ledger.lastFired != null && ledger.lastFired.firedAtMs > s.nowMs:      -- báo dự phòng kêu sau Step cuối đã lưu
        → RANG(firedAtMs = ledger.lastFired.firedAtMs)
  if cause ∈ {BOOT, PACKAGE_REPLACED}                       → MISSING        -- reboot xoá alarm [A-AM]; cập nhật app: không chắc còn
  if fb != null && fb ≤ nowTrip                               → MISSING        -- tới giờ mà không có dấu vết đã kêu (force-stop, OEM)
  → PENDING
```
Sau `TripEngine.restore(s, now, info)`:
1. Thực thi hiệu ứng của Step khôi phục như §5.2 (có thể có `Alarm(FALLBACK_MISSED, ringNow=true)` → kêu; `FallbackAlarmChanged(RESYNC)` →
   đặt lại).
2. `PENDING` và `fb != null` → `ScheduleFallback(fb)` lại cùng giờ (đặt mới trước, huỷ cũ sau; lấy lại báo nếu OS đã xoá, ví dụ
   force-stop). `FallbackScheduled` khớp `fb` nên engine chấp nhận.
3. Pha ∈ {ALARMING, OVERSHOT} và `view.alarmRinging` và `!facts.ringingNow` → `Feed(AlarmSilenced(silencedAtMs =
   toTrip(facts.silencedAtWallMs) ?: now))` (T10 §7.2).
4. Chế độ: FGS đang chạy trong process này → `TRACKING_FGS`; ngược lại `HEADLESS`. `HEADLESS` và pha ∈ {ACQUIRING, TRACKING} →
   `TripNotice.Interrupted` ("Chuyến đi bị gián đoạn — chạm để tiếp tục theo dõi", ADR-001 #4, PRD §4). Pha ALARMING/SNOOZED/OVERSHOT → không
   hiện (đang có báo thức).
5. `onFallbackFired` gọi sau khôi phục: nếu `ledger.lastFired.generation` đã được gói vào `RANG` thì bỏ; ngược lại `Feed(FallbackFired)`.

Bảng điểm vào:

| Tình huống | Đường | Kết quả |
|---|---|---|
| Process bị giết, hệ thống sticky restart `LocationService` (`intent == null`) | `ensureLoaded(PROCESS_START)`; nếu có chuyến chưa ENDED: thử `startForeground(LOCATION)` | thành công → `TRACKING_FGS`, đăng ký FLP lại; `SecurityException` → `HEADLESS`, `Interrupted`, `stopSelf`. Không có chuyến → `stopSelf`. S1 đo trên máy có vị trí không |
| Process chết, `wakeAtMs` tới | `WakeAlarmReceiver` | khôi phục (`PENDING`), Tick, `HEADLESS` |
| Process chết, báo dự phòng tới | `FallbackAlarmReceiver` | ghi sổ, kêu, khôi phục `RANG`, `HEADLESS`, engine ALARMING |
| Người dùng Tắt trên màn báo thức T16 khi process chính chết | T16 ghi `pendingDismiss` rồi gửi `RING_EVENT` | khôi phục `DISMISSED` → ENDED → `finished/` |
| Reboot | `BootReceiver` (`BOOT_COMPLETED`) | `MISSING`: tới giờ → `FALLBACK_MISSED` kêu ngay; chưa tới → `RESYNC` đặt lại; `Interrupted` |
| Cập nhật app giữa chuyến | `BootReceiver` (`ACTION_MY_PACKAGE_REPLACED`) | như reboot (MISSING) nhưng anchor còn hợp lệ |
| Người dùng mở app | `BridgeRegistrar.backend` → `ensureLoaded`; `MainActivity.onStart` → `onAppVisible` | `HEADLESS` + chuyến chưa ENDED → khởi động lại FGS (D11) |
| Chạm thông báo "gián đoạn" | mở `MainActivity` với extra `napstop.resumeTripId` | như trên, `StartReason.NOTIFICATION_TAP` |
| Task Manager "Dừng" (Android 13+) | không có callback; alarm vẫn chạy [A-STOP] | như "process chết" |
| Buộc dừng (Cài đặt) | hệ thống huỷ alarm của app | không có báo dự phòng tới khi mở lại app (khi đó `MISSING` nếu đã quá giờ). Rủi ro RK-T15-6 |

#### 5.9 Máy trạng thái của runtime/service (`TrackingMode`)

```

   IDLE ─────────────────────▶ STARTING ───────────────────────────────▶ TRACKING_FGS ◀──────────────┐
     ▲                            │ Failed / quá giờ                        │ FGS chết (sticky lỗi,       │ onAppVisible /
     │                            ▼                                         │ process mới không có FGS)   │ notification tap
```

| Từ | Sự kiện | Sang | Việc |
|---|---|---|---|
| IDLE | `start` thiếu điều kiện | IDLE | `Rejected` |

| STARTING | `Started` | TRACKING_FGS | commit, hiệu ứng step0, `Publish`, trả `Started` |
| STARTING | `Failed` / hết `FGS_START_TIMEOUT_MS` | IDLE | `stop`, `Rejected(start-failed)` |
| STARTING | `start` lần hai | STARTING | `Rejected(trip-active)` |
| TRACKING_FGS | `onDestroy` không do runtime yêu cầu (hệ thống/OEM) | HEADLESS | FLP coi như tắt; `Interrupted` nếu chưa báo |
| (process mới) | `ensureLoaded` có chuyến | HEADLESS hoặc TRACKING_FGS | §5.8 |
| HEADLESS | `onAppVisible` / tap, pha ≠ ENDED, đủ quyền | STARTING | `start(reason)`; lỗi → ở lại HEADLESS |
| TRACKING_FGS / HEADLESS | Step có `TripEnded` | ENDING → IDLE | hiệu ứng `Finish`; `tracking.stop()` |

là `alarmMaxActiveS` của engine).

### 8. Pin, quyền riêng tư, a11y, copy

**Pin.** FLP theo tier của engine (SPARSE 180 s BALANCED, MEDIUM 30 s HIGH, DENSE 5 s HIGH, T10 §5). Mỗi Step O(1). Snapshot ≤ 1 lần/60 s
ngoài sự kiện. Thông báo ≤ 1 lần/15 s. Đánh thức theo `wakeAtMs` (T10 §10: vài lần mỗi giờ khi GPS OK; ≈ 7/giờ khi mất GPS ở vùng xa).
`setAlarmClock` chỉ có một báo kêu mỗi chuyến (thường là không kêu); đặt lại nhiều lần không tốn pin đáng kể. Không có vòng lặp bận, không giữ
wakelock dài. S4/T32 đo.

**Quyền riêng tư.** Toạ độ chỉ nằm trong `EngineState` (snapshot ở `noBackupFilesDir`) và trong bộ nhớ. Không log toạ độ, khoảng cách hay tên đích
ở mọi mức; log chỉ có tên lớp exception, enum, thời gian, `tripId`. `RawFix`, `StoredTrip`, `TripMeta`(tên đích) ghi đè `toString()`.
`PendingIntent` extras không có toạ độ/tên đích. Journal debug không có toạ độ/khoảng cách/tên đích. Không gửi gì tới Analytics/Crashlytics
(T29 tự lo). Thông báo trên màn khoá dùng bản công khai không có tên đích (`VISIBILITY_PRIVATE`).

**a11y.** Thông báo là UI hệ thống: tiêu đề và nội dung là câu đầy đủ (TalkBack đọc được), nút hành động có nhãn chữ ("Dừng theo dõi"),
không dựa vào màu. Tên kênh dễ hiểu trong Cài đặt.

### 1. F3 — kêu "now" lỗi hoặc process chết trước khi kêu: **khe canh chuông** (ring guard)

**Nguyên nhân.** Spec §5.2 dựa vào khe báo dự phòng còn lại khi `ringNow` lỗi. Khe đó do engine đặt; khi chuyến bắt đầu sát vùng báo, engine
chưa kịp dời nó (cửa sổ im lặng 30 s, `fallbackMinIntervalS`), nên khe còn là deadline lúc bắt đầu (~3 h sau).

**Quyết định G1 — trước mọi `Alarm(ringNow=true)`, bảo đảm có một khe báo dự phòng kêu không muộn hơn `now + fallbackLagS`.**
```

EffectPlanner, Step có Alarm(ringNow=true), thứ tự mới:
  [ArmRingGuard(guardAtWall), PersistNow(300), Ring | Feed(FallbackFired) (như cũ), …]
ArmRingGuard:
  cur = ledger.current
  if cur != null && cur.targetAtWallMs ≤ guardAtWall → giữ cur, đánh dấu cur.kind = GUARD (ghi sổ)   -- khe sẵn có đã đủ gần
  else → FallbackScheduler.schedule(kind = GUARD, targetAtWall = guardAtWall)                    -- A/B: đặt khe mới trước, huỷ cũ sau
  không Feed(FallbackScheduled) cho khe GUARD (engine không biết khe này)
  lỗi đặt → warn; đi tiếp (khe cũ, nếu có, còn nguyên)
FallbackAlarmChanged(null, SUPERSEDED) → KHÔNG huỷ khe nào nữa (thay CancelFallback(onlyIfRingOk = true) của §5.2):
  khe còn lại lúc này chính là khe canh chuông ≤ now + 30 s
```
**Khe canh chuông tới giờ** (`FallbackAlarmReceiver`, khe `kind = GUARD`):
```

if facts.ringingNow                                   → bỏ, huỷ khe. KHÔNG ghi lastFired, KHÔNG Feed(FallbackFired)   -- chuông còn sống
```

### 2. F1 — khôi phục sau reboot / cập nhật app khi đĩa chậm: **không bao giờ bỏ cuộc lặng lẽ**

**Quyết định B1 — vòng nạp có thử lại trong receiver.** `BootReceiver` (BOOT_COMPLETED, MY_PACKAGE_REPLACED), và mọi receiver nền (Wake,
Fallback, RingEvent, TripAction) cùng sticky restart, dùng chung `RestoreLoop`:
```
RestoreLoop.run(cause, deadline = startElapsed + RECEIVER_BUDGET_MS − 500):
  attempt = 0; safetyArmed = false
  loop:
    r = runtime.tryLoad(cause)     -- LOADED | NO_TRIP | CORRUPT | TIMEOUT(ledger: FallbackLedger?)   (mỗi lần đọc ≤ ioBudgetMs như vòng 2)
    if r is TIMEOUT && r.ledger != null && !safetyArmed: armSafety(r.ledger); safetyArmed = true      -- B2
    if r ∈ {LOADED, NO_TRIP, CORRUPT} → xử lý như thường (CORRUPT → §3 F2); return
    if elapsed + ioBudgetMs ≥ deadline → break
    delay(min(250 · 2^attempt, 1 000)); attempt++
  -- vẫn chưa nạp được
  scheduleRestoreRetry(cause, n = 0)                                                                  -- B3
  if (ledger đọc được && ledger.activeTripId != null && !ledger.interruptedAlerted):
       notifier.show(activeTripId, Interrupted, destinationName = null, alert = true); ghi interruptedAlerted (best-effort)
```
`tryLoad` là `ensureLoaded` hiện có nhưng trả kết quả; kết quả đọc muộn vẫn theo quy tắc R2-1 (bỏ nếu đã có chuyến mới).

**Quyết định B2 — khe an toàn từ sổ khi snapshot chưa đọc được.** Sổ nhỏ, đọc trên làn riêng; nếu đọc được mà snapshot thì chưa:
```
armSafety(L): nếu L.activeTripId != null && L.activeTripId ∉ L.endedTripIds && L.current != null:
   chỉ khi cause ∈ {BOOT, PACKAGE_REPLACED}   (PROCESS_START: alarm của OS vẫn còn, không đặt)
   target = max(L.current.targetAtWallMs, nowWall + SAFETY_LAG_MS)
   FallbackScheduler.schedule(kind = SAFETY, tripId = L.activeTripId, targetAtWall = target)          -- A/B như thường
```
`SAFETY_LAG_MS` = 30 000 (hằng; `params` nằm trong snapshot chưa đọc được). Khi
snapshot nạp được sau đó, khôi phục chạy như thường: `RestorePlanner` thấy `lastFired` (nếu khe an toàn đã kêu) → RANG; chưa kêu → MISSING
→ engine đặt lại báo dự phòng (A/B thay khe SAFETY) hoặc báo `FALLBACK_MISSED` ngay (khe SAFETY ≤ 30 s thành khe canh chuông theo G1).
`L.current == null` (engine không có báo dự phòng chờ, ví dụ đang ALARMING) → không đặt, đúng như engine (MISSING khi đã báo → không kêu).

**Quyết định B3 — hẹn thử lại bằng alarm khi hết ngân sách receiver.**
- `scheduleRestoreRetry(cause, n)`: `setExactAndAllowWhileIdle(ELAPSED_REALTIME_WAKEUP)` (không có quyền exact → `setAndAllowWhileIdle`) tới
  `WakeAlarmReceiver`, **PendingIntent riêng** (request code khác wake thường), extras `restoreRetry = n`, `cause`. Trễ: 30 s, 60 s, 120 s, 240 s,
  rồi 300 s mỗi lần; dừng khi nạp xong, `NO_TRIP`, `CORRUPT` (F2), hoặc sau `RESTORE_RETRY_MAX_MS` = 24 h (khi đó, nếu sổ có chuyến: đăng
  Interrupted có âm một lần — người dùng ít nhất thấy khi mở máy).
- Receiver nhận `restoreRetry`: chạy `RestoreLoop.run(cause từ extra)`; hết lần lại hẹn `n + 1`.
- `cause` lấy từ extra vì `PACKAGE_REPLACED` không suy ra được từ anchor; `BOOT` vẫn tự nhận ra qua `bootCount` khi snapshot nạp được.

**Số kỳ vọng sau sửa** (`f1Numbers`, đĩa chậm 500 / 1 500 / 2 100 / 2 500 / 5 000 ms): mọi mức → **có** khe báo dự phòng (khe SAFETY từ sổ ngay
khi sổ đọc được, rồi khe engine khi snapshot nạp) và **có** thông báo "gián đoạn"; đĩa treo hẳn suốt receiver → có alarm `restoreRetry` hẹn
30 s, và lần thử sau nạp được thì khôi phục đầy đủ.

### 3. F2 — sổ còn chuyến nhưng snapshot mất/hỏng: báo một lần rồi thôi

   người dùng chạm hoặc vuốt.

### 4. F5 — `wake_fire` ghi giờ của alarm vừa giao

### 5. Thay đổi kiểu dữ liệu / hằng

- `FallbackSlotRec` thêm `kind: SlotKind { ENGINE, GUARD, SAFETY }` và `targetAtWallMs: Long` (khoá Properties mới; thiếu → `ENGINE`,
