# T01 — CI GitHub Actions: analyze, test Dart, test Kotlin JVM, build APK debug

Trạng thái đề xuất: **spec-ready**. Có 3 câu hỏi mở, không câu nào chặn coding, câu nào cũng đã có phương án mặc định.
Riêng bước kiểm chứng cuối (PR mẫu trên GitHub) cần người dùng duyệt push (§6).

## Bối cảnh & mục tiêu

- PLAN Phase 0, Gate: "Build được APK rỗng, **CI xanh**". TASKS T01: tiêu chí "Workflow xanh trên PR mẫu".
- T00 (done) dựng `app/`: Flutter **3.47.8** (Dart 3.13.7), `very_good_analysis` 11, `sdk: ^3.13.7`, flavor `dev`/`prod`
  (`default-flavor: dev`), AGP 9.1.0 / Gradle 9.3.1 / Kotlin 2.4.0, JDK 17, NDK 28.2.13676358, 1 test Kotlin JVM. Theo T00 §3c
  và R4, **CI phải pin đúng Flutter 3.47.8**: bản cũ hơn không resolve được VGA 11 và không parse được `new(...)`.
- CLAUDE.md: "độ tin cậy trên hết", "mọi hàm logic thuần phải có unit test". CI là chốt chặn tự động cho các task sau
  (T12 Trip Engine Kotlin chạy fixture, T14 Pigeon, T20+ UI).
- Quyền riêng tư: MVP 1 không backend, chưa có Firebase. T01 không cần secret nào.
- Mục tiêu: một workflow đơn giản, tái lập được, chạy trên PR và `main`: format, analyze, test Dart (2 flavor),
  test Kotlin JVM (2 biến thể), build APK debug (2 flavor). Sau này thêm job `tracegen` (T02) chỉ cần chép một khối.

## Phạm vi

**Làm**
1. `.github/workflows/ci.yml`: 2 job song song là `dart` và `android` (nội dung chuẩn ở §3).
2. Pin toolchain: Flutter 3.47.8 stable, kiểm lại phiên bản Flutter/Dart sau khi cài; JDK Temurin 17; NDK 28.2.13676358;
   runner `ubuntu-24.04`. Pin action bằng **full commit SHA** (§2).
3. Cache: Flutter SDK + pub cache (qua `subosito/flutter-action`), Gradle (qua `actions/setup-java` `cache: gradle`).
4. Bảo mật: `permissions: contents: read`, `persist-credentials: false`, không dùng secret, không dùng `pull_request_target`.
5. `concurrency`: huỷ run cũ của cùng PR; run trên `main` thì xếp hàng, không huỷ.
6. Job summary (bảng kết quả trên trang run) để người dùng đọc và báo lại, vì repo private và máy không có `gh` (§6).
7. Thêm 1 test Dart kiểm `AppFlavor.current` khớp `--flavor` của lần chạy (§4). Nhờ test này, lần chạy `--flavor prod`
   mới có giá trị.
8. `app/README.md`: thêm mục "CI".
9. Kiểm chứng: tĩnh tại máy (actionlint), chạy lại các lệnh của CI trên Windows, rồi PR mẫu trên GitHub (người dùng duyệt push).

**KHÔNG làm**
- Job `tracegen` (T02 thêm, có khung sẵn ở §5). Pigeon codegen check (T14). Kiểm quyền APK theo allow-list (đề xuất cho T15).
- Build iOS / runner macOS (Gate 1; macOS tốn phút gấp khoảng 10 lần Linux).
- Ký số release, upload APK làm artifact mỗi run (T40; lý do ở §7). Firebase, secret.
- Dependabot, branch protection, chạy actionlint trong CI (xem "Đề xuất sau MVP" và Câu hỏi mở).
- Không sửa `pubspec.yaml`, Gradle, code `lib/`.

## Thiết kế

### 1. Kiến trúc workflow

```
on: pull_request (mọi base) │ push main │ workflow_dispatch      (bỏ qua nếu chỉ đổi docs/**, **.md, .claude/**)
                │
     ┌──────────┴───────────┐  (song song, ubuntu-24.04)
     ▼                      ▼
 job dart (≤15')        job android (≤30')
 checkout               checkout
 flutter 3.47.8 (+cache) JDK 17 Temurin (+cache gradle)
 verify versions        flutter 3.47.8 (+cache) · verify versions
 pub get --enforce-lock Gradle heap 4g (runner 8 GB)
 dart format check      sdkmanager ndk;28.2.13676358
 flutter analyze        pub get --enforce-lockfile
 flutter test (dev)     flutter build apk --config-only (sinh gradlew)
 flutter test --flavor  ./gradlew :app:testDevDebugUnitTest :app:testProdDebugUnitTest
   prod                 flutter build apk --debug          (default flavor = dev)
 summary (always)       flutter build apk --debug --flavor prod
 artifact (failure)     verify APK package id (aapt2)
                        summary (always) · artifact test reports (failure)
```

Các quyết định chính:

| # | Quyết định | Lý do |
|---|---|---|

| D3 | Flutter qua `subosito/flutter-action` v2.23.0, `flutter-version: 3.47.8`, `channel: stable` | Action tải đúng archive chính thức từ `releases_linux.json`, so khớp `.version == "3.47.8"`. | D5 | JDK: `actions/setup-java` Temurin 17 + `cache: gradle` | Runner mặc định đã là JDK 17 [G5], nhưng khai báo tường minh để tránh đổi ngầm. Cùng action này cache được `~/.gradle/caches` và `~/.gradle/wrapper` [A2], không cần thêm action khác |
| D6 | NDK cài tường minh bằng `sdkmanager` | Ảnh `ubuntu-24.04` chỉ có NDK 27.3/29.0/30.0, **không có 28.2.13676358** [G5]. Nếu để AGP tự tải (như T00) thì tải ngầm trong Gradle, log khó đọc. Trên Linux, `injectGradleWrapperIfNeeded` gọi `makeExecutable` cho file vừa chép [F3], nên không gặp lỗi mất bit `+x` từ Windows. Workflow thêm `test -x android/gradlew` để báo lỗi rõ ràng nếu hành vi này đổi |
| D8 | `flutter pub get --enforce-lockfile` | Bắt CI dùng đúng `pubspec.lock` đã commit (kể cả content-hash); lock lệch thì fail [D1] |
| D9 | Test Dart chạy 2 lần: không `--flavor` (default = dev) và `--flavor prod`, kèm `--dart-define=NAPSTOP_EXPECT_FLAVOR` | Lần chạy dev đồng thời kiểm `default-flavor: dev` trong pubspec. Test thăm dò ở §4 chứng minh flavor thật sự truyền tới Dart (đề xuất X1 trong test report T00) |
| D10 | Build APK 2 flavor + kiểm package id bằng `aapt2 dump packagename` | Chặn hồi quy cấu hình flavor (`app.napstop.dev` / `app.napstop`) [AN1]. Rẻ, khoảng 1 giây |

**Quy trình cập nhật pin** (ghi trong comment đầu file workflow): chọn release, lấy SHA bằng
`git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>' 'refs/tags/<tag>^{}'` (nếu có dòng `^{}`, tức tag
annotated, thì dùng SHA của dòng đó), sửa SHA và comment `# vX.Y.Z`, chạy actionlint, rồi mở PR. Lệnh này chạy được trên
Windows mà không cần `gh`.
Mỗi lần nâng Flutter (task riêng, liên quan T00 R4/R9) phải sửa **cùng lúc** `FLUTTER_VERSION`, `DART_VERSION`,
`ANDROID_NDK_VERSION` trong workflow.

### 3. Nội dung chuẩn `.github/workflows/ci.yml`

Coder chép nguyên văn. Lệch nào cũng phải ghi vào Implementation notes kèm lý do. File dùng LF (đã có `.gitattributes`).

```yaml
# NapStop CI (T01). Spec: docs/specs/T01.md
#
# Every action is pinned to a full commit SHA; the release tag is in the trailing
# comment. To update a pin, resolve the tag with
#   git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>' 'refs/tags/<tag>^{}'
# (use the ^{} line if present), update SHA + comment, then run actionlint.
#
# FLUTTER_VERSION / DART_VERSION / ANDROID_NDK_VERSION must match the dev
# machine (CLAUDE.md). Change them only in a dedicated Flutter upgrade task.
name: CI

on:
  pull_request:
    paths-ignore:
      - 'docs/**'
      - '**.md'
      - '.claude/**'
  push:
    branches: [main]
    paths-ignore:
      - 'docs/**'
      - '**.md'
      - '.claude/**'
  workflow_dispatch:

permissions:
  contents: read

concurrency:
  group: ci-${{ github.event.pull_request.number || github.ref }}
  # Cancel superseded PR runs; never cancel runs on main.
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

env:
  FLUTTER_VERSION: '3.47.8'
  DART_VERSION: '3.13.7'
  # = ndkVersion of Flutter 3.47.8 (flutter_tools gradle_utils.dart); not preinstalled on ubuntu-24.04.
  ANDROID_NDK_VERSION: '28.2.13676358'

defaults:
  run:
    shell: bash
    working-directory: app

jobs:
  dart:
    name: dart
    runs-on: ubuntu-24.04
    timeout-minutes: 15
    steps:
      - name: Checkout
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Set up Flutter
        uses: subosito/flutter-action@1a449444c387b1966244ae4d4f8c696479add0b2 # v2.23.0
        with:
          channel: stable
          flutter-version: ${{ env.FLUTTER_VERSION }}
          cache: true
          pub-cache: true

      - name: Verify Flutter and Dart versions
        run: |
          flutter --version
          flutter --version --machine > "$RUNNER_TEMP/flutter-version.json"
          jq -e --arg f "$FLUTTER_VERSION" --arg d "$DART_VERSION" \
            '.frameworkVersion == $f and .channel == "stable" and (.dartSdkVersion | startswith($d))' \
            "$RUNNER_TEMP/flutter-version.json"

      - name: Install dependencies
        run: flutter pub get --enforce-lockfile

      - name: Check formatting
        run: dart format --output=none --set-exit-if-changed lib test

      - name: Analyze
        run: flutter analyze

      # No --flavor on purpose: this run also proves pubspec default-flavor is dev.
      - name: Test (default flavor = dev)
        run: |
          mkdir -p build/ci
          flutter test --reporter github --file-reporter json:build/ci/test-dev.json \
            --dart-define=NAPSTOP_EXPECT_FLAVOR=dev

      - name: Test (flavor prod)
        run: |
          mkdir -p build/ci
          flutter test --flavor prod --reporter github --file-reporter json:build/ci/test-prod.json \
            --dart-define=NAPSTOP_EXPECT_FLAVOR=prod

      - name: Job summary
        if: always()
        continue-on-error: true
        run: |
          summary="$GITHUB_STEP_SUMMARY"
          printf '%s\n' '### dart' '' '| Check | Result |' '|---|---|' >> "$summary"
          if [[ -s "$RUNNER_TEMP/flutter-version.json" ]]; then
            jq -r '"| Flutter | \(.frameworkVersion) (\(.channel), Dart \(.dartSdkVersion), rev \(.frameworkRevision[0:10])) |"' \
              "$RUNNER_TEMP/flutter-version.json" >> "$summary"
          else
            echo '| Flutter | unknown |' >> "$summary"
          fi
          for flavor in dev prod; do
            file="build/ci/test-$flavor.json"
            if [[ -s "$file" ]]; then
              jq -rs --arg flavor "$flavor" '
                [.[] | select(.type == "testDone" and .hidden == false)] as $done
                | "| Dart tests (\($flavor)) | \($done | map(select(.result == "success" and (.skipped | not))) | length) passed, \($done | map(select(.skipped)) | length) skipped, \($done | map(select(.result != "success")) | length) failed |"' \
                "$file" >> "$summary"
            else
              echo "| Dart tests ($flavor) | not run |" >> "$summary"
            fi
          done

      - name: Upload Dart test results
        if: failure()
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: dart-test-results
          path: app/build/ci/
          if-no-files-found: ignore
          retention-days: 7

  android:
    name: android
    runs-on: ubuntu-24.04
    timeout-minutes: 30
    steps:
      - name: Checkout
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: Set up JDK 17
        uses: actions/setup-java@b843ebf9b913146b38da2eaa7aeddf76074ae1ad # v6.1.0
        with:
          distribution: temurin
          java-version: '17'
          cache: gradle
          cache-dependency-path: |
            app/android/**/*.gradle.kts
            app/android/gradle.properties
            app/android/gradle/wrapper/gradle-wrapper.properties
            app/pubspec.lock

      - name: Set up Flutter
        uses: subosito/flutter-action@1a449444c387b1966244ae4d4f8c696479add0b2 # v2.23.0
        with:
          channel: stable
          flutter-version: ${{ env.FLUTTER_VERSION }}
          cache: true
          pub-cache: true

      - name: Verify Flutter, Dart and Java versions
        run: |
          flutter --version
          flutter --version --machine > "$RUNNER_TEMP/flutter-version.json"
          jq -e --arg f "$FLUTTER_VERSION" --arg d "$DART_VERSION" \
            '.frameworkVersion == $f and .channel == "stable" and (.dartSdkVersion | startswith($d))' \
            "$RUNNER_TEMP/flutter-version.json"
          java -version

      # The project sets -Xmx8G; private-repo runners have 8 GB RAM. User-home
      # gradle.properties overrides the project file.
      - name: Size Gradle for the CI runner
        run: |
          mkdir -p "$HOME/.gradle"
          echo 'org.gradle.jvmargs=-Xmx4g -XX:MaxMetaspaceSize=1g -XX:+HeapDumpOnOutOfMemoryError' \
            >> "$HOME/.gradle/gradle.properties"

      - name: Install Android NDK ${{ env.ANDROID_NDK_VERSION }}
        run: |
          "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --install "ndk;$ANDROID_NDK_VERSION" < /dev/null

      - name: Install dependencies
        run: flutter pub get --enforce-lockfile

      # gradlew is not committed (T00); Flutter injects it and marks it executable.
      - name: Generate Gradle wrapper and local.properties
        run: |
          flutter build apk --config-only
          test -x android/gradlew

      - name: Kotlin unit tests (JVM)
        working-directory: app/android
        run: ./gradlew :app:testDevDebugUnitTest :app:testProdDebugUnitTest

      - name: Build debug APK (default flavor = dev)
        run: flutter build apk --debug

      - name: Build debug APK (flavor prod)
        run: flutter build apk --debug --flavor prod

      - name: Verify APK package names
        run: |
          aapt2="$(find "$ANDROID_HOME/build-tools" -type f -name aapt2 | sort -V | tail -n 1)"
          test -x "$aapt2"
          out="$RUNNER_TEMP/apk.md"
          printf '%s\n' '| APK | Package | Size |' '|---|---|---|' > "$out"
          status=0
          for pair in 'app-dev-debug.apk app.napstop.dev' 'app-prod-debug.apk app.napstop'; do
            read -r name expected <<< "$pair"
            apk="build/app/outputs/flutter-apk/$name"
            if [[ ! -f "$apk" ]]; then
              echo "::error::$apk not found"
              status=1
              continue
            fi
            actual="$("$aapt2" dump packagename "$apk")"
            echo "| $name | $actual | $(du -h "$apk" | cut -f1) |" >> "$out"
            if [[ "$actual" != "$expected" ]]; then
              echo "::error::$name has package '$actual', expected '$expected'"
              status=1
            fi
          done
          exit "$status"

      - name: Job summary
        if: always()
        continue-on-error: true
        run: |
          summary="$GITHUB_STEP_SUMMARY"
          printf '%s\n' '### android' '' >> "$summary"
          if [[ -s "$RUNNER_TEMP/flutter-version.json" ]]; then
            jq -r '"- Flutter \(.frameworkVersion) (Dart \(.dartSdkVersion))"' "$RUNNER_TEMP/flutter-version.json" >> "$summary"
          fi
          echo "- JDK: $(java -version 2>&1 | head -n 1)" >> "$summary"
          echo >> "$summary"
          python3 - >> "$summary" <<'PY'
          import glob
          import xml.etree.ElementTree as ET

          print("| Kotlin task | Tests | Failures | Errors | Skipped |")
          print("|---|---|---|---|---|")
          for task in ("testDevDebugUnitTest", "testProdDebugUnitTest"):
              files = sorted(glob.glob(f"build/app/test-results/{task}/TEST-*.xml"))
              if not files:
                  print(f"| {task} | not run | | | |")
                  continue
              totals = [0, 0, 0, 0]
              for path in files:
                  root = ET.parse(path).getroot()
                  for i, key in enumerate(("tests", "failures", "errors", "skipped")):
                      totals[i] += int(root.get(key, "0"))
              print(f"| {task} | " + " | ".join(str(n) for n in totals) + " |")
          PY
          if [[ -s "$RUNNER_TEMP/apk.md" ]]; then
            echo >> "$summary"
            cat "$RUNNER_TEMP/apk.md" >> "$summary"
          fi

      - name: Upload Android test reports
        if: failure()
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: android-test-reports
          path: |
            app/build/app/reports/tests/
            app/build/app/test-results/
          if-no-files-found: ignore
          retention-days: 7
```

Ghi chú cho coder và reviewer:
- `defaults.run.shell: bash` là **bắt buộc**. Khi khai báo tường minh, GitHub chạy `bash --noprofile --norc -eo pipefail {0}`.
  Nếu bỏ trống thì chỉ là `bash -e {0}`, không có `pipefail` [G1].
- **Không** dùng `yes | sdkmanager …`: `yes` nhận SIGPIPE, `pipefail` làm step fail với mã 141. Ảnh runner đã chấp nhận
  license SDK lúc cài (`echo "y" | $SDKMANAGER …`) [G8], nên stdin `/dev/null` là đủ. Nếu step vẫn dừng ở prompt license,
  xem R3.
- `continue-on-error: true` **chỉ** được dùng ở 2 step "Job summary". Các step còn lại phải để lỗi làm hỏng job.
- Đường dẫn trong `uses:` (`path:` của upload-artifact) tính từ `$GITHUB_WORKSPACE`, không bị `working-directory` tác động.
  Vì vậy phải có tiền tố `app/`.
- Gradle của Flutter đổi build dir về `app/build/<module>` (`android/build.gradle.kts`), nên test result Kotlin nằm ở
  `app/build/app/test-results/<task>/TEST-*.xml`. Đã đối chiếu với file T00 sinh ra trên máy dev.
- Flutter tool tự nhận ra môi trường CI (biến `GITHUB_ACTIONS`, `CI`) và tắt analytics cùng banner lần đầu [F4], nên
  output `--machine` là JSON sạch. Gọi `flutter --version` trước để mọi việc khởi tạo lần đầu xong trước khi chạy lệnh có `--machine`.
- `flutter analyze` mặc định `--fatal-infos` và `--fatal-warnings` [F5], nên lint info của VGA cũng làm fail.
- Reporter `github` có sẵn trong `flutter test` 3.47.8 [F6]. Field `testDone.result/skipped/hidden` lấy theo giao thức JSON reporter [D2].
- Gradle in cảnh báo deprecation `android.builtInKotlin`/`android.newDsl` (T00 R9). Đây là cảnh báo đã biết, không phải lỗi CI.

### 4. Test thăm dò flavor (sửa `app/test/app/flavor_test.dart`)

Thêm một `group` mới sau group `AppFlavor.parse` hiện có. Giữ nguyên 6 test cũ.

```dart
/// Set by CI: `flutter test [--flavor prod] --dart-define=NAPSTOP_EXPECT_FLAVOR=<dev|prod>`.
/// Empty when running plain `flutter test` locally, so the check is skipped.
const String _expectedFlavor = String.fromEnvironment('NAPSTOP_EXPECT_FLAVOR');

// inside main(), after group('AppFlavor.parse', ...):
group('AppFlavor.current', () {
  test(
    'matches the --flavor of this test run',
    () => expect(AppFlavor.current.name, _expectedFlavor),
    skip: _expectedFlavor.isEmpty ? 'NAPSTOP_EXPECT_FLAVOR is not set' : null,
  );
});
```

  Chạy `flutter test` thường ở máy thì test này bị skip (`+8 ~1`), không làm phiền dev.
- Tổng số test của mỗi lần chạy trong CI: **9 passed, 0 skipped, 0 failed** (6 parse + 2 widget + 1 thăm dò).

## Câu hỏi mở

Không câu nào chặn coding. Cả ba đã có phương án mặc định.

1. **Repo `Ryo51289/gps-alarm` là private hay public?** (Truy cập ẩn danh trả 404, nên đoán là private.) Câu trả lời ảnh
   hưởng quota phút và cấu hình runner, không ảnh hưởng thiết kế. **Mặc định:** coi là private, thiết kế như trên.
2. **Cách đọc kết quả CI:** (a) người dùng đọc web và dán Summary (mặc định cho T01, việc một lần); (b) người dùng tạo
   fine-grained PAT **chỉ đọc** (repo này; quyền Actions: Read, Metadata: Read), đặt vào biến môi trường cục bộ (không ghi
   vào repo), để agent dùng `curl` gọi REST API đọc trạng thái và log; (c) cài `gh` (`winget install GitHub.cli`) rồi đăng nhập.
   **Đề xuất:** (a) cho T01; cân nhắc (b) hoặc (c) trước Phase 2, khi CI chạy thường xuyên.
3. **Branch protection cho `main`:** **đề xuất không bật** trong MVP 1. Luồng hiện tại là orchestrator commit cục bộ rồi push
   thẳng `main`; "required status checks" sẽ chặn hoặc làm phức tạp luồng này, và có thể không có cho repo private trên gói
   Free. Xem lại khi có thêm người hoặc khi chuyển sang luồng PR.

Việc người dùng cần làm (không phải câu hỏi thiết kế, theo §6): duyệt push `main` (nếu remote đang sau) và `t01-ci`; mở PR
qua link; báo trạng thái và Summary của run; tuỳ chọn re-run (TC13) và PR âm (TC14); duyệt xoá nhánh remote sau khi xong.
Nếu Actions đang tắt hoặc chỉ cho phép action của GitHub: vào Settings → Actions → General, chọn cho phép action bên thứ ba
(cần cho `subosito/flutter-action`).
