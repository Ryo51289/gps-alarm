### 4. Công thức `expectFallback` (T10 §8.3, D4; thay T11 §5.3 và README §3.1; toàn số nguyên, `~/` chia nguyên, đối số ≥ 0)

```
killT     = config.kill.t;   asOfT = killT − I              -- sT của T10 §8.3 chính là asOfT
modeAtT   = resolveAnchor(modeAt) + modeAt.offsetS           -- như cũ
early     = min(3600, max(0, modeAtT − killT − 600) ~/ 4)    -- fallbackEarlyMaxS 3600, fallbackEarlyFrac 1/4, fallbackNearS 600
estimateT = modeAtT + 30 − early                             -- fallbackLagS 30
hintKmh   = {train: 55, coach: 60, bus: 20, unknown: 60}[config.vehicleHint ?? trace.vehicle]
asOfStraightM = floor(truth.straightM[asOfT ~/ I])           -- vị trí THẬT (không nhiễu), đích hiệu dụng, cùng mảng với mốc straight<=X
hT        = distance: (max(0, asOfStraightM − thresholdM) · 432) ~/ (100 · hintKmh)
            time:     max(0, (asOfStraightM · 432) ~/ (100 · hintKmh) + 20 − 60 · thresholdMin)
            smart:    max(0, (asOfStraightM · 432) ~/ (100 · hintKmh) + 20 − 600)
hintEstimateT = asOfT + max(600, hT + 30 − min(3600, max(0, hT − 600) ~/ 4))
notBefore = clamp(min(estimateT, hintEstimateT) + toleranceS[0], 0, durationS)
notAfter  = clamp(estimateT + toleranceS[1], 0, durationS)
```
- Hằng: `432 = 100 · 3,6 · routeFactorPrior (1,2) / fallbackHintSpeedFactor (1,0)`; `20` = `etaStopPenaltyS`; `600` (smart) =
  `smartTargetS`; `600` (sàn, `hT − 600`) = `fallbackNearS`. Đặt thành hằng có tên trong `generator.dart` (cạnh `kFallbackLagS`…):
  `kFallbackEarlyMaxS = 3600`, `kFallbackEarlyDivisor = 4`, `kFallbackHintNumerator = 432`, `kEtaStopPenaltyS = 20`, `kSmartTargetS = 600`,
  `kExpectedSpeedKmh = {train: 55, coach: 60, bus: 20, unknown: 60}`.
- Chỉ số mảng: `truth.straightM[j]` là tick `j·I` (`states[j].t == asOfT`, assert). `asOfT` nằm trong gap vẫn có giá trị (truth chuyển
  động không phụ thuộc gap).
- Hàm thuần dùng chung (generator và `validate` cùng gọi; oracle test viết lại độc lập):
  ```dart
  ({int estimateT, int hintEstimateT, int notBefore, int notAfter}) fallbackEstimates({
    required CaseMode mode, required int? threshold, required String hint,  // threshold: thresholdM | thresholdMin | null (smart)
    required int modeAtT, required int killT, required int asOfStraightM,
    required int sampleIntervalS, required int durationS,
    required int toleranceLo, required int toleranceHi,
  });
  ```
  `fallbackWindow(...)` (generator) thêm tham số `mode`, `threshold`, `hint`, `asOfStraightM`; `ResolvedFallback` thêm `asOfStraightM`,
  `hintEstimateT`. `resolveCase` lấy `hint` = `spec.vehicleHint ?? profile.vehicle.name`, `asOfStraightM` từ `truth.straightM`.
- `validate` không có vị trí thật, nên kiểm `asOfStraightM` là int ≥ 0 rồi **tính lại** `estimateT`, `hintEstimateT`, `notBefore`,
  `notAfter` chỉ từ đầu vào (`modeAtT`, `killT` của `window`, `asOfStraightM`, `toleranceS`, `config.mode`/ngưỡng/`vehicleHint`,
  `trace.vehicle`, `durationS`; thêm `vehicle` vào `_CaseEnv`) và so **từng** trường của fixture với giá trị tính lại (không dùng giá trị
  fixture của trường này để kiểm trường kia). Đầu vào thiếu hoặc sai kiểu thì bỏ qua phép tính lại (chỉ báo lỗi đầu vào). Tính đúng của
  `asOfStraightM` do `check` (so byte) và oracle TG50 bảo đảm.

**Ví dụ tính (số `sM` lấy từ điểm GPX có nhiễu ở `asOfT`, theo test report T10.1-T10.2 nit 1; generator dùng truth không nhiễu nên
