# T23.7 — Bug: đổi địa chỉ ô "Công ty" không được lưu sau khi quay lại

Trạng thái đề xuất: **spec-ready**

## Bối cảnh & mục tiêu

- PO báo 12/11/2026 (iPhone, IPA `b50a2ba`): đổi địa chỉ ô "Công ty" (địa chỉ Apple, T23.5), quay lại → ô giữ địa chỉ cũ.
- Điều tra (vòng 1, xem §Phụ lục A): tầng lưu trữ và luồng "Chọn …" đúng; lỗi khớp **H1** — nhấn giữ ô → "Đổi địa điểm" →
  màn 2 `mode=pick` → chạm gợi ý/ga (nút sáng lên "Chọn <tên>") → Back (mũi tên hoặc vuốt cạnh iOS) mà **không** bấm "Chọn …"
  → picker trả `null`, ô không đổi. Theo T23 (dòng "Back": `mode=pick` trả `null`, không lưu) đây là đúng spec, nhưng người dùng
  hiểu "chạm gợi ý = đã chọn xong".
- **PO xác nhận 12/11/2026: lỗi là H1.** PO chốt cách sửa (không mở lại):
  1. Ở `mode=pick` khi chọn cho một ô đã lưu, nút xác nhận đổi nhãn thành **"Lưu vào <tên ô>"** (Nhà / Quê / Công ty).
     Nơi khác dùng màn 2 giữ nhãn hiện tại.
  2. Có lựa chọn đang chờ (nút đã sáng) mà người dùng Back → hỏi **"Lưu vào Công ty?"** với "Lưu" / "Bỏ"; đóng hộp thoại = ở lại
     màn 2. "Lưu" = như bấm nút xác nhận; "Bỏ" = thoát, trả `null`. Không có lựa chọn → Back như hiện nay, không hỏi.
- H2 (đổi đích từ màn 3 không ghi vào ô) **giữ nguyên** theo T25; ngoài phạm vi.

## Thiết kế

### 1. Thành phần & luồng

```
HomeScreen._pickInto(slot)
  └─ ref.read(destinationPickerProvider)(context, slot)          // đổi chữ ký: thêm slot
       └─ context.pickDestination(slot: slot)
            └─ push<TripDestination>('/destination?mode=pick&slot=<slot.name>')
                 └─ app_router: DestinationScreen(pickMode: true, pickSlot: slot)
                      ├─ nút xác nhận: "Lưu vào <ô>" → _confirm() → context.pop(destination)
                      └─ PopScope(canPop: !_guardLeave, onPopInvokedWithResult: …)
                           Back khi _guardLeave → _askLeave() → hộp thoại
                              Lưu → _confirm()   | Bỏ → context.pop()  | đóng → ở lại
  ◀─ destination (hoặc null) → HomeScreen upsert(slot, destination) như hiện nay
```

Ghi DB vẫn chỉ ở `HomeScreen._pickInto` (không thêm đường ghi mới). "Lưu" trong hộp thoại đi đúng đường của nút xác nhận.

### 2. Route & interface

`app/lib/app/router/app_routes.dart`
```dart
/// Query key of `/destination?mode=pick` naming the saved place slot the
/// pick goes into (T23.7). Value: `SavedPlaceSlot.name`.
const String kDestinationSlotParam = 'slot';

abstract final class AppRoutes {
  // destinationPick giữ nguyên '/destination?mode=pick' (router_test khẳng định).
  /// Screen 2 as a picker for [slot] (T23.7).
  static String destinationPickFor(SavedPlaceSlot slot) =>
      '$destinationPick&$kDestinationSlotParam=${slot.name}';
}

extension AppNavigation on BuildContext {
  /// Screen 2 as a picker; null when the user backs out. With [slot], the
  /// confirm button reads "Lưu vào <slot>" and Back with a pending choice
  /// asks first (T23.7).
  Future<TripDestination?> pickDestination({SavedPlaceSlot? slot}) =>
      push<TripDestination>(
        slot == null ? AppRoutes.destinationPick : AppRoutes.destinationPickFor(slot),
      );
}

/// Opens screen 2 as a picker for [slot]. A seam for widget tests.
typedef DestinationPicker = Future<TripDestination?> Function(
  BuildContext context,
  SavedPlaceSlot slot,
);

final destinationPickerProvider = Provider<DestinationPicker>(
  (ref) => (context, slot) => context.pickDestination(slot: slot),
);
```
Thay đổi chữ ký `DestinationPicker` là nội bộ; các override trong test cập nhật `(_) async` → `(_, _) async` (4 chỗ trong
`home_screen_test.dart`).

`app/lib/app/router/app_router.dart` — route `/destination`:

### 4. Chặn Back

Trạng thái chặn (tính trong `build`):
```dart
final guardLeave = widget.pickSlot != null && selection != null && !_navigating;
```

```dart
return PopScope<Object?>(
  canPop: !guardLeave,
  onPopInvokedWithResult: (didPop, _) {
    if (didPop) {
      _controller.cancelPending();   // như hiện nay (T23 B1)
      return;
    }
    unawaited(_askLeave());           // chỉ tới đây khi guardLeave
  },
  child: scaffold,
);
```

Mũi tên Back trên thanh trên **phải** đi qua PopScope: đổi `onPressed: () => context.pop()` thành
`onPressed: () => unawaited(Navigator.maybePop(context))`. (`context.pop()`/`Navigator.pop` bỏ qua `canPop`; `maybePop` tôn trọng
nó và gọi `onPopInvokedWithResult(didPop: false)` — xem tài liệu PopScope.) Ở chế độ thường và khi không chặn, `maybePop`
pop y như trước (kết quả `null`).

```dart
bool _asking = false;

Future<void> _askLeave() async {
  final slot = widget.pickSlot;
  final selection = ref.read(_provider).selection;
  if (_asking || slot == null || selection == null || _navigating) return;
  _asking = true;
  _focus.unfocus();
  final choice = await showLeaveSaveDialog(            // widgets/leave_save_dialog.dart
    context,
    slotLabel: AppLocalizations.of(context).savedSlotLabel(slot),
    destinationName: selection.destination.name,
  );
  _asking = false;
  if (!mounted) return;
  switch (choice) {
    case LeaveSaveChoice.save:
      _confirm();                     // giữ nguyên: kiểm isValid, cancelPending, _navigating, context.pop(destination)
    case LeaveSaveChoice.discard:
      _controller.cancelPending();
      _navigating = true;             // canPop thành true ở frame sau; pop trực tiếp không phụ thuộc
      context.pop();                  // trả null, bỏ qua PopScope
    case null:
      break;                          // đóng hộp thoại = ở lại, giữ lựa chọn
  }
}
```

Ghi chú hành vi theo từng thao tác Back khi `guardLeave == true`:

| Thao tác | Kết quả |
|---|---|
| Mũi tên "Quay lại" (Android/iOS) | `maybePop` → bị chặn → hộp thoại |
| Android system back / predictive back | bị chặn (không có animation predictive), `didPop=false` → hộp thoại |
| **iOS vuốt cạnh trái** | **Flutter tắt hẳn cử chỉ** khi `canPop=false` (`ModalRoute.popGestureEnabled` trả `false` khi `popDisposition == doNotPop`; tài liệu PopScope: "no gesture will be detected at all, so onPopInvokedWithResult will not be called"). Vuốt không làm gì, người dùng ở lại màn 2 với lựa chọn còn nguyên; muốn thoát thì bấm mũi tên (→ hộp thoại) hoặc "Lưu vào …". **Không mất lựa chọn âm thầm nữa** — đúng mục tiêu của PO, nhưng hộp thoại không bật bằng vuốt (giới hạn nền tảng, xem R1). |

Khi `guardLeave == false` (không ô, chưa chọn, hoặc đang điều hướng): mọi Back như hiện nay, kể cả vuốt cạnh iOS.

Các lối ra không phải "pop" (alarm fallback `/alarm` push lên trên, `go` sang màn 4/8 từ coordinator) **không** bị PopScope chặn
và không hỏi — giữ hành vi T27 hiện có.

Lựa chọn đang giải mã địa chỉ (resolve chưa xong) chưa phải `selection`; nếu trước đó đã có lựa chọn khác, hộp thoại hỏi lưu
lựa chọn **đang hiển thị** (tên ở thân hộp thoại) — chấp nhận.

### 7. A11y

- Nút "Lưu" / "Bỏ": `NapButtonSize.medium` (touch ≥ 48 px theo T20); hộp thoại chạy `androidTapTargetGuideline`,
  `labeledTapTargetGuideline`, `textContrastGuideline` ở light + dark.

  giữa Android/iOS) để "Lưu vào Công ty?" được đọc khi mở; focus vào hộp thoại.
