# T21 — Màn 0 Cấp quyền + Màn 9 Hướng dẫn pin theo hãng (nhận diện hãng máy)

Trạng thái đề xuất: **spec-ready** (2 câu hỏi mở, cả hai **không chặn**; coder làm theo phương án mặc định)

Ngày kiểm tra nguồn: 2026-11-03. Wireframe đọc từ bản tải về của canvas (`Onboarding.dc.html` = màn 0, `HuongDanPin.dc.html` = màn 9,

## Bối cảnh & mục tiêu

- PRD §3 màn 0: vị trí "Khi dùng ứng dụng" + "Chính xác" (Android **không** xin vị trí nền, ADR-001); thông báo; Android: báo thức toàn
  màn hình, báo thức chính xác (chỉ khi máy chưa cấp), hướng dẫn tắt tối ưu pin theo hãng; iOS 26+: AlarmKit. PRD §3.1: mức bắt buộc; mỗi
  quyền có màn giải thích ngắn trước hộp thoại hệ thống; bị từ chối thì có nút "Mở Cài đặt".
- PRD §3 màn 9: theo hãng (Xiaomi, Samsung, Oppo, Vivo); 3 bước + chạy thử 30 giây. Wireframe n9: "tự nhận hãng máy, từng bước có ảnh, nút
  kiểm tra chạy thử app ngầm 30 giây để xác nhận".
- ARCHITECTURE §7.1/§7.2 là nguồn chuẩn cho quyền, cách đọc trạng thái và trang cài đặt. §7.3: quy tắc bắt đầu chuyến là hàm Dart thuần

- TASKS T21 (việc mang sang): `PermissionHostApi` Android **thật** thay stub T14; bọc lỗi để `wrapError` không gửi stack trace (T14 F3);
  `DeviceStatusReader` inject được nguồn để test JVM (T14.1 O2); native không trả `precise = notApplicable` trên Android (review T22 #9);
  test report T22 O6: thẻ "Sẵn sàng" xanh khi `deviceStatus()` lỗi, và DND "Ưu tiên" trên API 26–29 không cảnh báo — T21 chốt cách đọc và

```dart
/// T21: screen 9 background check (Android). Times are epoch ms
/// (System.currentTimeMillis). No coordinates.
class BackgroundCheckMsg {
  BackgroundCheckMsg({
    required this.scheduledAtMs,
    required this.dueAtMs,
    this.firedAtMs,
    this.screenOnAtFire,
    required this.exact,
  });

  int scheduledAtMs; // when startBackgroundCheck ran
  int dueAtMs; // scheduledAtMs + delayMs
  int? firedAtMs; // when the receiver ran; null = not yet
  bool? screenOnAtFire; // PowerManager.isInteractive() at fire time
  bool exact; // true: setExactAndAllowWhileIdle; false: setAndAllowWhileIdle
}

@HostApi()
abstract class PermissionHostApi {
  /// T21: @async (native reads stored flags off the main thread; iOS reads
  /// notification settings asynchronously). Dart signature unchanged.
  @async
  PermissionStatusMsg status();

  // request, openSettings, deviceInfo, deviceStatus, mapsConfig,
  // distancesFromLastKnownM: unchanged, same order.

  /// T21: schedules the screen 9 check alarm in [delayMs] (5000..120000),
  /// replacing any previous check. Errors: invalid-config
  /// ("delayMs: out of range"). iOS: internal ("unsupported").
  @async
  BackgroundCheckMsg startBackgroundCheck(int delayMs);

  /// T21: the latest check (survives process death), or null.
  @async
  BackgroundCheckMsg? backgroundCheck();

  /// T21: cancels the alarm and forgets the record. No-op when none.
  @async
  void cancelBackgroundCheck();
}
```

### 4. Android — trạng thái quyền

#### 4.1 Nguồn và ảnh chụp trạng thái (Kotlin)

```kotlin
package app.napstop.core.bridge.permission

/** Everything status() needs, read once. Pure data: JVM-testable. */
data class PermissionSnapshot(
    val sdkInt: Int,
    val fine: Boolean,
    val coarse: Boolean,
    val locationRequested: Boolean,          // PermissionFlags
    val locationRationale: Boolean?,         // rationale(FINE) || rationale(COARSE); null = no activity
    val preciseUpgradeAttempts: Int,         // PermissionFlags
    val locationEnabled: Boolean,
    val postNotificationsGranted: Boolean,   // checkSelfPermission(POST_NOTIFICATIONS); false below 33
    val notificationsEnabled: Boolean,       // NotificationManager.areNotificationsEnabled() (API 24+)
    val notificationsRequested: Boolean,     // PermissionFlags
    val notificationsRationale: Boolean?,    // rationale(POST_NOTIFICATIONS); null = no activity or < 33
    val canUseFullScreenIntent: Boolean?,    // null: sdk < 34 or unreadable
    val canScheduleExactAlarms: Boolean?,    // null: sdk < 31 or unreadable
    val ignoringBatteryOptimizations: Boolean?, // null: unreadable
)

/** Platform reads. Every call may throw; the impl catches per item. */
interface PermissionSources {
    val sdkInt: Int
    fun isGranted(permission: String): Boolean          // Context.checkSelfPermission
    fun rationale(permission: String): Boolean?          // activity?.shouldShowRequestPermissionRationale; main thread
    fun locationEnabled(): Boolean                       // API 28+ isLocationEnabled; else GPS || NETWORK provider enabled
    fun notificationsEnabled(): Boolean
    fun canUseFullScreenIntent(): Boolean                // only called when sdk >= 34
    fun canScheduleExactAlarms(): Boolean                // only called when sdk >= 31
    fun ignoringBatteryOptimizations(): Boolean          // PowerManager.isIgnoringBatteryOptimizations(packageName)
}

/** Small persistent flags, SharedPreferences "napstop_permissions". Reads/writes on [io]. */
interface PermissionFlags {
    suspend fun read(): Flags
    suspend fun markLocationRequested()
    suspend fun markNotificationsRequested()
    suspend fun countPreciseAttempt()
    suspend fun resetPreciseAttempts()
    data class Flags(val locationRequested: Boolean, val notificationsRequested: Boolean, val preciseUpgradeAttempts: Int)
}
```

Lỗi khi đọc **từng mục** (bắt riêng, `warn("permission <item>: <Class>")`, không ném):
- Mục **chặn chuyến** (`locationEnabled`): lỗi → `true`. Lý do: báo sai "định vị tắt" sẽ chặn người dùng vì một lỗi đọc; `startTrip`
  (T15) kiểm lại ở native và trả `permission-missing` nếu thật sự tắt.
- Mục **cảnh báo** (`canUseFullScreenIntent`, `canScheduleExactAlarms`, `ignoringBatteryOptimizations`, `notificationsEnabled`): lỗi →
  `null`/`false` → trạng thái `denied` (thà cảnh báo thừa).
- `checkSelfPermission` không ném theo tài liệu; vẫn bọc.
- `PermissionFlags.read()` lỗi → `Flags(false, false, 0)`.

#### 4.2 Ánh xạ thuần `PermissionMapping.status(s: PermissionSnapshot): PermissionStatusMsg`

```
promptable(requested, rationale) = !requested || rationale == true

location   = (fine || coarse) ? WHILE_IN_USE
           : promptable(locationRequested, locationRationale) ? NOT_DETERMINED : DENIED
precise    = fine ? GRANTED
           : coarse ? (sdkInt >= 31 && preciseUpgradeAttempts == 0 ? NOT_DETERMINED : DENIED)
           : NOT_DETERMINED                                  -- chưa có vị trí: checkStart bỏ qua precise
locationServicesEnabled = locationEnabled
notifications = notificationsEnabled ? GRANTED
           : (sdkInt >= 33 && !postNotificationsGranted && promptable(notificationsRequested, notificationsRationale))
             ? NOT_DETERMINED : DENIED                       -- < 33 hoặc đã cấp quyền mà người dùng tắt: chỉ còn Cài đặt
fullScreenIntent = sdkInt < 34 ? GRANTED : (canUseFullScreenIntent == true ? GRANTED : DENIED)
exactAlarm       = sdkInt < 31 ? GRANTED : (canScheduleExactAlarms == true ? GRANTED : DENIED)
batteryOptimizationIgnored = ignoringBatteryOptimizations == true ? GRANTED : DENIED
alarmKit   = NOT_APPLICABLE
```
Bất biến (test K01, quét mọi tổ hợp): `precise != NOT_APPLICABLE`; `location != ALWAYS`; `alarmKit == NOT_APPLICABLE`; chỉ `alarmKit`
được là `NOT_APPLICABLE`.

Ghi chú:
- API 26–30: hệ thống cấp FINE và COARSE cùng nhóm, nên "chỉ COARSE" gần như không xảy ra; nếu có thì `precise = denied`.
- API 31+: hộp thoại có "Chính xác/Gần đúng" và "Khi dùng ứng dụng/Chỉ lần này/Từ chối" [A-RT]. Không có API phân biệt "Chỉ lần này" (T19
  §1.1); màn giải thích có câu `permLocationHint`.

```
m == null || nowMs - m.scheduledAtMs > kStale          → null
m.firedAtMs != null:
    lateBy = firedAtMs - dueAtMs
    lateBy > kLate                                       → late(lateBy)
    m.screenOnAtFire == true                             → passedScreenOn
    else                                                 → passed           (bắn trước giờ do đổi đồng hồ: vẫn passed)
m.firedAtMs == null:
    nowMs < dueAtMs + kGiveUp                            → running(remaining = max(0, dueAtMs - nowMs))
    else                                                 → missed
```
Không có tham số Remote Config (hằng số cố định của màn chẩn đoán).

#### 7.4 Controller và vòng đời

```dart
/// State of screen 0. autoDispose: a new visit starts with an empty sticky set.
final onboardingControllerProvider = AsyncNotifierProvider.autoDispose<OnboardingController, OnboardingState>(OnboardingController.new);

@immutable final class OnboardingState {
  const new({required this.status, required this.device, required this.items, required this.check, required this.busy});
  final PermissionStatusMsg status; final DeviceInfoMsg device;
  final List<OnboardingItem> items; final StartCheck check;
  final bool busy;                                  // a request/openSettings is running: every action button disabled
}

final class OnboardingController extends AsyncNotifier<OnboardingState> {
  Future<void> refresh();                           // permissionStatus() again (resume, retry)
  Future<OnboardingOutcome> act(OnboardingItem item); // runs item.request or item.settings (after the sheet, in the widget)
}
enum OnboardingOutcome { done, settingsUnavailable, requestFailed, ignored }
```

  Mở được thì chờ resume (`AppLifecycleListener`) để `refresh`. `busy = false` trong `finally`.

### 11. Telemetry (T29 chưa code)

  backgroundCheckTelemetryResult(v)` (null thì không gửi) hoặc `cancelled`.

### 12. Thay đổi `evaluateReadiness` (T22 §8.3) — O6

Chữ ký không đổi. Thêm `ReadinessChipKind.deviceStatusUnknown`, `ReadinessChipKind.dndCheckAlarms` (**cuối** enum); `readinessChip` trong
`home_strings.dart` thêm 2 `case`.
```
android = device.platform == android
5. âm lượng:
   android && status == null                                            → deviceStatusUnknown(caution)
   status != null: như cũ (muted/0 → alarmMuted; < 30 → alarmVolumeLow; còn lại alarmVolume) khi có số hoặc muted
                   android && alarmVolumePct == null && alarmMuted != true → deviceStatusUnknown(caution)
6. Không làm phiền (status != null):
   filter == none || (priority && priorityAllowsAlarms == false)         → dndBlocksAlarms(warning)        (như cũ)
   priority && priorityAllowsAlarms == null && alarmMuted != true        → dndCheckAlarms(caution)          (API 26–29, hoặc đọc lỗi)
   android && filter == unknown && chưa có deviceStatusUnknown           → deviceStatusUnknown(caution)
iOS: không đổi (status null hoặc thiếu trường → không chip).
level/action: quy tắc cũ (caution → check; action không đổi — app không sửa được âm lượng/DND).
```
`readinessProvider`: sửa doc comment ("deviceStatus() lỗi → chip 'Chưa kiểm tra được âm báo'"). Không đổi luồng gọi.

### 13. Pin, quyền riêng tư, a11y

- **Pin:** màn 0, 9 không có việc nền. Phép thử: 1 exact alarm + 1 lần rung ~1 s, chỉ khi người dùng bấm. `status()` đọc vài system service
  rẻ, chỉ lúc mở màn và resume.
- **Quyền riêng tư:** không đọc/gửi vị trí ở T21 (ngoài `distancesFromLastKnownM` có sẵn). Log Kotlin chỉ có tên mục + tên lớp exception.
  Không log `DeviceInfoMsg` (có `model`). SharedPreferences `napstop_permissions` loại khỏi sao lưu và chuyển máy (`backup_rules.xml`,
  `data_extraction_rules.xml`: `<exclude domain="sharedpref" path="napstop_permissions.xml"/>`), vì khôi phục cờ "đã xin" sang máy mới sẽ
  làm dòng quyền báo sai `denied`.
- **a11y:** vùng chạm ≥ 48 (T20); mọi nút có nhãn đầy đủ (§7.2); tiêu đề màn và tiêu đề bước là header; thanh tiến độ và minh hoạ
  `ExcludeSemantics`; banner kết quả là live region, đếm ngược thì không; cỡ chữ 2.0 không tràn (cuộn được, nút chuyển xuống dòng, ẩn minh
  hoạ); tương phản theo token T20 (chữ `success` trên `surface`, `danger` cho phụ đề chặn); `NapMotion` cho animation.
- **Copy:** tiếng Việt có dấu, câu ngắn; thuật ngữ trùng T19/PRD: "Khi dùng ứng dụng", "Chính xác", "Báo thức toàn màn hình", "Báo thức
  chính xác", "Không làm phiền".

## Câu hỏi cho designer

**CQ1 — Màn 0 có thể bị bỏ qua ở lần chạy đầu khi đọc cờ chậm (§6.5, D10, R10).** `main()` đợi `isOnboardingCompleted` tối đa

cho quyền") nhưng treo → Trang chủ. Đề xuất (chọn một): (a) `onTimeout: () => false` (treo → màn 0; người đã xong chỉ thấy màn 0
