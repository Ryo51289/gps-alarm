# T23.8 — Tuyến đi làm: tự bật theo dõi khi tới điểm cố định trong khung giờ (iOS trước)

Trạng thái đề xuất: **spec-ready** cho bản sửa C1 (Q1–Q8 đã chốt 13/11/2026, §13). D12 viết lại, thêm D12b, D17, D18 và sửa D6 sau
review C1 vòng 1 (`docs/reviews/T23.8-C1.md` #1–#3) — việc coder phải làm: mục "Sửa spec sau review C1 vòng 1" cuối file. C2–C6 vẫn chờ
B0 = Go.

ADR: `docs/architecture/adr/003-commute-auto-start-always-location.md`. Spike: `docs/spikes/T23.8.md`.

## 1. Bối cảnh & mục tiêu

- PO 13/11/2026: người dùng khai một tuyến cố định A→B. Tới A trong khung giờ sáng (vd 07:00–08:00) thì app **tự** theo dõi tới B;
  tới B trong khung giờ chiều (vd 17:30–19:30) thì tự theo dõi về A. Báo thức khi gần tới như chuyến thường (PRD §4). Đã chốt: tự bật
  hoàn toàn (không chỉ nhắc), chấp nhận xin "Luôn cho phép", làm trước T23.6 B1, iOS trước.
- Hiện tại chuyến chỉ bắt đầu khi bấm "Bắt đầu theo dõi" lúc app mở (PRD §4 "Theo dõi chuyến"; T17 D8, D10). iOS chạy với When In
  Use (PRD §3.1); "Luôn cho phép" chỉ đề nghị "khi có tính năng dùng tới" — tuyến đi làm là tính năng đó.
- Trip Engine (`Trip`, T10/T13) **không đổi**. Thay đổi nằm ở lớp runtime/nền tảng và Flutter.
- Ràng buộc: không backend; vị trí không rời máy; không có Mac (WSL `swift test`, typecheck xtool, CI macOS, iPhone 16 Plus của PO
  iOS 27).

## 2. Phạm vi

   (tạm dừng); trạng thái sẵn sàng + cảnh báo. Lối vào: thẻ trên màn 1, dòng trên màn 12.

3. drift v2: bảng `commute_routes` + migration v1→v2.
4. Pigeon: `CommuteHostApi` (mới), `PermissionKindMsg.locationAlways` (thêm cuối), `DestinationSource.commute` phía Dart.
5. Native iOS: theo dõi 2 vùng A/B; bộ quyết định thuần (khung giờ, ngày, một lần/chiều/ngày, chống lặp); bắt đầu chuyến từ nền;

7. Spike B0, test thuần Swift + Dart, trace mới qua `tools/tracegen`, giao thức máy.

Luồng tự bật:
```
iOS khởi chạy app ở nền (vùng A) → didFinishLaunching → CommuteHost.bootstrap (đồng bộ: tạo lại CLServiceSession nếu tuyến bật;
  Task: tạo lại monitor "napstop.commute", lặp events) → sự kiện (id "nc.r<rev>.A", satisfied, date)
→ CommuteController.onRegionEvent: bg = bgTasks.begin("commute")
   decision = CommuteTriggerEvaluator.evaluate(...)  -- thuần
   .start(dir) → meta = template(dir) với tripId UUID mới → runtime.start(meta, B.lat, B.lng, origin: .commute(dir, rev))

```

### 5.2 Kiểu dữ liệu thuần (`Sources/TripRuntime/Commute/`)

```swift
public enum CommuteDirection: String, Codable, Sendable { case towardB, towardA }   // towardB: trigger = enter A
public enum CommutePoint: String, Codable, Sendable { case a = "A", b = "B" }

public struct CommuteWindow: Codable, Sendable, Equatable {
    public let enabled: Bool
    public let startMinute: Int     // 0...1439, local
    public let endMinute: Int       // exclusive, startMinute < endMinute ≤ 1440
    public let weekdayMask: Int     // bit0 = Monday … bit6 = Sunday, 1...127
}

/// Has coordinates: description redacted, never logged (T10 §10).
public struct CommuteRoute: Codable, Sendable, Equatable, CustomStringConvertible {
    public let revision: Int
    public let enabled: Bool
    public let nameA: String, nameB: String
    public let aLat: Double, aLng: Double, bLat: Double, bLng: Double
    public let towardB: CommuteWindow, towardA: CommuteWindow
    public let templateTowardB: TripMeta, templateTowardA: TripMeta   // tripId replaced at start
    public var description: String { "CommuteRoute(<redacted>)" }
}

public enum RegionState: String, Codable, Sendable { case unknown, inside, outside }

public struct CommuteState: Codable, Sendable, Equatable {
    public var revision: Int
    public var lastState: [CommutePoint: RegionState]   // D6
    public var lastEventAtMs: [CommutePoint: Int64]     // dedupe (id, date)
    public var firedKeys: [String]                       // "towardB@2026-11-14", pruned > COMMUTE_FIRED_KEEP_DAYS
    public var failureNoticeKeys: [String]               // one failure notice per direction per day
    public var guardTrip: DepartureGuardState?
}

public struct AutoStartRecord: Codable, Sendable, Equatable {
    public let tripId: String; public let direction: CommuteDirection
    public let revision: Int; public let startedAtWallMs: Int64
}

### 5.3 Thuật toán `CommuteTriggerEvaluator.evaluate(event, route, state, ctx) -> (TriggerDecision, CommuteState)`

```

rev ≠ route.revision → skip(staleRevision)                       -- controller xoá điều kiện cũ

if last != nil && event.dateWallMs < last && last ≤ ctx.nowWallMs → skip(outOfOrder)          -- D18, không đổi state
if event.state == .unknown → skip(notEntry)            -- D6 (review C1 #2): KHÔNG đổi lastState lẫn lastEventAtMs

Kênh báo (AlarmKit/Thông báo) do `runtime.start` kiểm (T17 D14) → `rejected(permission-missing ["alarmChannel"])`.

Tình huống:
- **Rời A rồi vào B cùng khung** (người dùng đặt khung chồng nhau): khi tới B, chuyến towardB còn chạy → `tripActive`; trạng thái B
  thành `inside` → sau khi tắt báo, không kích hoạt lại cho tới khi ra khỏi B rồi vào lại.
- **Rung ở ranh giới**: in/out/in trong ngày → lần đầu bật, các lần sau `alreadyFiredToday`.
- **Trễ khung giờ**: tới A 08:05 → `outsideWindow`, không làm gì (không thông báo).
- **Đổi múi giờ**: khung giờ theo giờ địa phương hiện tại của máy; đổi múi giờ trong ngày có thể cho thêm một lần (chấp nhận, ghi rõ).
- **Đổi đồng hồ tay**: không chống; khoá ngày theo giờ máy. Chỉnh lùi: `lastEventAtMs` nằm ở tương lai so với `nowWallMs` → D18 không
  chặn, sự kiện mới được nhận.
- **`unknown` xen giữa** (review C1 #2): `outside → unknown → inside` = vào vùng (bật nếu đủ điều kiện); `inside → unknown → inside` =
  `notEntry`. Trạng thái chưa từng biết (`[]` sau đổi revision) + `unknown` → vẫn chưa biết; `inside` kế tiếp = `firstDetermination`.
- **Lệch thứ tự** (review C1 #3): `inside@t2` rồi `outside@t1` (t1 < t2) → `skip(outOfOrder)`, trạng thái vẫn `inside`; `inside@t3` sau
  đó → `notEntry`. Cùng `date` khác `state` không bị coi là lệch thứ tự (xử lý như sự kiện mới).
- Thứ tự skip mới so với C1: `duplicate` → `outOfOrder` → (`unknown` → `notEntry`) → cập nhật state → các bước còn lại như cũ.

### 5.6a Khoảng cách A–B tối thiểu (D12) — thuần, `CommuteRouteValidator`

**Engine làm gì khi xe còn đứng ở điểm đón** (đọc từ `Trip/ModeRules.swift`, `Trip/Estimator.swift`; Kotlin `core-trip`
`ModeRules.kt`/`Estimator.kt` cùng công thức):
- Tốc độ chưa "established" (cần ≥ `speedEstablishedMovingS` = 120 s **chạy** và ≥ 3 mẫu; đứng yên không tính) → `v` = **tốc độ gợi ý**
  của `vehicleHint` (bus 20, train 55, coach/unknown 60 km/h), `k = routeFactorPrior` (1,2). Vì vậy **ETA không vô hạn** khi đứng yên:
  `eta = dNow·k/v + etaStopPenaltyS`. Đã established mà tốc độ đo < `minSpeedForEtaMps` → `eta = nil`.
- `slow` (smart): chưa established → `hintKmh < smartSlowSpeedKmh`; established và tốc độ đo < 15 km/h → `true`.
- Điều kiện báo (`modeReason`): distance `dNow ≤ thr·distanceModeFactor`; time `eta ≤ thr·60` hoặc `dNow ≤ arrivedRadiusM`;
  smart `slow ? dNow ≤ slowDistM : (eta ≤ smartTargetS || dNow ≤ smartFloorM)`, `slowDistM = max(smartTargetS·smartSlowSpeedKmh/3.6,
  smartFloorM)`.
- GPS tốt và đứng yên: fix thứ hai cho `stationary` → `stopStartMs` đặt → `dNow = dSmooth` (không trượt). Trước fix thứ hai `dNow` trượt
  theo `cvDr·elapsed` (tốc độ gợi ý) — biên `COMMUTE_AB_MARGIN_M` phủ phần này.

**Công thức** (mọi phép tính `Double`, kết quả làm tròn lên mét):
```
p      = EngineParamsFactory.fromOverrides(m.engineParamsJson)       // đúng params TripRuntime.start sẽ dùng (TripRuntime.swift:826)
vMps   = hintKmh(m.vehicleHint, p) / 3.6                              // bus→expectedSpeedKmhBus, train→…Train, coach→…Coach, unknown→…Unknown
reach(T) = max(0, T − p.etaStopPenaltyS) · vMps / p.routeFactorPrior  // dNow lớn nhất để eta ≤ T khi chưa established
R(m) = switch m.mode
  distance: m.distanceThresholdM · p.distanceModeFactor
  time:     max(p.arrivedRadiusM, reach(m.timeThresholdMin · 60))
  smart:    max(slowDistM(p), p.smartFloorM, reach(p.smartTargetS))     // slowDistM như ModeRules (≥ smartFloorM)
requiredSeparationM(route) = max(COMMUTE_MIN_AB_M, ceil(max(R(templateTowardB), R(templateTowardA)) + COMMUTE_AB_MARGIN_M))   // Int
tooClose ⇔ haversine(A, B) < requiredSeparationM
```
- Validator ở module `TripRuntime`, không gọi được `ModeRules`/`Estimator` (internal của `Trip`) → viết lại công thức trên bằng các trường
  `public` của `EngineParams`; **không sửa `Trip`** (TripTests P05 không đổi). CU28 khoá công thức với engine thật: engine đổi luật thì CU28 đỏ.
- Mỗi số hạng của `max` đều là tầm báo **đạt được** ở một trạng thái thật (hint ≥ ngưỡng chậm → nhánh ETA; hint < ngưỡng chậm → `slow`,
  và khi đó `reach(smartTargetS) < slowDistM`), nên chặn trên này cũng sát (CU28 kiểm cả hai phía).
- `COMMUTE_AB_MARGIN_M` = 1 000 m: bán kính vùng 200 m (sự kiện vào vùng có thể tới khi người dùng đã đứng gần B hơn tâm A 200 m) + sai số
  fix đầu + trượt `dNow` trước fix thứ hai (≤ ~45 s ở 60 km/h) + sai lệch haversine/đường thẳng của engine (cùng công thức `Geo`).
- Ngoài phạm vi D12 (D17 lo): GPS mất ở điểm đón (`gpsLost` dùng `gpsLostAlarmEtaS` và suy đoán theo tốc độ gợi ý, không chặn trên
  được theo khoảng cách); `lowBattery` (độc lập khoảng cách, giữ — an toàn trước).

**Giá trị mặc định** (params mặc định, `engineParamsJson = null`; `→` = `requiredSeparationM`):

- Lịch sử (T28): chuyến `commute` có nhãn "Tuyến đi làm" cạnh kết quả.
- Màn 4: chuyến tự bật hiển thị như chuyến thường; thêm dòng phụ "Tự bật theo tuyến đi làm".
