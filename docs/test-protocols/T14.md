## Phần B — M01: process chết giữa chuyến rồi khôi phục

`flutter test` mặc định gỡ app sau khi chạy (cờ `--uninstall` mặc định bật, `flutter_tools/lib/src/commands/test.dart`), và một test
không tự giết được process của chính nó. Vì vậy M01 dùng app probe (không phải test): `integration_test/manual/bridge_restore_probe.dart`.
Lần mở đầu (chưa có chuyến) probe bắt đầu một chuyến **không simulation** (stub `NORMAL` 1×, báo sau ~12 phút). Các lần mở sau, probe in
những gì `currentTrip()` khôi phục, rồi nghe `updates` và in thời gian tới `TripStateUpdateMsg` đầu tiên. Log có tiền tố `NAPSTOP_PROBE`.

```bash
flutter build apk --debug -t integration_test/manual/bridge_restore_probe.dart
adb uninstall app.napstop.dev; adb install build/app/outputs/flutter-apk/app-dev-debug.apk
adb logcat -c
adb shell am start -n app.napstop.dev/app.napstop.MainActivity
adb logcat -d -s flutter | grep NAPSTOP_PROBE        # B1
```

| Bước | Thao tác | Mong đợi | Kết quả |
|---|---|---|---|
| B1 | Mở lần đầu | `started tripId=m01-…`; vài giây sau có `first-update afterMs=<200 phase=acquiring` hoặc `tracking` | |
| B2 | `adb shell input keyevent KEYCODE_HOME`; đợi 5 s; `adb shell am kill app.napstop.dev`; `adb shell pidof app.napstop.dev` | `pidof` không in gì (process đã chết) | |
| B3 | `adb shell am start -n app.napstop.dev/app.napstop.MainActivity` | `restored tripId=<cùng id B1> phase=tracking simulation=null alarmInS=<nhỏ hơn B1 đúng bằng thời gian đã trôi>`; `first-update afterMs` < 500 | |
| B4 | `adb shell am force-stop app.napstop.dev`, rồi mở lại như B3 | Như B3 (cùng `tripId`, `simulation=null`) | |
| B5 | Đợi > 13 phút kể từ B1 (app đóng: `force-stop`), rồi mở lại | `restored … phase=alarming`; `event AlarmMsg` **có thể không có** nếu `currentTrip()` chạy trước khi nghe (hành vi đã biết, review quyết định 1): UI dựa vào `phase`/`alarmRinging` | |
| B6 | Quét log như A4 | 0 dòng | |

Dọn dẹp: chạy lại Phần A (I01 tự dừng chuyến còn sót và ack hàng đợi), hoặc `adb uninstall app.napstop.dev`.

## Phần C — Vòng đời activity (review M1)

Vẫn dùng app probe ở Phần B (đang có chuyến).

| Bước | Thao tác | Mong đợi | Kết quả |
|---|---|---|---|
| C1 | Mở app → `KEYCODE_HOME` → mở lại từ launcher (`am start`) | Không có dòng `restored` mới (engine vẫn sống, Dart không chạy lại `main`) **hoặc** có `restored` + `first-update` < 500 ms. Log `update n=…` tiếp tục tăng sau khi quay lại | |
| C2 | Mở lại từ Recents (`KEYCODE_APP_SWITCH`, chọn NapStop) | Như C1 | |
| C3 | `adb shell settings put global always_finish_activities 1` (Don't keep activities). Mở app → HOME → mở lại, lặp 3 lần | Mỗi lần mở: `restored tripId=<cùng id>` + `first-update afterMs` < 500 (engine mới, replay ngay); `update n=5`, `n=10` vẫn xuất hiện (tick chạy lại) | |
| C4 | **Khôi phục:** `adb shell settings put global always_finish_activities 0`; kiểm `adb shell settings get global always_finish_activities` | `0` | |

Kịch bản 2 engine cùng lúc (activity thứ hai) chưa tái hiện được vì app chỉ có một activity. Bằng chứng JVM:
`BridgeRegistrarTest`, `BridgeLifecycleTesterTest` (6 thứ tự gắn/gỡ × 2 kiểu gỡ).

## Phần E — C01: CI kiểm code sinh trên GitHub

1. Sau khi push: job `dart` của `ci.yml` trên `main` phải xanh, bước "Check Pigeon output is up to date" chạy và pass.
2. Thử âm (nhánh tạm, không merge): sửa một **doc comment `///`** trong `app/pigeons/core_api.dart` (ví dụ thêm một chữ vào doc của
   `stopTrip`), **không** sinh lại, push nhánh → bước "Check Pigeon output is up to date" phải **fail**. Comment `//` thường không vào code
   sinh nên không làm bước này fail (đúng thiết kế). Xoá nhánh sau khi thử.

| Bước | Mong đợi | Link run | Kết quả |
|---|---|---|---|
| E1 `main` | xanh | | |
| E2 nhánh thử âm | bước Pigeon fail, các bước khác không chạy tới | | |
