# Giao thức thử T26 — Màn 4 Đang theo dõi, màn 6 (mất GPS), màn 7 (pin yếu)

Dành cho: người thử trên emulator API 34 hoặc điện thoại Android thật. Spec: `docs/specs/T26.md` (M01–M04, §4–§6).
Kết quả ghi vào `docs/test-reports/T26.md` (cột "Kết quả" bên dưới chép sang báo cáo, kèm tên ảnh).

> Quyền riêng tư: chỉ dùng chuyến `replay` (fixture) hoặc chuyến giả lập. Không chụp màn hình có vị trí thật của bạn.

## Chuẩn bị

1. Ghi: hãng, model, bản Android, emulator hay máy thật, ngôn ngữ máy (khuyên dùng Tiếng Việt).
2. Bản **dev debug**: `cd app && flutter build apk --debug`, rồi `adb install -r build/app/outputs/flutter-apk/app-dev-debug.apk`.
   Đừng chạy `flutter test integration_test` sau bước này: lệnh đó cài bản test đè lên và **gỡ app** khi chạy xong (mất quyền và cờ màn 0).
3. Mở app, qua màn 0 ("Tiếp tục"), cấp vị trí chính xác, thông báo, báo thức chính xác.
4. Lệnh debug (Git Bash: `export MSYS_NO_PATHCONV=1`):
   ```bash
   P=app.napstop.dev
   R="-n $P/app.napstop.core.trip.host.DebugCommandReceiver -a app.napstop.action.DEBUG"
   adb shell mkdir -p /sdcard/Android/data/$P/files/replay
   adb push fixtures/traces/train_hn_dh.gpx fixtures/traces/train_hn_dh.expect.json /sdcard/Android/data/$P/files/replay/
   # app phải ĐANG HIỂN THỊ khi gửi replay (T15, ADR-001)
   adb shell am broadcast $R --es cmd replay --es file train_hn_dh.gpx --es expect train_hn_dh.expect.json \
       --es mode distance --ei threshold 1000
   adb shell am broadcast $R --es cmd dump        # trạng thái runtime → logcat tag NapStopDebug
   adb shell am broadcast $R --es cmd replay_stop # dọn sau mỗi phần
   ```
5. Chụp màn: `adb exec-out screencap -p > <tên>.png`.
6. Integration I01–I04 (emulator, không phải giao thức tay; ghi để lặp lại được): mỗi lần chạy, **trước** lệnh `flutter test`:
   cài APK (`adb install -r …`) + `pm grant` 3 quyền (FINE, COARSE, POST_NOTIFICATIONS), vì lần chạy trước đã gỡ app.
   Lệnh: `flutter test integration_test/t26_tracking_test.dart -d emulator-5554`.

## M01 — Khôi phục màn 4 (chuyến thật, `replay`)

| # | Bước | Kết quả mong đợi | Kết quả (Đạt/Không + ảnh) |
|---|---|---|---|
| 1 | Ở Trang chủ, gửi `replay train_hn_dh` (mục Chuẩn bị 4). Không bấm gì | Trong ≤ 60 s, Trang chủ có thẻ chuyến. Màn 4 **không** tự mở khi app đang hiển thị ở Trang chủ mà không có resume (D12 chỉ chạy khi khởi động và khi quay lại) | |
| 2 | Bấm Home của máy, rồi mở lại app từ launcher | Vào thẳng màn 4 "Ga Đồng Hới", số km và giờ "Dự kiến tới lúc HH:MM" là giờ thật; không có badge giả lập | |
| 3 | Ở màn 4 bấm Back hệ thống | Về Trang chủ, chuyến vẫn chạy (thông báo thường trực còn) | |
| 4 | App ở nền: giết process (`am kill` không giết được khi có FGS; dùng `adb shell run-as $P kill -9 $(adb shell pidof $P)`). Mở lại từ launcher | Vào màn 4 đúng chuyến; số liệu đổi trong ≤ 60 s | |
| 5 | App ở nền: giết process như bước 4. Kéo thanh thông báo, chạm thông báo thường trực | Vào màn 4 đúng chuyến | |
| 6 | Đợi báo thức kêu (`AlarmActivity`), tắt trên màn báo thức, quay lại app | Không bị đẩy vào màn 4 của chuyến đã kết thúc; ở Trang chủ (hoặc màn 8 khi T27 có), không có thẻ chuyến. Không đè `/overshoot` | |
| 7 | Đổi giờ hệ thống +10 phút giữa chuyến (Cài đặt → Ngày giờ, tắt tự động), mở màn 4 | Ghi lại: dòng "Cập nhật X phút trước" có hiện sai không; khi view mới tới (≤ 60 s) thì dòng đó phải mất. Trả lại giờ tự động | |
| 8 | ACQUIRING lâu: bắt đầu chuyến thật trong nhà kín (hoặc `replay` với file GPX rỗng/`gps_drop` ngay đầu), khoá máy 10 phút, giết process như bước 4, mở lại | Ghi lại thời điểm banner "Chưa có GPS — báo thức chưa hoạt động" hiện. Spec: chỉ sau 120 s kể từ lúc mở lại (review #4, giới hạn đã biết) | |

## M02 — Màn 7 pin yếu (chuyến `replay` dài)

| # | Bước | Kết quả mong đợi | Kết quả |
|---|---|---|---|
| 1 | `replay train_hn_dh` (≈ 8 giờ ở 1×), mở màn 4 | Ô pin "Pin N% · Đủ tới nơi" hoặc "Đang sạc" | |
| 2 | `adb shell dumpsys battery unplug; adb shell dumpsys battery set status 3; adb shell dumpsys battery set level 12` (emulator: thiếu `status 3` thì máy vẫn báo đang sạc) | Trong ≤ 60 s + 1 chu kỳ poll 30 s: ô pin "Pin 12%". Khi engine thấy rủi ro: sheet "Pin có thể không đủ tới nơi" tự mở **một lần**, "Tiết kiệm tối đa" chọn sẵn, thanh mức pin có vùng nhạt + vạch ở 5 % | |
| 3 | Bấm "Để sau" | Sheet đóng; banner "Pin có thể không đủ tới nơi" + nút "Chọn cách"; ô pin "Có thể không đủ" màu đỏ | |
| 4 | Bấm "Chọn cách" → "Tiết kiệm tối đa" → "Áp dụng" | Sheet đóng, banner mất, ô pin "Tiết kiệm tối đa". `dump`/journal: chu kỳ SPARSE/MEDIUM × 2 (T10 §4.9) | |
| 5 | `dumpsys battery set level 5` | Báo thức kêu lý do pin ("Pin còn 5%…"). Màn 4 dưới `AlarmActivity` hiện "Đang báo thức" | |
| 6 | Dọn: `adb shell dumpsys battery reset`, `replay_stop` | | |

## M03 — TalkBack, cỡ chữ lớn nhất

| # | Bước | Kết quả mong đợi | Kết quả |
|---|---|---|---|
| 1 | Bật TalkBack, cỡ chữ lớn nhất. Mở màn 4 (chuyến `replay`) | Ô trạng thái xếp dọc; vuốt qua: "GPS tốt, ±8 m", "Pin …", "Tai nghe, Chưa cắm"; thanh tiến độ đọc "Đã đi N%. Mốc báo ở M%." | |
| 2 | `gps_drop` (mất GPS) | Banner "Mất tín hiệu GPS" **tự được đọc** một lần; số lớn có "~"; không đọc tốc độ | |
| 3 | Mở sheet màn 7 (M02 bước 2) | 3 lựa chọn đọc "đã chọn"/"chưa chọn"; "Áp dụng" chạm được ở cuối sheet | |
| 4 | "Dừng theo dõi" | Sheet xác nhận đọc tiêu đề + "NapStop sẽ không báo thức cho chuyến tới …"; "Tiếp tục theo dõi" giữ chuyến | |
| 5 | Chuyến ở SNOOZED (bấm "Báo lại" trên màn báo thức, quay lại app) | Đếm ngược "Báo lại sau 0:45" **không** đọc liên tục mỗi giây | |
